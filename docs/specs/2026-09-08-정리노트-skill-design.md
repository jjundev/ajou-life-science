# 정리노트 스킬 설계

날짜: 2026-09-08 · 상태: 승인됨 (브레인스토밍 3문답 + 설계 2묶음)

## 목적

회차 강의 STT에서 `정리노트/MMDD.md` + `MMDD.html` + `tests/test_note_MMDD.py`를 만드는 **절차**를 `/정리노트 MMDD` 로 호출 가능하게 한다. 규칙은 `정리노트/CLAUDE.md`에 이미 있으므로 스킬은 절차만 담고 규칙은 참조한다.

세 번(0903·0901·0908)의 손작업에서 절차가 한 번도 바뀌지 않았고, 유일하게 손으로 베끼다 빠뜨린 것이 테스트 파일(0901)이었다. 그래서 테스트 생성만 스크립트화한다.

## 결정 사항

| # | 결정 | 근거 |
|---|---|---|
| 1 | 위치: **프로젝트 로컬** `.claude/skills/정리노트/` | 저장소 경로에 묶여 있고 다른 프로젝트에서 안 씀. `writing-skills` 지침("프로젝트 전용은 instructions 파일에") 준수 — 규칙은 CLAUDE.md, 절차만 스킬 |
| 2 | 자율성: **게이트 1회** | 읽기·분류(1~3단계)에서 비싼 실수가 남. 4단계에서 표 셋 보여주고 OK 후 main까지 무정지 |
| 3 | 스크립트: **테스트 생성기 하나** | 0903·0908 테스트가 파라미터 4개 빼고 동일. 절차에 한 줄로 박혀 누락 불가 |
| 4 | 두 장 걸침: **한 파일, § 연속, `src` 필드** | "날짜 = 회차" 불변식 유지. 학생은 강의 하나 = 노트 하나 = 퀴즈 하나 |

## 구성

```
.claude/skills/정리노트/SKILL.md     절차 (판단 작업만). 규칙은 정리노트/CLAUDE.md 참조
scripts/new_note_test.py              테스트 생성기
tests/test_new_note_test.py           생성기 자체 테스트
tests/test_note_MMDD.py               생성기 산출물 (기존 0903·0908 은 그대로)
```

## 트리거 · 입력 · 결석

- 트리거: `/정리노트 MMDD` · "MMDD 강의 듣고 왔어" · "MMDD 정리노트 만들어줘"
- STT: `STT/MMDD*.md` 글롭 (파일명 불규칙)
- 직전 노트: 이 날짜보다 앞선 가장 최근 `정리노트/MMDD.md` — ⏪ 대조와 🔜 라벨 정정용
- 문제지: 강의계획서 주차↔장 대응으로 `23, 24 소스/N강 합본.pdf` 결정
- 결석: STT 없으면 결석/누락 여부를 먼저 묻고, 결석이면 강의노트+교재로 재구성 + ⚠️ 결석 헤더 + ⏪ 없음

## 절차

| 단계 | 하는 일 | 산출 |
|---|---|---|
| 0 | STT·직전 노트·합본 PDF 존재 확인 | 없으면 정지 |
| 1 | STT 전부 읽기. 시작(복습)·끝(마지막 발언). `pdftotext` 강의노트로 절 대응 | 범위표 |
| 2 | 고정 grep으로 ⚠️ 후보 수집 → 개념별 묶음 | ⚠️ 목록 |
| 3 | 합본 PDF → PNG(dpi 170) → 빨간 정답 → **전 문항 자기 지식 대조** → 분류 | 분류표 + 답안지 오류 |
| **4 ⏸** | 표 셋 제시: 범위·경계 / 문항 분류·정답 대조 / 구조 제안(§ 목록, 두 장이면 구분선) | **OK 대기** |
| 5 | md → html(직전 복사, 데이터 교체) → `new_note_test.py` → 직전 노트 🔜 정정 | 파일 4개 |
| 6 | `unittest discover` · 브라우저 정답1/오답1 클릭 · keyNote · ref 파일명 · 콘솔 0 | 전부 통과 |
| 7 | 브랜치 논리 커밋 → main 머지 → 재테스트 → 브랜치 삭제 → 파일 전달 → 보고 | |

## 테스트 생성기

```
python3 scripts/new_note_test.py MMDD --quiz SPEC [--quiz SPEC …]
    [--scope-terms a,b] [--prior MMDD] [--supplement] [--force] [--out PATH]
```

- `--quiz 7,8,11` 단일 출처 / `--quiz "1강:32,40" --quiz "2강:1,2"` 다중 출처. 접두가 하나라도 있으면 다중 모드, 그때 전부 접두 필수
- 산출 `tests/test_note_MMDD.py`. 템플릿 내장. 덮어쓰기는 `--force` 필수
- 단일 모드 = 0908 테스트와 동일 검사. 다중 모드 = `(src, n)` 쌍 비교 + `src` 누락 시 실패
- 생성 파일은 `NOTE_REPO_ROOT` 환경변수로 루트를 덮어쓸 수 있다 (자체 테스트가 fixture에 대해 돌리기 위함)

자체 테스트 `tests/test_new_note_test.py`:
1. 0908 파라미터로 생성 → 실제 0908 파일에 대해 실행 → 전부 통과 (손작업과 동등)
2. 다중 모드 생성 → `src` 빠진 fixture → 퀴즈 집합 검사가 실패
3. `--force` 없이 기존 파일 위에 → 거부(exit≠0)
4. 단일·다중 spec 혼용 → 거부

## 두 장 걸침 스키마 (CLAUDE.md §13 으로 추가)

- 퀴즈 항목에 선택 필드 `src:"1강"`. 엔진은 있으면 번호 앞에 표시. **0908.html 엔진에 지금 반영** (복사 사슬용). 0908은 `src` 없어 화면 불변
- md 매핑표에 `출처` 열 (다중 모드 행: `| 1강 | 32 | … |`). § 는 파일 안에서 연속. 장 전환 자리에 `## ── N장 제목 ──` 구분선(§ 아님). ✂️는 개념 중간 끊김에만
