# bio-review-pack 후속 보완 — 설계 (핸드오프 2)

2026-10-01 대화(`/grill-yourself`)에서 확정한 설계다. 선행 설계는 `docs/superpowers/specs/2026-10-01-bio-review-webquiz-variants-design.md`.

## 의도

웹과제 bank는 그 장 응시 뒤에 생긴다. 그래서 이미 만든 팩에 웹과제 원문(partA)과 새 변형(partC)을 덧붙이는 일이 장마다 반복된다(10/8 이후 4장 bank → 0929·1001). 직전 세션이 일회용 스크립트로 손으로 한 이 일을 스킬의 정식 **보강 모드**로 만들고, 팩 설계 기록(manifest·금지어·감사표)을 저장소에 남기며, 정리노트에 빠진 사실·커닝페이퍼 당황 패턴·사소한 수정, 그리고 이 대화의 결정 #11~#13(낯선 참 진술, 장 섞기, 보충 배지 구분)을 마친다.

분류: architectural — 새 진입점(`augment`), 새 스크립트(`scripts/augment.py`), 새 저장 계약(`복습노트/<range>/.pack/`). 나머지는 bounded 수정.

## 접근

| B | 일반 실행에 번호 보존 옵션 | — (정리노트까지 재생성) |
| C | 단발 HTML 패치 스크립트 | — (직전 세션에서 이미 버림) |

## 확정 결정

| # | 결정 | 값 |
|---|---|---|
| 0 | 구조 | A |

| 2 | 순서 | `.pack` 소급 생성 먼저(원천이 `/private/tmp`·`/tmp`에만 있음) |
| 3 | `.pack` | git 추적, 백업 `want()`에 포함 |
| 4 | 기존 카드 보호 | id·part·source·answer 불변, 카드 파일 존재, 새 id는 기존 최대+1부터. 본문 편집은 허용 |
| 5 | 문구 갱신 | 숫자 토큰만 정규식으로 교체. 새로 생긴 part만 문구 삽입. 못 하면 경고 |

| N1 | 기존 변형 5지화 | 0910~0929 29개, 새 보기는 (5)에 추가(정답 번호 유지), 1001 제외 (사용자 확정) |
| N2 | 1001 | 이번 작업 제외 (사용자 확정) |
| N3 | 낯선참 개수 | 팩당 1~2개 (사용자 확정) |

## 하지 않는 것

- 1001 팩 수정 — 다른 세션 작업 중
- 4장 bank 실제 보강 — 10/8 응시 후. 이번엔 도구와 왕복 검증까지
- 기존 변형에 `+낯선참`·`+장섞기` 소급 — 풀이기록과 어긋남
- manifest 스키마 변경 — 복원 사실은 `.pack/log.md`에만
- 정리노트 재생성, 0901~0908 팩

## 동작

- `/bio-review-pack <range> augment`: 기존 카드 그대로, 새 bank 문항 partA·새 변형 partC를 최대 번호 다음부터 붙이고 복습문제 HTML·MD만 다시 쓴다. 보호 검사 실패 시 쓰기 전에 멈춘다.
- 제목 "N선", 안내 문항 수, 꼬리말 `웹과제(N장)` 자동 갱신. 안내의 다른 문장은 보존.
- 조립할 때마다(일반·보강) `.pack/`에 `manifest.json`, `question-audit.md`, `key-check.md`, `variants.md`, `problem-pages.txt`, `log.md`.
- 정리노트 5곳 보충, 새 변형 표시 2종, 보고 줄 글자 정리, 당황 패턴 12개, 0910 p49·p50 / 0929 p35·p36 손질, 29개 변형 5지화.
