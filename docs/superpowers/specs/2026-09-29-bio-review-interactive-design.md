# 복습문제 선택·채점 설계

2026-09-29 대화에서 제시한 grill-yourself 설계를 구현 계획과 함께 보존한다. 사용자가 writing-plans를 요청하면서 변경하지 않은 결정 #6은 스킬의 기본 확정 규칙에 따라 기존 8개 날짜 전체와 생성 템플릿으로 확정했다. 이번 요청은 계획 작성이며 구현 착수 요청은 아니다.

## 목표와 범위

답이라고 생각하는 보기를 클릭하면 즉시 채점되고, 모든 보기 바로 아래에 정답·오답 이유가 나타난다. 기존 0901, 0903, 0908, 0910, 0915, 0917, 0922, 0929의 복습문제 HTML 8개(전체 237문항 중 객관식)와 향후 생성 경로에 적용한다.

## 사용자 동작

- 처음에는 문제와 클릭 가능한 보기만 표시한다. 힌트는 필요할 때 펼친다.
- 보기 클릭 즉시 내 선택, 정답, 정답 여부와 모든 보기별 해설을 표시한다.
- 선택한 답은 잠그고, 다시 풀기를 누르면 해당 문항의 선택·결과·해설을 초기화한다.
- 문제 이동과 새로고침 후에도 선택을 유지한다. 저장이 불가능해도 현재 화면의 풀이는 동작한다.
- 문항 내용이 달라지면 오래된 선택을 무효화한다.
- 보기는 키보드로 조작할 수 있고, 정오답은 색상뿐 아니라 글자로도 표시한다.
- 원문 정보·힌트·수업 연결·정답 이의사항은 보존한다.
- 모호한 기출은 ‘단일 정답 판정 주의’를 표시하고 출제 의도와 다른 해석을 함께 설명한다. 대안 해석을 일괄 오답 처리하지 않는다.
- 보기가 없는 문항은 기존 해설 확인 방식을 유지한다.
- 데이터 연결에 실패한 문항은 잘못 채점하지 않고 기존 풀이를 제공한다.

## 구현 제약

- 기존 문제·보기·정답·해설·출처·그림·수식 내용을 보존한다.
- 해설의 ‘맞아요/틀려요’ 문구로 정답을 추론하지 않는다.
- 별도의 서버 API나 프런트엔드 프레임워크를 추가하지 않는다.
- 생성 HTML은 기능에 필요한 CSS와 JavaScript를 내장한다.
- 기존 Markdown의 정적 문제·풀이 읽기 기능을 유지한다.
- 타이머·무작위 출제·별도 오답노트·주관식 자동 채점은 제외한다.

## 보충 결정

1. 인터랙션이 정상 초기화된 객관식은 선택 전 직접 풀이 열기를 숨긴다. JavaScript 비활성 또는 데이터 오류 때는 원래 풀이를 볼 수 있다.
2. 보기별 해설은 복제하지 않고 기존 노드를 이동한다. 원본 문서와 Markdown에는 현재 정적 구조가 남는다.
3. 모호한 문항은 선택 후 공통 안내와 모든 해설을 보여주되 이진 정오답을 매기지 않는다. 기존 기준 답은 ‘출제 의도상 답’으로 표시한다.
4. 답 제출은 기존 푼 문제 집합에 추가하고, 다시 풀기는 해당 기록을 제거한다. 기존 수동 표시는 보존하되 ‘읽음/푼 것으로 표시’와 선택 기록을 혼동하지 않게 한다.
5. 저장 범위는 문서 파일명, 문항 id, 문제·보기·정답·해설의 내용 버전으로 구분한다. 문항 수정은 다른 문항의 선택까지 초기화하지 않는다.

## 후속 변경: 보기별 접기·펼치기

사용자 요청으로 전체 해설 자동 펼침을 다음 동작으로 대체한다. 답을 선택하면 모든 보기 버튼이 해설 접기·펼치기 버튼으로 바뀌며, 내 선택과 정답만 처음에 펼친다. 둘이 같으면 한 개만 펼친다. 다른 보기와 이미 열린 보기도 클릭하거나 Enter/Space로 개별 토글한다. 토글은 제출한 답이나 완료 기록을 바꾸지 않는다. 다시 풀기는 모든 해설을 닫고, 새로고침은 저장된 답에 따라 기본 펼침 상태를 복원한다. 인쇄에서는 모든 해설을 표시한다.

## 후속 변경: 추가 해설 중복 제거

긴 모호성 사유와 추가 해설은 오른쪽 풀이 패널에만 표시한다. 중앙에는 짧은 채점 상태와 보기별 접이식 해설만 유지한다. 메타데이터에만 있는 모호성 사유도 오른쪽에 보존하되 원본 풀이에 같은 내용이 있으면 중복 추가하지 않는다.
