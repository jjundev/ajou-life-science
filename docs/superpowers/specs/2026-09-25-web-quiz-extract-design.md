# 웹과제 스크린샷 등록 스킬 설계

상태: 2026-09-25 대화의 `grill-yourself` 추천안에 따라 설계 확정. 사용자는 이어서 `writing-plans`를 호출했다. 구현 승인은 아직 아니다.

## 목적과 완료 기준

생명과학 웹과제 완료 후 제공된 스크린샷을 `웹과제/N장/`의 검증 가능한 문제은행으로 등록하는 재사용 스킬을 만든다. 원문 추출에서 멈추지 않고, 강의 자료에 근거한 분석 답·보기별 진단까지 작성하여 `validate --complete`를 통과한 경우에만 복습팩용 등록 완료라고 보고한다. 공식 답은 화면에서 확인한 경우에만 기록한다.

## 범위와 기존 계약

- 정본은 `.agents/skills/web-quiz-extract/SKILL.md`, Claude 진입점은 `.claude/skills/web-quiz-extract`가 정본 폴더를 가리키는 심볼릭 링크다. 자동 발견 가능한 모델 호출 스킬로 둔다. `bio-review-pack`은 수정하지 않는다.
- 파일 양식은 `웹과제/question-bank.schema.json` 버전 1을 그대로 따른다. 새로운 데이터 형식, 수집기, OCR 서비스, 외부 의존성은 추가하지 않는다.
- 대상은 평가 하나를 `웹과제/N장/questions.json`에 저장하는 기존 경로다. 이미 파일이 있으면 덮어쓰거나 자동 병합하지 않고 충돌을 보고한다.
- 현재 지원 형식은 보기 2개 이상인 단일 선택형과 검사 가능한 SVG 그림이다. 다중 선택형·서술형·충실하게 SVG로 복원할 수 없는 사진이 등장하면 그 사실과 원본 위치를 보고하고 해당 평가를 complete로 등록하지 않는다.
- 그림이 없다면 `assets: []`와 `image/` 파일 없음이 정상이다. 그림이 있으면 원문만 담은 `exam` SVG와 해설이 들어갈 수 있는 `explained` SVG를 `image/`에 만든다. 두 그림 모두 원본과 시각 대조한다. 원본 문제 화면에 없는 정답 힌트는 `exam`에 넣지 않는다.
- 원본 스크린샷은 `raw/`에 바이트 그대로 보존한다. 이미 `raw/`에 있다면 다시 복사하지 않는다. 외부 파일을 복사할 때 같은 이름·다른 바이트가 있으면 중단한다. macOS NFD 이름은 실제 이름을 유지하고 조회 비교에만 NFC를 쓴다.

## 스킬의 순서와 각 완료 조건

1. **입력 인벤토리:** 장 번호, 평가 날짜·제목, 스크린샷 경로를 확인한다. 화면마다 파일 해시·가로세로 픽셀·문항 번호·보기 수·캡처 시점·다른 화면과의 중복 또는 연속 관계를 표로 연결한다. 평가 전체 문항 수와 1부터 끝까지의 원문이 실제 화면으로 확인되어야 다음 단계로 간다. 시간 제한·총점이 안 보이면 스키마가 허용하는 `null`을 쓴다. 날짜·장 번호·문항 수가 확정되지 않으면 raw와 누락 보고만 남긴다.
2. **시각 전사:** 화면마다 발문, 조건·소문항, 그림, 보기 ID·문구·순서, 배점을 읽어 원문과 대조한다. OCR은 초안 보조로만 사용하고 최종 전사는 원본 화면을 다시 보고 확인한다. 같은 문항의 여러 캡처는 모두 `source_ids`에 연결한다. `selected_option_id`, `official_answer`, `analysis.answer_option_id`를 구별한다. 선택 표시를 정답으로 승격하지 않는다.
3. **그림·근거:** 지원되는 그림은 제한된 SVG로 재작성하고 `scripts.question_bank.svg.validate_svg` 및 원본 화면 대조를 거친다. 강의노트·STT·교과서 등 실제 파일과 위치·인용문을 확인한 뒤 `analysis.requirements`, 모든 보기의 `option_diagnostics`, 분석 답·모호성 기록을 작성한다. 근거가 없으면 빈 인용문이나 가짜 설명을 만들어 schema를 억지로 통과시키지 않는다. 이 경우 raw와 누락 보고를 남기고 complete 등록을 보류한다.
4. **등록·검증:** 질문 번호 집합이 정확히 `1..expected_question_count`인지, 스크린샷 source가 모두 참조되는지, 보기 수와 순서가 인벤토리와 같은지 검사한다. `review.status=verified`는 각 문항·그림의 원문/근거 대조가 끝난 뒤에만 사용하며, 저장 해시는 `canonical_digest(question_payload(...))` 및 `canonical_digest(asset_payload(...))`로 현재 파일에서 계산한다. `validate --complete` 성공 뒤 `preview.html`을 생성하고 실제 브라우저 데스크톱·375px 화면에서 원문·선택/공식/분석 답 분리, SVG 배치, 링크를 확인한다. 실패하면 등록 완료라고 보고하지 않는다.

## 실패와 보고

누락 화면, 읽을 수 없는 텍스트, 지원하지 않는 문항/그림, 근거 자료 부재, 파일명 충돌, 기존 bank 존재는 각각 원본 파일과 문항 번호를 포함해 보고한다. 부분 수집을 전체 평가로 둔갑시키지 않는다. 위 사유로 complete가 불가능하면 `questions.json`을 새로 게시하지 않는다. 보존한 raw는 `bio-review-pack`의 기존 규칙대로 미등록 자료로 남는다. 진단 인벤토리는 `웹과제/N장/intake.md`에 저장하며, 이 파일은 bank의 대체물이 아니다.

## 구현과 검증 범위

새 스킬과 Claude 링크만 추가한다. 기존 1장 bank, SVG, preview, 복습팩, 검증기 및 schema는 수정하지 않는다. 새 스킬의 설명은 웹과제 종료 스크린샷 등록 요청에만 반응하도록 짧게 쓴다. 절차에는 각각 확인 가능한 완료 조건을 두고 세부 필드 규칙은 기존 schema/검증기 링크를 참조해 한 곳만 유지한다.

구현 검증은 새 스킬의 frontmatter·경로 검증, 기존 1장 bank의 complete 검증, 그리고 독립된 읽기 전용 드라이런으로 한다. 드라이런은 1장 raw의 화면↔문항 대응, 원문 선택과 공식 답의 구별, 그림 처리, 전체 문항 수 게이트를 실제 파일로 판단하게 한다. 별도 결손 캡처 사례에서는 complete 등록을 거부해야 한다. 자동 검증만으로 의미 정확성이 증명된다고 보고하지 않는다.
