# 5장 웹과제 피드백을 생성 스킬에 반영하는 설계

기준일: 2026-10-15. 이 문서는 같은 채팅의 grill-yourself 설계를 구현자가 함께 읽을 수 있도록 고정한 것이다. 이번 범위는 스킬·검증 지침·5장 피드백이며, 기존 학습 산출물 재생성은 제외한다. 사용자에게 제시했던 결정 #9는 다음 메시지에서 변경되지 않아 권장값으로 확정했다.

## 목적과 범위

기존 `웹과제/<N>장/note-feedback.md` → 작성 계획 → 본문/문항 → 근거 검토 경로를 확장한다. 설명을 읽을 때의 이해와 이름·조건·비교 단위가 달라진 문제에서의 회상을 연결한다. 독립적인 학습 관리 시스템, 새 JSON 스키마, UI, 자동 개인 진단기는 만들지 않는다.

수정 대상은 web-quiz-extract, bio-review-pack, bio-webquiz-forecast, bio-problem-explain, bio-cheatsheet, bio-review-coach다. bio-preview-note·interactive·video·STT는 이번에 수정하지 않는다. 공통 규칙은 bio-review-pack의 기존 참조 파일을 재사용하고 소비 스킬에서는 이를 연결한다.

## 확인된 입력

- `웹과제/5장/questions.json`과 `intake.md`: 전체 17문항·84보기. 14번만 보기 4개이며 나머지는 5개다. 공식 답은 전부 미확인이다.
- 부정형: 3·4·6·8·14번, 5/17. 수치 계산: 11번. 서열 처리: 5·7번. 제공된 표 판독: 7번 코돈표. 서로 다른 분류이므로 중복 집계할 수 있다.
- 3·6·9번은 캡처 선택과 분석 답이 다르다. 이것은 공식 오답 수가 아니다. 캡처는 제출 전이고 최종 제출 답·확신도는 모른다.
- 7번의 무선택과 원문 방향 생략은 각각 별도의 불확실성이다. 7번을 개인 취약점의 증거로 세지 않는다.
- `복습노트/1006/.assets/정리노트_1006_Transcription_Translation_and_Lac_Operon.md`에는 이미 `정지 돌연변이(nonsense mutation)`와 UGC→UGA 예가 있다. 영어 병기가 없었다고 진단하지 않는다.
- 확인한 `웹과제예상/5장/src/v1/cards/p9.html`과 `v4/cards/p9.html`은 주로 한국어 명칭을 이용한다. 해당 자료를 사용자가 실제로 공부했는지는 미확인이다.
- 기존 예상 v1~v4의 bank/raw 부재 문장은 생성 당시 기록이다. 현재 bank 존재에 맞춰 소급 수정하지 않는다.

## 관찰·분석·개인 가설의 구분

피드백은 아래 세 절을 분리한다.

1. **출제 관찰:** 발문, 형식, 조건·용어·표 판독 방식 등 원본이 직접 보여 주는 사실.
2. **문항별 학습 피드백:** q01~q17 각각의 source ID, 필요한 판별 기준, 실제 강의/STT/교재 위치, 연결할 노트·토픽, 원문 주의점. 근거가 부족한 주장은 보류한다.
3. **개인 학습 가설:** 선택 기록, 가능한 원인, 경쟁하는 설명, 확인 질문의 설계, 상태를 기록한다. 상태는 진단 전 모두 `미확인 가설`이다. 일반 출제 경향과 섞지 않는다.

개인 가설의 초기 범위:

| 근거 | 가설 | 경쟁하는 설명 | 확인 방식 |
|---|---|---|---|
| q09 선택 C, q12 선택 E | 정지/무의미/넌센스/nonsense의 이름 연결 불안정 | 일시적 실수, 변이 종류 자체의 혼동 | 명칭 없는 현상 설명 후 다른 명칭으로 역방향 질문 |
| q01 선택 B, q06 선택 A | 유전자·전구체·성숙 mRNA라는 비교 단위 혼동 | 부정형 발문을 놓침 | 명칭·발문 방향을 고정하고 비교 단위만 바꿔 질문 |
| q03 선택 A | 작용 대상과 조절 단계의 연결 불안정 | 부정형 발문을 놓침 | 현상→단계 분류, 이후 질문 방향만 전환 |
| q07 선택 없음 | 진단 보류 | 캡처 시점·최종 선택·원문 방향 미확인 | 추가 진단이 요청될 때 명확한 방향의 새 문제 사용 |

## 저작 규칙

### 명칭 전환과 역방향 회상

- 본문에는 출처가 확인된 한국어명·영문명·다른 번역명만 연결한다. 다른 장에 5장 용어를 강제하지 않는다.
- `정지 돌연변이 ↔ 넌센스 돌연변이 ↔ nonsense mutation`처럼 실제 자료가 확인하는 대응을 제시한다. 무의미라는 명칭은 사용된 예상 카드 등 근거도 연결한다.
- 생성 연습은 이름→현상과 현상→이름을 모두 다룰 수 있다. 문제 본문에 모든 동의어를 붙여 시험할 능력을 미리 알려 주지 않으며, 대응은 해설에서 공개한다.
- 원문 문제에 번역·힌트·정답 용어를 덧붙이지 않는다. eli5의 전문용어 없는 짧은 설명은 유지하고 formal/warn/요약에 필요한 대응을 둔다.

### 비교 단위와 분류 경계

- 필요한 토픽에는 대상·조건·결과·헷갈리는 인접 사례를 짧게 명시한다. 모든 토픽에 고정 표나 긴 동기 문단을 강제하지 않는다.
- 같은 전구체에서 서로 다른 성숙 mRNA가 생기는 것, 성숙 mRNA 한 종류가 보통 하나의 단백질을 암호화하는 것, 원핵 오페론 mRNA가 여러 단백질을 암호화하는 것을 구분한다.
- 전사/전사 후/번역/번역 후는 변화의 대상과 과정으로 분류한다. 시간상 전사 전의 변화라는 이유만으로 전사 조절에서 제외하지 않는다.
- 부정형의 내용상 참·거짓과 답으로서의 적합성을 구분한다. 절대 표현이면 무조건 오답이라는 요령은 금지한다.

### 반복과 난이도

- 기존 발문 복제·실제 웹과제 발문 복사 금지는 유지한다.
- 같은 혼동을 반복할 때 두 요소 이상 변경하는 일반 규칙에 좁은 예외를 둔다. 명칭 전환 또는 비교 단위 진단을 목적으로 한다면 한 요소만 변경할 수 있고 설계표에 이전 카드·변경 요소·목적을 기록한다. 동일 발문을 허용하는 예외가 아니다.
- 장별 근거가 있으면 기본/심화 배합도 그 근거로 정한다. 기본 12·심화 3 및 partC 기본 75~80%는 장별 근거가 부족할 때의 참고 생성 정책으로만 유지한다. 실제 통계나 의무 비율로 표현하지 않는다.
- 근거만으로 수준 분포를 정할 수 없으면 그 사실과 생성 목표의 이유를 공개한다. 새 고정 비율을 5장 관찰 하나에서 만들지 않는다.
- 예상 15문항, 기출 5·신규 10, 기존 기출 모드 예외, 정답 A~E 각 3개는 유지한다. 정답 글자 배합은 출제 예측이 아닌 생성 정책이다.

## 스킬별 전달 계약

- **web-quiz-extract:** 기존 bank 검증·원자 게시를 유지한다. 검증된 등록 뒤 note-feedback을 작성하는 절차를 연결한다. 피드백 실패는 별도 미완료로 보고하며 이미 검증된 bank를 삭제하거나 검토 해시를 다시 쓰지 않는다. 공식 답을 추론으로 채우지 않는다.
- **bio-review-pack:** 기존 note-feedback-audit의 ID별 계획·실제 본문 문장·보류 이유를 유지한다. 용어 존재와 실제 판별 기준 충족을 구분하고 lite에서도 검토한다. augment를 본문 반영으로 세지 않는다.
- **bio-webquiz-forecast:** 원천 수집에서 장별 피드백의 관찰/판별 기준을 읽는다. 개인 가설은 확인 전 표시를 유지하고 기존 개요에 학생 오개념으로 단정하지 않는다. blueprint의 기존 열을 유지하고, 회상 연습은 표 뒤 별도 목록에 카드 ID·근거·변경 요소·의도를 기록한다. 새 pack.json 필드를 만들지 않는다.
- **bio-problem-explain:** understand/recall/pitfall에서 명칭 연결과 결정적 구분을 설명하되 같은 긴 설명을 복제하지 않는다. 해설을 읽은 성공을 독립 회상으로 보고하지 않는다. source_visual/content/independent/browser, 해시·수정 최대 2회·발행 보류 계약은 유지한다.
- **bio-cheatsheet:** 5장 관찰을 panic-patterns에 추가하고 ② 용어 구역의 대응을 근거와 연결한다. 시간 제한 미확인은 그대로 두고 다른 장 값을 5장 값으로 쓰지 않는다. 시트 갱신 필요성과 실제 재생성 완료를 구분한다.
- **bio-review-coach:** 분석만 요청받으면 가설을 보고하고 임의로 퀴즈를 시작하지 않는다. 코칭 요청에서는 한 번에 한 문제, 모르겠다/찍음·불확실 선택지를 유지하며 한 요소 전환으로 가설을 구분한다. 최초 독립 풀이·코칭 후 성공·장기 숙달을 구분한다.

## 검증과 완료 경계

기계 검사는 피드백 ID/source 누락, 파일·링크·해시와 기존 런타임 계약을 확인한다. 의미 검토는 실제 원본과 근거 문장으로 다른 표현의 보기를 판단할 수 있는지 확인한다. 문구 존재 테스트나 에이전트 풀이 성공을 학생의 학습 효과로 보고하지 않는다.

이번 구현에서는 임시 RUN의 최소 저작 사례와 판단 기록으로 규칙의 작동을 점검한다. 1006·1008 노트나 예상 v5·해설·커닝페이퍼를 새로 발행하지 않는다. 실제 새 산출물을 발행할 때는 해당 생성 스킬의 기존 전체 검증을 그대로 수행한다.

사용자가 요청한 구현·커밋 범위만 전달하며, 원본 bank·raw·기존 노트·예상 v1~v4·풀이기록·기존 감사표는 보존한다. 계획 작성 마지막 확인에서 5장 등록 산출물은 별도 커밋 `b69a977`로 추적 중이다. 이번 작업은 그 등록 커밋을 재작성하거나 원본을 변경하지 않는다. 실행 시작 때 추적·미추적 상태를 다시 확인한다.
