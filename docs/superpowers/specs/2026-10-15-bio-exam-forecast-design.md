# 생명과학 시험 예상문제 스킬 설계

2026-10-15 대화에서 정리한 설계다. 구현 계획은 `../plans/2026-10-15-bio-exam-forecast.md`다. 이 문서와 계획 저장은 구현·실제 문제 생성·Git 발행의 실행 승인이 아니다.

## 1. 목적과 확정 범위

`bio-exam-forecast`는 사용자가 입력한 장 범위 안에서 객관식 55문항과 주관식 단답형 20문항을 만드는 저장소 전용 스킬이다. 기존 `bio-webquiz-forecast`의 출제·검토 방식과 `bio-problem-explain`의 해설 파이프라인을 참고·재사용한다. 문제 HTML과 검토된 해설 HTML이 모두 준비되어야 전체 완료다.

사용자 지정 문항 수는 실제 시험에 대한 가정이다. 웹과제가 실제 시험에 일부 나온다는 것은 사용자 제공 정보이고, 재출제 비율은 미확인이다. 출처 배합·장별 균등 배정은 대화에서 제안된 기본 생성 정책으로 기록하며 실제 통계로 표현하지 않는다.

## 2. 공통 제약

- 객관식 55문항·단답형 20문항, 합계 75문항을 기본으로 한다.
- 문제와 모든 보기를 판단하는 데 필요한 지식은 사용자가 입력한 장 범위 안에 있어야 한다.
- 실행할 때마다 공통 출제 경향 MD와 선택 범위의 장별 피드백을 새로 읽는다.
- 출제 경향 본문을 새 스킬에 복제하지 않는다. 읽은 파일의 경로·SHA-256과 문항별 적용 근거를 남긴다.
- 원문 재사용은 발문·수치·조건·보기 순서·그림을 보존한다. 의미를 수정한 문항은 변형으로 표시한다.
- 화면의 사용자 선택을 공식 정답으로 취급하지 않는다. 공식 답과 분석 답의 상태를 구별한다.
- 범위 부족·조건 모호함·정답 충돌·원문 미확인으로 75문항을 채울 수 없으면 부족을 보고한다. 범위 확장·반복 채우기·빈 문항은 금지한다.
- 기존 버전·문제은행·STT·강의노트·고정 vendor 사본을 수정하지 않는다.
- Python 3.10 이상을 사용한다. 문제은행 검증은 기존 jsonschema 의존성을 재사용하고 새 LLM API·스케줄러·백엔드를 추가하지 않는다.
- 최초 검토 이후 수정·재검토는 최대 2회다. 문제·해설 단계를 오가더라도 같은 실행의 수정 횟수를 초기화하지 않는다.
- 문제와 해설이 모두 검증되어야 전체 완료다. 해설이 미해결이면 검증된 문제는 보존하고 부분 완료로 보고한다.
- 커밋·푸시·실제 수업 범위의 75문항 생성은 별도 요청 전에는 실행하지 않는다.

## 3. 입력·범위

호출 예: `/bio-exam-forecast 1장~6장`, `/bio-exam-forecast 4장-5장`, `/bio-exam-forecast 3장`. 공백과 NFC/NFD를 정규화하고 `~`, `～`, `-` 범위 구분을 허용한다. 숫자만 있는 `1~6`, `3`도 허용한다. 첫 버전은 연속 범위·단일 장만 지원한다. 쉼표 목록·역순·0·음수·장 구분 외 문자열은 명확한 오류로 거부한다.

범위 식별자는 여러 장이면 `1장-6장`, 단일 장이면 `3장`이다. 유효한 정수라도 실제 자료가 없는 장은 자료 부족으로 처리한다. 장 번호를 1~6으로 하드코딩하지 않는다.

장 번호 태그·금지어 검사는 보조 수단이다. 에이전트는 `scope.json`의 토픽별 근거와 후보의 `required_chapters`를 실제 문항·모든 보기·그림과 대조한다. 이전 수업이라도 입력 범위 밖의 지식을 필수로 요구하면 제외한다. 장 섞기는 선택 범위 안에서만 허용한다. 수업 설명이 없다는 이유만으로 시험 제외를 단정하지 않는다.

## 4. 동적으로 읽는 근거

필수 공통 파일은 `.agents/skills/bio-review-pack/references/webquiz-style.md`와 `references/note-feedback.md`다. 선택 범위마다 `웹과제/<N>장/note-feedback.md`, `questions.json`, `intake.md`의 존재를 확인하고 해당하는 자료를 읽는다. 정리노트·장마감·강의노트·STT·교과서·23·24 기출은 실제 선정 토픽의 범위·답·형태를 검토할 때 읽는다.

공통 MD가 없으면 중단한다. 장별 피드백이나 bank가 없으면 `missing`으로 기록하고 다른 해당 장 자료를 사용한다. 공통 MD의 오래된 상태 서술(예: 4장 bank 미등록)과 현재 bank 존재가 다르면 현재 검증된 파일 상태를 사용하고 불일치를 공개한다. 새로운 bank를 핑계로 공통 MD를 자동 수정하지 않는다.

공통 MD의 문항 유형·판별 기준·주의사항을 사용한다. 기존 웹과제 전용의 15문항·고정 카드 번호·A~E 균등 배합·이전 장 허용 규칙은 시험 프로필에 그대로 이식하지 않는다. 시험 프로필의 55+20·엄격한 입력 범위가 우선한다. 난이도·유형의 참고 목표도 실행 시 읽은 MD와 해당 장 자료에서 정해 policy_summary에 기록한다. 대화 당시 약 80/20 난이도 참고값을 제안했지만 이를 스킬 코드의 고정 비율로 복제하지 않으며 원문에는 목표 배합을 강제하지 않는다.

`source-manifest.json`은 존재·부재를 모두 기록한다. 파일 항목은 `path`(저장소 상대 POSIX 경로), `role`, `status`(`present|missing`), `sha256`(부재면 null)이다. bank가 참조하는 원본·그림·근거 파일과 실제 사용한 PDF도 포함한다. prepare부터 문제 검토·해설 추출·발행 직전까지 재확인한다. 파일 내용 변경·삭제·부재 파일의 신규 등장 모두 현재 실행을 무효화한다. 다음 실행에서는 최신 내용을 다시 읽는다. 기존 세트의 HTML은 자동 재생성하지 않는다.

`policy-notes.md`에는 에이전트가 실제 읽은 절의 위치·인용/요약·장별 적용/비적용 이유를 기록한다. 해시 기록만으로 읽거나 의미를 반영했다고 판정하지 않는다.

## 5. 기본 배합과 선정

| 형식 | 출처/모드 | 목표 |
|---|---|---:|
| 객관식 | web/original | 20 |
| 객관식 | web/variant | 10 |
| 객관식 | past/original | 10 |
| 객관식 | new/generated | 15 |
| 단답형 | web/variant | 8 |
| 단답형 | past/original 또는 variant | 4 |
| 단답형 | new/generated | 8 |

총문항의 장별 균등 배정을 먼저 정한다(정수 잔여는 장 번호 오름차순). 그 총문항 수를 가중치로 largest remainder 방식으로 객관식 55개를 나누고, 장별 나머지를 단답형 20개로 둔다. 1~6장 예: 총 `(13,13,13,12,12,12)`, 객관식 `(10,9,9,9,9,9)`, 단답형 `(3,4,4,3,3,3)`.

장/형식별 수·범위·가족 중복 금지는 필수 제약이다. 출처 배합은 목표다. 출처 부족은 같은 장·형식의 다른 적격 출처로 보완하고 목표/실제/사유를 보고한다. 부족한 후보는 에이전트가 범위 안에서 추가 생성·검토할 수 있다. 그래도 부족하면 미완료로 보고하며 세트 build를 허용하지 않는다.

후보 우선순위: 시험 포함/중요 명시 → 서로 다른 실제 평가에서 재확인된 개념 → 아직 빠진 핵심 소주제 → 명칭·대상·단계·방향·비교 단위 혼동 → 이전 버전에서 덜 다룬 개념. 정리노트 여러 곳에 복제된 동일 원문은 빈도 증가로 세지 않는다. 이 순위를 수치 출제 확률로 표현하지 않는다.

같은 원문·동일 변형 계열은 안정적인 `family_id`로 묶고 세트당 하나만 선택한다. 웹과제와 기출에 같은 문제가 있어도 한 가족이다. 정확한 중복 fingerprint와 의미상 가족 판정은 구별한다. 단어만 바꾼 중복·문항 사이 답 노출은 별도 의미 검토에서 교체한다. 이전 버전의 미사용 가족을 우선하되 소진 시 원문 재사용을 금지하지 않고 겹침을 공개한다. 생성 문항의 동일 발문 재사용은 허용하지 않는다.

## 6. 문항 계약

`scope.json`은 `chapters`, `topics`를 가진다. topic은 `id`, `chapter`, `title`, `evidence`(아래 reference 목록), `scope_status`(`included|excluded|uncertain`), `reason`을 가진다. `included` 토픽의 근거로만 최종 후보를 만든다. 서로 다른 파일의 concept 이름은 해당 실행의 topic ID로 대응한다.

`candidates.json`의 각 후보는 다음 필드를 가진다. 의미 필드의 초안은 비어 있을 수 있으나 최종 선정 전 검토·검증을 마쳐야 한다.

| 필드 | 값/책임 |
|---|---|
| `id`, `family_id` | 고유 후보 ID, 같은 원문/변형 계열 ID |
| `format`, `origin`, `mode` | `mcq|short`, `web|past|new`, `original|variant|generated` |
| `primary_chapter`, `required_chapters`, `topic_ids` | 주 배정 장 1개, 모든 필요 장, scope.json 토픽 |
| `level`, `priority` | 1~3, 위 다섯 우선순위의 불리언 5개(순서 고정) |
| `types`, `selection_reason` | 출제 유형 문자열 배열(공통 MD에 새 유형이 추가되어도 고정 enum으로 막지 않음), 선정 이유 |
| `problem_html` | 문제·조건·그림·보기 전체, 정답/해설 미포함 |
| `options` | 객관식의 순서 있는 `{id,text}` 배열. 원문 4/5보기 보존, 생성 기본 5·필요 시 4. 단답형은 빈 배열 |
| `answer` | 객관식 `{kind:'choice',option_id:...}` 또는 단답형 `{kind:'short',canonical,accepted,case_sensitive}` |
| `rejected_answers`, `solution_steps` | 단답형 불허 답 `{text,reason}` 목록(해당 시), 비어 있지 않은 풀이 단계 |
| `source_refs` | `{path,sha256,locator,role}` 목록. 공식 답/분석 답 구분도 함께 기록 |
| `style_basis` | `{path,sha256,locator,criterion,application}` 목록. 생성 문항에 필수 |
| `transformation`, `minimum_steps` | 변형한 요소·유지할 판별 원리, 실제 최소 풀이 단계 |
| `original_payload_sha256` | original이면 canonical 원문 구조의 해시, 아니면 null |
| `review` | `scope`, `key`, `source`, `style`, `family` 각각 `{status,evidence}`. 최종 적격은 모두 pass |

단답형은 용어·구조 이름·수치·짧은 서열을 묻는다. 원문 선택지를 지우기만 해 답이 여러 개가 되는 변형은 금지한다. canonical과 accepted는 근거가 있는 표현만 허용한다. 자동 비교는 NFC+양끝 공백 제거를 기본으로 하며 `case_sensitive=false`일 때만 대소문자를 무시한다. 단위/분수 표현은 accepted에 명시하고 임의 동등식 계산·내부 공백 삭제·gene symbol 소문자화를 하지 않는다. 허용답과 일치하지 않으면 자동 오답 대신 자기채점 대기로 둔다.

기출 합본은 해당 페이지를 이미지로 대조하여 빨간 정답·그림·조건을 확인한다. 기존 `exam_pool.load_pool()`은 후보 발견 보조이고 정답·원문 검증의 증거가 아니다. 단답형 기출은 이 객관식 collector에 없을 수 있으므로 페이지를 확인한 뒤 따로 등록한다.

## 7. 결과물·문제 화면

`시험예상/<범위>/시험예상문제_<범위>_v<K>.html`, `문제해설_<범위>_시험예상_v<K>.html`과 `.pack/`만 범위 폴더 최상위에 둔다. 내부는 `.pack/v<K>/`에 `pack.json`, `blueprint.md`, `scope.json`, `source-manifest.json`, `policy-notes.md`, `candidates.json`, `selection-report.md`, `question-review.json`, `verification.md`, `cards/`를 둔다. 해설 MD·그림·자료도 해당 버전 하위에 둔다.

`pack.json`: `schema_version=1`, `profile='exam'`, `scope`(장 배열), `range`(식별자), `version`, `counts={mcq:55,short:20}`, `targets`, `policy_summary`, `problems`(선정 후보 전체에 최종 `id=p1..p75`, `candidate_id` 추가), `source_manifest='source-manifest.json'`. targets는 mcq의 web_original=20/web_variant=10/past_original=10/new_generated=15, short의 web=8/past=4/new=8을 가진다. policy_summary는 `type_targets` 배열(`chapter,type,target,reason,source_ref`)과 `difficulty_targets` 배열(`chapter,basic,advanced,reason,source_ref`)이다. 근거가 부족해 목표를 정할 수 없는 항목은 target 또는 basic/advanced를 null로 두고 이유를 적는다. 이 값은 매 실행 자료를 읽은 에이전트가 정하며 스크립트가 MD 자연어에서 자동 추출하지 않는다. p1~p55는 mcq, p56~p75는 short다. blueprint는 같은 problems에서 파생하고 주제·유형·판별 기준·출처·수준·최소 단계·선정 사유를 표시한다. 두 기록의 불일치는 오류다.

문제 HTML은 기존 review 템플릿의 디자인 토큰/스타일과 로컬 KaTeX/Pretendard를 재사용하되, 즉시 채점하는 기존 interaction runtime은 실행하지 않는다. 시험용 작은 템플릿·JS로 선택/입력→전체 제출→정답/출처/선정 이유 공개를 처리한다. 소스 코드 열람 방지 기능은 요구하지 않는다. 출력 가능한 문제 UI에서 제출 전 정답이 노출되지 않아야 한다. JS 실패/비활성 시에도 답은 hidden 상태로 유지하고 안내를 표시한다.

답은 현재 페이지에서 유지하고 재시작 시 초기화한다. 여러 버전 사이 저장 상태를 공유하지 않는다. 첫 버전은 영구 답안 저장·타이머·PDF·개인 약점 진단·정밀 점수화를 추가하지 않는다. 결과는 객관식 정답 수, 단답형 자동 일치 수/자기채점 대기 수로 표시한다.

## 8. 검증·해설 연결

기계 검사는 ID/55+20/장 배정/가족·정확 중복/원문 보존/파일·앵커·SVG ID/입력 해시/카드·pack·blueprint 일치/허용답 모델을 검사한다. 해시는 의미상 범위·정답·그림 적합성을 증명하지 않는다. 문제 검토는 `source_visual`, `content_scope_style`, `independent`, `browser` 네 항목과 p1~p75의 문항별 증거를 필요로 한다. 의미 검토에는 장별 피드백 적용, 새 문제 과난도, 중복 개념 과집중·답 노출을 포함한다.

정답·풀이·출처·설계표를 뺀 blind HTML은 문제/보기/그림/표를 온전히 보존한다. 독립 검토자는 학습 근거 자료는 읽되 정답키·설계표·풀이·해설은 받지 않는다. 기존 blind.py의 SVG 텍스트화·객관식만 추출하는 방식을 그대로 사용하지 않는다.

해설은 새 `exam` profile로 p1~p75를 읽는다. `SourcePack.context_hashes`에 pack/blueprint/scope/policy/source-manifest/문제검토와 실제 source reference 해시를 묶고 부재 파일의 새 등장도 검사한다. 날짜형/최신/all은 기존 복습노트 선택을 유지하며 시험 예상은 명시 HTML 경로만 받는다. 단답형은 기존 비선택형 풀이 구조와 허용답 목록을 사용한다. 기존 네 해설 검토와 발행 게이트를 유지한다.

문제만 오류면 문제 수정·검증 후 새 RUN에서 해설 추출, 해설만 오류면 해설 build/check와 네 검토를 다시 수행한다. 검토 횟수는 하나의 실행 기록에서 관리한다. 검토자가 pass라고 적지 않은 항목을 스크립트가 자동 승인하지 않는다.

## 9. 완료와 비목표

스킬 설치 검증은 임시 합성 저장소에서 75문항·해설·브라우저 흐름으로 한다. 설치만으로 실제 1~6장 세트를 생성하지 않는다. 실제 문제 생성은 이 스킬을 호출한 후에 별도로 수행한다. 두 HTML의 검증 상태·장별 구성·출처 목표/실제 차이·경향 반영·반복·공식 답 미확인·미해결을 보고한다.

공통 MD를 미래에 고치면 다음 실행의 판단 자료가 갱신된다. 스킬 소스 코드·이전 결과를 자동 수정하거나 백그라운드 감시를 설치하는 기능은 포함하지 않는다.
