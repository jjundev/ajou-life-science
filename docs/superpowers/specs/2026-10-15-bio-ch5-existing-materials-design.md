# 5장 웹과제 피드백의 기존 학습 자료 반영 설계

2026-10-15. 채팅의 grill-yourself 설계를 구현 계획과 함께 보존한다. 사용자 결정 #1: **복습팩 먼저, 커닝페이퍼 그다음**. 기존 Native 실행 방식 선호를 유지하되 이번 요청은 계획 작성이며 구현 시작 지시는 아니다.

## 목표와 경계

실제 5장 웹과제의 17개 판별 기준을 기존 자료와 대조하고, 부족한 설명·회상 연습만 보완한다. 설명의 존재, 회상 연습의 존재, 학생의 숙달을 각각 구별한다. 기존 자료 전체가 잘못되었다거나 모든 문장을 다시 써야 한다고 가정하지 않는다.

기존 흐름을 사용하는 bounded 변경이다. 독립 산출물인 복습팩과 커닝페이퍼는 별도 계획으로 나누고 순차 실행한다. 생산 코드·템플릿·스키마·스킬 변경은 범위 밖이다. 예상문제 v1~v4, 원문 bank/raw, 공식 답 필드와 해시, 다른 장 자료는 보존한다. 커밋·main 병합·push·워크트리 정리는 별도 지시가 없으면 수행하지 않는다.

## 1단계: 복습팩

- 작업 출발점: `codex/bio-ch5-feedback-skills`의 `5e353ba` 및 그 후 승인된 계획 파일. 실행 시 현재 Git 상태를 다시 확인한다. 다른 작업자의 변경은 보존한다.
- 1006·1008은 설명과 연습을 우선 점검한다. 1001도 복제·결합·교정 기준을 점검하되 충분하면 본문과 문제를 그대로 둔다.
- 17개 피드백 ID를 기존 8열 감사표로 추적한다. 상태는 본문 반영 / 기존 설명 충분 / 이전 노트 연결 / 미학습 보류 / 판독·근거 불확실이다. 여러 팩의 같은 ID는 중복 문항 출제를 뜻하지 않는다.
- 명칭↔현상: 정지·넌센스·nonsense와 조기 종결, missense·silent·frameshift의 차이. 원천에서 확인된 명칭만 사용한다.
- 비교 단위: 전구체 하나에서 가능한 성숙 mRNA 종류와 성숙 mRNA 한 종류의 암호화 범위를 구별한다.
- 조절 단계: DNA 접근성·개시와 만들어진 RNA의 가공·수명·번역 억제를 대상·조건·직접 효과로 구별한다.
- 이미 충분한 본문은 인용해 유지한다. 연습 부족은 별도로 판단한다. 기존 연습으로 충족되면 새 문제를 추가하지 않는다. 부족하면 같은 수업 범위의 새 생성 문제만 기존 최댓값 다음 ID로 추가한다. 고정 추가 개수는 없다.
- 기존 카드의 ID·part·source·answer·문제·보기를 보존한다. 실제 웹과제 원문에 힌트·번역·조건을 추가하지 않는다. 새 생성 문항은 원문 복제와 구별한다.
- 본문을 고치는 팩은 full 조립·검토 경로를 사용한다. augment만으로 본문 반영을 주장하지 않는다. full은 전체 검증 절차를 뜻하며 전면 재저작을 뜻하지 않는다.
- 기존 토픽 ID·앵커·인터렉티브 HTML·링크·사용자 맞춤 설명·위젯 스크립트·풀이기록을 보존한다. HTML/MD/manifest/그림/문제설명을 동기화한다.
- 원자료·내용·별도 블라인드 재풀이·브라우저 검토를 실제로 수행한다. 문제설명의 현재 입력 해시와 네 검토가 맞아야 발행한다. 실패한 팩은 백업에서 이전 팩 전체를 복구하고 성공 팩과 구별해 보고한다. 근거 불확실 행이 있어도 그 불확실성을 정직하게 공개하는 것과 잘못된 정답 충돌을 구별한다.
- q03·q06·q09의 선택 불일치는 공식 오답이나 확정 취약점이 아니다. q07의 무선택·방향 생략은 학습 결함으로 확정하지 않는다.

## 2단계: 커닝페이퍼

1단계의 대상 팩 감사·검증과 필요한 발행이 완료된 뒤 시작한다. 보류 팩이 있으면 선행 미완료로 보고하고 시트 재생성을 시작하지 않는다.

- `웹과제예상/커닝페이퍼/5장/`의 기본 HTML·PDF·spec·찾기-점검을 갱신한다. 웹과제당일 등 응시 기록은 보존한다.
- ① 시험장 체크와 ② 용어 바꿔 부르기를 맨 앞에 둔다. ② 명칭 대응·판별 단서까지 갱신하므로 refresh가 아니라 전체 재생성이다.
- 갱신된 노트와 실제 원자료를 사용한다. 개인 학습 가설·공식 정답 번호를 시트 사실로 옮기지 않는다.
- 기존 형식대로 구역 10~16개, ③부터 구역별 함정 1~3개와 출처, 고정 쪽 수 없음. 새 spec 필드는 만들지 않는다. basis는 stale.py의 실제 출력으로 채운다.
- 찾기-점검은 기존 규칙의 기출 5행, 서로 다른 구역, 부정형·그림 각각 1개 이상이며 시간 칸은 비워 둔다. 사용자 입력이 있으면 기존 파일을 보존하고 새 초안과 대조한다.
- HTML 검사, 전체 PDF 쪽 이미지 확인, 별도 사실 리뷰를 통과한 결과만 교체한다. 이후 사용자가 이 순차 계획의 구현을 지시하면 기본 시트 재생성·교체도 그 범위에 포함되므로 중복 승인을 묻지 않는다. 이번 계획 작성 단계에서는 기존 자료를 교체하지 않는다. 후보만 요청한 경우에만 RUN/out에 남긴다.

## 완료 증거

팩별 감사표의 실제 문장·근거 위치, 카드와 풀이기록 보존 검사, 변경 자료의 현재 해시에 맞춘 검토 기록, 브라우저 결과, 시트 전체 쪽 검토가 있어야 한다. 자동 검사를 통과했다는 사실을 학생 학습 효과나 숙달 증거로 쓰지 않는다. 보존할 원본의 변경, 소리 없이 사라진 기존 보충 설명·스크립트, 낡은 해설을 갱신 완료로 보고하는 상황은 실패다.
