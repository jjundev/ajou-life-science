# 정리노트 작성 규칙

이 디렉터리의 회차 노트를 만들거나 고칠 때 반드시 따른다.

## 1. 파일 = 강의 회차

- 파일명은 `MMDD.md` / `MMDD.html`. 날짜 하나가 강의 한 회차다.
- 강의는 주 2회(화·목). 여러 회차가 모여 교재 한 장(章)을 이룬다.
- **본문에는 그 회차에 실제로 강의한 것만 쓴다.** 다음 회차 내용을 당겨오지 않는다.

## 2. 경계 처리

강의가 개념 중간에서 끊기면 그 자리에 이음매 블록을 둔다. 내용은 쓰지 않고 이름만 예고한다.

> ✂️ **여기서 강의가 끊겼습니다** — "(교수님의 마지막 발언 인용)"
> 다음: (다음에 나올 항목 나열) · `MMDD.md`

직전 회차를 교수님이 도입부에 복습하면 문서 앞쪽에 거울상 블록을 둔다.

> ## ⏪ 지난 회차 복습 (교수님이 도입부에 짚은 것)
> (요점 3~5줄) · 원 강의: `MMDD` · 📝 관련 문항 N, N

## 3. 무엇을 본문에 넣는가 — STT 기준

- 해당 회차 STT에 **한 번이라도 언급**된 개념 → 본문.
- STT에 **전혀 없는데 문제에는 나오는** 개념은 실제 근거에 따라 강의노트·교재·외부 참고로 구분하여 `## 📎 강의 밖 보충 — 문제 대비용` 섹션에 둔다. 강의에서 생략했다는 사실을 시험 제외로 바꾸지 않는다.
- 보충은 실제 근거에 따라 **강의노트·교재·외부 참고**로 구분한다. 출처를 감추지 않고 보충을 어디에서 왔는지를 명확히 나타낸다.

이 기준이 필요한 이유: 강의노트 PDF는 목차 뼈대일 뿐이다. 전기음성도·옥텟·pH 같은 것이 15개 강의노트 전체에 한 번도 안 나온다. 강의노트만 믿으면 안 되고, STT가 주 자료다.

## 4. 밀도

각 개념은 다음을 갖춘다. 한 줄 요약체는 금지한다(그건 강의노트가 이미 하고 있다).

- 정의와 **성립 조건**
- **인과** — 왜 그렇게 되는가
- `⚠️` **오개념 방어** ← 이 노트의 존재 이유
- `> 💡 **교수님**` 인용 — 비유·암기법
- `📝 **관련 문항**: N, N`

모든 보기의 선택 적합성과 근거를 확인한다. 필요한 사실이 해설에만 있으면 본문이나 출처가 표시된 보충에서 먼저 가르친다. 그림 판독 문항은 정답을 열기 전의 그림과 설명만으로 풀 수 있어야 한다. 30초 요약에서도 성립 조건과 분류 경계를 유지하고, 기능 경로에 참여하는 것을 그 계의 구성원으로 표시하지 않는다. 쉬운 설명에도 시험 판별에 필요한 원래 용어를 남긴다.

`⚠️` 블록의 재료는 STT에서 교수님이 **반복했거나, 되물었거나, "헷갈린다"고 말한 지점**이다. 노트를 쓰기 전에 STT를 훑어 이것부터 전수 수집한다.

문서 맨 위에는 `## ⏱ 30초 요약` 표를 둔다. 시험 직전에 이것만 본다.

## 5. 교수님 잡담

개념에 걸린 것만 남기고 나머지는 버린다. 판별 기준은 "이 비유를 지우면 개념 이해가 나빠지는가"다.

## 6. md와 html의 분업 — 중복 0

| | `MMDD.md` | `MMDD.html` |
|---|---|---|
| 30초 요약·본문·✂️·📎·매핑표 | ✅ 유일 원천 | ❌ |
| **정답 + 근거 + 오답 진단** | ❌ | ✅ 유일 원천 |
| **구조 시각화 (토글·슬라이더)** | ❌ | ✅ |
| ASCII 다이어그램 | ✅ 보조 | ❌ |

- 문제 JSON은 원문·관찰 기록·분석의 유일 원천이고, 퀴즈 HTML은 생성 결과다. MD에는 정답과 보기별 해설을 넣지 않는다. 새 원본·engine·`src`·source graph부터 이 규칙을 적용하고, 기존 HTML-only 퀴즈는 호환을 위해 현상 유지한다.
- 기존 PDF-only 매핑표는 단일 출처일 때 숫자 문항 번호 첫 열을 유지하고, 여러 PDF 출처일 때는 §13의 `출처 | 문항 번호` 형식을 유지한다. web bank가 추가된 회차는 이 legacy 표와 별도로 **WEB 문항 매핑** 표를 만들며, 그 헤더만 `| 출처 | 문항 ID | 질문 요약 | 절 | 상태 |`라는 정확한 다섯 열을 쓴다. WEB 표에는 원본 bank ID를 deferred까지 각각 한 번씩 적고, HTML `QUIZ`에는 legacy 감사 문항과 included/review web 활성 문항을 함께 넣는다.
- html은 본문을 복사하지 않는다. 해설에서 `→ MMDD.md §N-N 참조`로 넘긴다.
- 이 규칙이 무너지면 두 파일이 서로 다른 말을 하기 시작하고, 노트는 자산이 아니라 부채가 된다. `tests/test_note_MMDD.py`가 기계로 막는다.

### ELI5 파생 학습 가이드

ELI5 파일은 원천 MD와 원본 퀴즈 HTML에서 생성하는 파생 학습 자료다.
원천 두 파일의 본문 중복 금지 규칙을 ELI5 설명 생략의 근거로 쓰지
않는다. ELI5는 원본의 전체 학습 내용을 쉬운 표현과 시각 자료로
재구성하고, 원본 문제·회상 질문·복습 연결을 제공한다.

생성 절차는 .agents/skills/study-note-eli5/SKILL.md, coverage 데이터 계약은
해당 스킬의 references/coverage-contract.md를 따른다. 원본 정답·설명과
판단이 충돌하면 원문 주장과 근거를 표시하며 원천 파일을 자동 수정하지
않는다. 원천 변경 시 해당 가이드와 검토 기록을 재확인한다.
ELI5 가이드 및 파이프라인 산출물은 정리노트 루트를 깨끗하게 유지하기 위해
`정리노트/eli5/` 하위에 위치한다 (완성본 `MMDD-eli5.html`, 메타데이터 `meta/`, 소스 `src/`, 구버전 `archive/`).
coverage JSON은 제작·검증용이며 브라우저에서 불러오지 않는다.

일반 ELI5 요청은 완성본만 인계한다. 원본 노트에서 포함·복습·보류 문항의
전체 집합을 question-scope lock으로 먼저 고정하고, coverage의 문항 집합과
정확히 일치시킨다. 문항 상태를 바꿀 때는 원본 근거를 남기고 ID는 삭제하지
않는다. 포함·복습 문항은 정답을 열기 전의 설명만으로 풀 수 있어야 하며,
문항별 풀이 검토 기록이 없으면 complete로 처리하지 않는다.

일부 범위 결과는 사용자가 명시적으로 요청한 경우에만 허용한다. 파일명과
화면에 partial을 표시하고 누락 문항을 공개하며, complete 검증은 금지한다.

## 7. HTML 제약

- `file://`로 여는 로컬 파일이다. **외부 `fetch()`는 CORS로 차단된다.** 문항 데이터를 별도 JSON으로 뺄 수 없다 — `<script>` 안에 인라인한다.
- 외부 CDN·빌드 도구 금지. 문제 JSON과 검증을 통과한 SVG는 생성할 때 HTML 내부에 삽입하며 브라우저에서 외부 파일을 가져오지 않는다.
- 그림은 원본과 대조하여 표지와 의미를 보존하고, 편집 가능하며 오프라인인 형태로 유지한다. 인라인 SVG는 이 요구를 충족하는 원본 표현·편집성·오프라인 삽입 방식이다.
- 재사용 형태는 "엔진 + 데이터 분리"가 아니라 **"`정리노트/_template.html` 복사 후 상단 데이터 블록만 교체"**다.

## 8. ASCII 다이어그램과 기호

- 코드블록 **안에는 영문·기호·숫자만** 쓴다. 한글은 폰트마다 폭이 달라 정렬이 깨진다. 한글 설명은 코드블록 바깥 줄로 뺀다.
- **매핑표 외의 표에는 `| 1 |` 같은 맨숫자 첫 열을 쓰지 않는다.** 매핑표의 문항 번호를 뽑는 정규식(`^\| *[0-9]+ *\|`)에 걸려 테스트가 오검출한다. 번호가 꼭 필요하면 `1.` 이나 항목 이름으로 대체한다.
- **md 전체에서 원문자를 쓰지 않는다.** 목록 번호는 `(1) (2) (3)`. 답이 새는 형태는 반드시 보기 기호를 동반하므로, 원문자를 통째로 금지하는 것이 가장 싼 유출 방지 장치다. 테스트가 강제한다.

## 9. git

`정리노트/`, `tests/`, `scripts/`, `docs/`, `.agents/`, `.claude/`, 그리고 이번 회차 `STT/MMDD*.md`를 파일별로 add 한다. 이번 웹과제에 해당하는 `웹과제/` bank JSON·SVG·scope/source도 개별 파일만 명시할 수 있다. `git add .`이나 디렉터리 전체 추가는 하지 않는다. 소스 자료(STT·강의노트·교과서 PDF)는 이미 추적 중이다.

⚠️ **`*.zip`은 절대 add 하지 않는다.** 강의 플랫폼에서 통째로 내려받은 `아카이브.zip`이 강의노트·교과서 폴더에 떨어지는데, 교과서 쪽은 **205MB**다. `.gitignore`가 `*.zip`으로 막고 있으나 `git add -f` 하지 말 것. 커밋 전 `git status` 로 zip이 staged 아닌지 확인한다.

## 11. 문항 데이터 만들기

등록된 웹 문항은 `웹과제/<장>/questions.json`이 원문·관찰 기록·분석의 유일 원천이다. 모든 보기의 선택 적합성과 근거를 검토하고, 그림 의존 문항은 정답을 열기 전의 그림·설명으로 풀 수 있게 한다. `.venv-question-bank/bin/python -m scripts.question_bank validate BANK --complete`가 성공하기 전에는 미검토 항목을 누락처럼 취급하지 말고 구체적 필드와 source를 보고하여 검토 후 진행한다. 세부 데이터 형식은 `웹과제/question-bank.schema.json`과 생성 도구 계약을 따르며 여기서 다시 복제하지 않는다.

장별 bank는 특정 날짜 노트의 소유물이 아니라 여러 회차가 공유하는 근거다.
각 요청 MMDD는 사용자 요청과 실제 STT로 날짜·범위를 확정하고, bank 날짜나
파일명에서 새 회차를 추론하지 않는다. bank를 쓰는 각 MMDD의 WEB 표와 scope는
전체 원본 ID를 그 회차 기준으로 included/review/deferred 분류한다.

현재 `_template.html`의 `QUESTION-DATA` marker 안에 새로 작성하는 `META`와 `QUIZ`는 PDF-only 회차도 JSON-compatible이어야 한다. key와 문자열에 쌍따옴표를 쓰고 JavaScript 전용 literal을 넣지 않는다. marker가 없는 기존 legacy HTML은 계속 읽을 수 있다.

이 legacy read compatibility는 과거 artifact의 일괄 재작성을 허용하지 않는다.
기존 회차를 명시적으로 업데이트하면서 bank를 결합할 때는 current template과
strict JSON marker 계약으로 생성한다.

**문제지에는 정답이 빨간 글씨로 이미 표시되어 있습니다.** 텍스트로 뽑으면 색 정보가 날아가 안 보입니다. PyMuPDF로 `dpi=170` 렌더링해서 눈으로 확인하세요.

⚠️ **그 정답 키를 그대로 믿으면 안 됩니다.** 1강 합본 40문항 중 **3개가 틀렸습니다**(2번 · 30번 · 38번). 모든 문항을 자기 지식으로 대조하고, 판단이 어긋나면:

- 정답(`answer`)은 **옳다고 판단한 쪽**으로 둔다
- `keyNote`에 "인쇄된 답안지에는 X로 표시되어 있으나 오류로 판단됩니다"를 적어 함께 띄운다
- md 매핑표 상태 열에 `⚠️ 답안지 오류` 를 표시한다

답안지를 맹신하지 않게 만드는 편이 오히려 학습에 낫습니다. 다만 **어긋난다고 조용히 고치지 말고 반드시 드러내십시오.**

**보기가 없는 빈칸 채우기 문항**은 원문에 답이 그대로 인쇄되어 있습니다. 퀴즈로 만들려면 보기를 구성하고 `keyNote`에 그 사실을 밝힙니다.

**퀴즈 항목 스키마**

```js
{ n, src /* 선택, n 바로 다음 — §13 */, q, opts, answer /* 0-based */, why, trap: {오답인덱스: 진단}, keyNote /* 선택 */, ref }
```

- `why` 는 예외 없이 답니다. 근거 없는 정답표는 암기만 유도하고, 보기가 살짝 바뀐 실제 시험에서 무너집니다.
- `trap` 은 "고를 법한 오답"에만. 전 보기에 달 필요 없습니다.
- `ref` 는 md의 `### §N-N ...` 헤딩과 **글자 단위로** 일치해야 합니다. 테스트가 검사합니다.

## 12. 스킬과 생성기

절차는 `/summary-note MMDD` 스킬의 canonical 파일 `../.agents/skills/summary-note/SKILL.md`가 맡는다. `.claude/skills/summary-note/SKILL.md`는 그 파일을 가리키는 얇은 진입점만 둔다. **규칙이 바뀌면 이 파일을, 절차가 바뀌면 canonical SKILL.md를** 고친다. 둘에 같은 내용을 쓰지 않는다.

테스트 파일은 손으로 베끼지 않는다:

```bash
python3 scripts/new_note_test.py MMDD --quiz 7,8,11 --scope-terms 세포골격,확산 --prior 0908
```

html 은 `정리노트/_template.html` 을 복사해(`cp 정리노트/_template.html 정리노트/MMDD.html`) 상단 데이터 블록만 교체한다. md 는 직전 회차를 예시로 보고 새로 쓴다. 이 둘은 판단 작업이라 스크립트화하지 않는다.

## 13. 한 회차가 두 장에 걸칠 때

"날짜 하나 = 회차 하나" 는 그대로다. 파일을 장별로 쪼개지 않는다.

- **§ 번호는 파일 안에서 연속**한다(§1…§N). 장이 바뀌어도 1부터 다시 시작하지 않는다. `ref` 가 파일 안에서 유일해야 하기 때문이다.
- 장이 바뀌는 자리에 **구분선 헤딩** `## ── 2장 세포호흡과 광합성 ──` 을 둔다. § 가 아니고 `ref` 대상도 아니다.
- ✂️ 는 **개념 중간에서** 끊길 때만. 장이 자연스럽게 끝나는 자리는 구분선이 맡는다.
- 매핑표 첫 열에 **출처**(`1강`, `2강`)를 둔다: `| 1강 | 32 | 무엇을 묻는가 | 노트 위치 | 상태 |`.
- 퀴즈 항목에 `src:"1강"` 을 **`n` 바로 다음에** 둔다: `{ n:32, src:"1강", q:… }`. 테스트가 `n` 과 `src` 를 붙여서 읽는다.
- 생성기는 `--quiz "1강:32,40" --quiz "2강:1,2"` 로 부른다. 단일 출처 회차는 지금처럼 `--quiz 7,8` 이고 `src` 를 쓰지 않는다.
- 엔진은 `src` 가 있으면 번호 앞에 붙여 보여준다. 없으면 그대로다.
