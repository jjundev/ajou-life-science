# 생명과학 인터렉티브 자료

날짜나 주제 하나로 「DNA 구조와 복제 3D」(`references/example-dna.dc.html`)와 같은 화면의 인터렉티브 자료를 만든다. 공통 셸 템플릿에 주제별 장면과 문구만 채우고, 검사·내용 검토·브라우저 확인을 통과한 것만 저장한다. 중간에 사용자에게 묻지 않고 끝에 한 번 보고한다. 커밋은 제안만 한다.

**인자**: `[MMDD | 주제]`
- 날짜: 그날 수업에서 인터렉티브로 만들 주제를 스스로 골라 **2–4개** 만든다.
- 주제(예: `오페론`, `세포 호흡`): 그 주제 **1개**를 만든다.

**산출물** (`DEST` 폴더, 번호 `NN`은 두 자리, `<이름>`은 내용을 나타내는 한국어 이름):
- `인터렉티브_NN_<이름>.html` — 브라우저에서 바로 여는 단독 파일
- `.assets/자료_인터렉티브_NN_<이름>/` — 원본 `Main.dc.html`과 `canvas.json`(나중에 Design 캔버스로 올릴 때 쓰는 매니페스트)
- 기존 `정리노트_*.html` — 해당 자료를 보며 이해할 수 있도록 관련 설명 바로 뒤에 안내·현재 탭 링크를 추가한다.

**진행 표시**: 단계마다 한 줄만 쓴다. 예: `3/8 작성 중: 주제 3개 (병렬)`

**서브에이전트가 없는 환경(Codex 등)**: 병렬 에이전트 대신 같은 브리프로 주제를 차례로 직접 쓰고, 5단계 내용 검토는 새 세션에서 한다. 모델 지정은 Claude에서는 그대로, 다른 모델 환경에서는 opus→sol로 바꿔 읽는다.

**경로 약속**
- `SKILL` = 이 파일이 있는 폴더의 실제 절대 경로. 심볼릭 링크(예: `.claude/skills/bio-interactive`)로 불렸으면 링크를 푼 원본 경로를 쓴다.
- `REPO` = 저장소 루트
- `RUN` = `<scratchpad>/bio-interactive/<인자>/` (scratchpad가 없으면 `/tmp/bio-interactive/<인자>/`). 주제마다 `RUN/<n>/`(n = 1, 2, …).
- `DEST` = 1단계 `resolve.cjs` 출력의 `folder`
- 셸 상태는 Bash 호출 사이에 이어지지 않는다. `$SKILL`, `$RUN`, `$REPO`, `$DEST`는 실행할 때마다 실제 절대 경로로 바꿔 쓰거나 같은 Bash 호출 맨 앞에 세미콜론으로 먼저 설정한다(`SKILL=…; RUN=…; node "$SKILL/scripts/check.cjs" …`). `cd`는 쓰지 않고 파일도 절대 경로로 넘긴다.
- 파일명은 macOS에서 NFD로 저장된다. 경로를 손으로 짓지 말고 `resolve.cjs`가 돌려준 경로를 쓴다.

**하지 않는 것**: 링크 안내 외 정리노트 본문·위젯·스타일·스크립트 수정, 정리노트 MD·PDF 및 복습문제 수정, 기존 `인터렉티브_*`·`3D모형_*` 덮어쓰기, Design 캔버스 게시, 커밋.

**기존 자료 연결만 요청한 경우**: 자료를 새로 생성하지 않는다. 요청한 범위의 정리노트 HTML과 기존 `인터렉티브_*`·`3D모형_*`를 읽고 `references/note-links.md`대로 연결 명세를 만든 뒤 8–9단계만 실행한다. `전체`는 `복습노트/`의 기존 자료 전체를 뜻한다. 자료가 이미 있어 생성 후보가 0개인 상황과 연결 작업을 구분한다.

## 절차

### 0. 준비
`REPO`에 `복습노트/`, `STT/`, `강의노트/`, `교과서/생명과학_기초와_응용_2판/`이 있는지 확인한다. 없으면 "생명과학 저장소에서만 동작합니다"라고 알리고 멈춘다. `node -v`가 20 이상인지 확인한다.

### 1. 대상 풀기
```bash
SKILL=…; REPO=…; RUN=…; mkdir -p "$RUN" && node "$SKILL/scripts/resolve.cjs" "$REPO" "<인자>" | tee "$RUN/target.json"
```
- 인자 `MMDD-MMDD`는 그 이름의 범위 폴더가 있을 때만 날짜로 쓴다(없으면 `NO_TARGET`).
- 출력: `kind`(date|topic), `folder`(= `DEST`), `exists`, `date`, `notes`(`.assets/`의 정리노트 `.md`), `noteHtml`(같은 폴더의 기존 정리노트 HTML 실제 경로 목록), `stt`, `existing`(같은 폴더 `인터렉티브_*`·`3D모형_*`와 `<title>`), `next`(다음 번호).
- 날짜가 `0922-0924` 같은 범위 폴더 안이면 그 폴더가 나온다. 폴더는 없고 STT만 있으면 `exists: false`로 새 폴더 자리가 나온다.
- 주제는 정리노트 본문(링크 글자 제외)에서 찾고, H2·H3 제목에 나온 폴더를 먼저, 그다음 가장 최근 폴더를 고른다. 어느 정리노트에도 없으면 `복습노트/주제별/`이 나온다(교과서·강의노트로 만든다).
- `{"error":"NO_TARGET"}` → 「대상 없음: <인자>의 복습노트 폴더와 STT가 없어요」라고 보고하고 멈춘다. `NO_ARG` → 사용법을 보여 주고 멈춘다.

### 2. 주제 고르기
`references/topic-selection.md`대로 한다.
- 날짜: `notes`의 H2·H3와 「직접 해 보기」 블록으로 후보를 만들고 점수를 매긴다. `notes`가 비었으면 `stt`와 그 장의 `강의노트/N장 *.pdf`로 후보를 만든다. `existing` 제목과 겹치는 후보는 뺀다. 개수는 2–4개.
- 주제: 인자 그대로 1개. 정리노트에서 그 주제가 나온 절을 근거로 쓴다.
- 후보가 0개면 「후보 없음」과 이유를 보고하고 멈춘다.
- 주제마다 브리프를 `RUN/<n>/brief.md`에 쓴다(항목은 `references/topic-selection.md`).
- `noteHtml` 본문에서 연결할 절과 관찰 포인트를 골라 브리프의 「정리노트 연결」에 기록한다. 대응 절이 없으면 이유를 기록하고 생성은 계속한다.

### 3. 작성 (주제당 opus 에이전트 1명, 한 메시지에서 병렬)
먼저 주제마다 템플릿을 복사한다.
```bash
SKILL=…; RUN=…; for n in 1 2; do mkdir -p "$RUN/$n" && cp "$SKILL/assets/template.dc.html" "$RUN/$n/Main.dc.html"; done
```
각 작성자에게 넘길 것:
- 고칠 파일 `RUN/<n>/Main.dc.html`(이 파일만 고친다)과 브리프 `RUN/<n>/brief.md`
- 계약 `references/scene-api.md`, 디자인 규칙 `references/design.md`
- 품질 기준 예시 `references/example-dna.dc.html` — 장면을 실제 구조(개수·방향·비율)로 모델링하는 방식, 단계·꼭 기억해요 문구의 밀도를 본다. 이 예시는 예전 형식(`tabS` 등)이라 셸 부분은 따라 하지 않는다.
- 근거 자료: `notes`, `stt`, 해당 장의 `강의노트/N장 *.pdf`, `교과서/생명과학_기초와_응용_2판/0N장_*.pdf`
- 지시: 수업에서 다룬 내용만 쓰고, 교과서에서 보충한 것은 패널 문구에 「(교과서 보충)」으로 표시한다. 단계에 `f`를 쓰면 그 단계 과정이 화면에 다 보이는 지점에 두고, `phase`에 그 지점 재생 바 글자에서 ` · `로 나뉜 과정 이름 하나를 그대로 적는다(다음 과정의 시작점에 두지 않는다). 끝내기 전에 `node "$SKILL/scripts/check.cjs" "$RUN/<n>/Main.dc.html"`이 `ok`를 내야 한다.
- 돌려받을 것: 제목, 파일 이름(내용을 나타내는 한국어로 쓰고 고유명사·분자 기호만 영어, 띄어쓰기는 `_`, 예: `lac_오페론_스위치`, `전사와_RNA_가공`), 모드·단계 목록, 단순화한 것, 확신 없는 사실.

### 4. 검사
```bash
SKILL=…; RUN=…; for n in 1 2; do echo "== $n"; node "$SKILL/scripts/check.cjs" "$RUN/$n/Main.dc.html"; done
```
모두 `ok`여야 한다. 오류(`SHELL_MISSING`, `HOLE_UNKNOWN`, `HOLE_SYNTAX`, `EVENT_UNSUPPORTED`, `HEX_IN_MARKUP`, `TOPIC_INVALID`, `STEP_OFF_PHASE`, `RENDER_THROWS`, `DRAW_THROWS`, `SCENE_EMPTY`, `SCENE_NAN`, `TEMPLATE_LEFT`)는 출력 줄 그대로(예외 문장이 `—` 뒤에 붙어 있다) 그 작성자에게 한 번 돌려보내 고친다. 그래도 남으면 그 주제는 「보류」.

### 5. 내용 검토 (별도 opus 에이전트, 주제마다 1명, 병렬)
작성자가 아닌 새 에이전트에게 `Main.dc.html`, 브리프, 근거 자료, 그리고 단계마다 화면에 나오는 값(`node "$SKILL/scripts/steps.cjs" "$RUN/<n>/Main.dc.html"` 출력)을 주고 다음을 대조하게 한다.
- 패널 문구·단계·꼭 기억해요가 정리노트·교과서와 맞는지(용어, 방향 5′→3′ 같은 사실, 효소·분자 이름)
- 장면 모델이 사실과 맞는지(개수, 순서, 방향, 상대 크기, 무엇이 무엇에 붙는지)
- 수업 밖 내용에 「(교과서 보충)」 표시가 있는지
- 단계 문구가 그 지점의 재생 바 글자·캔버스 설명·패널 값과 맞는지
Critical·Important는 그 작성자에게 한 번에 모아 돌려보내 고치고 4단계를 다시 한다. 수정은 한 번만 한다. 남으면 「보류」.

### 6. 브라우저 확인
통과한 주제를 `RUN`에 빌드하고 `RUN`을 http.server로 띄워 내장 브라우저로 연다.
```bash
SKILL=…; RUN=…; for n in 1 2; do node "$SKILL/scripts/build.cjs" "$RUN/$n/Main.dc.html" "$RUN/$n/preview.html"; done
```
주제마다 1440×900과 375×812에서 각각 라이트·다크로 확인한다.
- 콘솔 오류 0, 375px에서 가로 스크롤 없음
- 모드 전환, 재생·일시정지·스크럽·속도(재생 모드)
- 단계 누르기: `node "$SKILL/scripts/steps.cjs" "$RUN/<n>/Main.dc.html"` 출력과 화면(재생 바 글자, 캔버스, 패널)을 단계마다 대조한다. 출력의 번호는 `STEPS` 전체 순서이고 화면 번호는 모드 안에서 1부터라, 출력의 `mode`로 그 모드 목록에서 찾는다
- 패널 열고 닫기(375px는 서랍, Escape로 닫힘), 넓은 화면 패널 너비 조절
- 회전 모드에서 끌어서 회전, 확대·축소·시점 처음으로
- 캔버스 라벨이 겹치거나 화면 밖으로 잘리지 않음, 다크에서 색이 묻히지 않음
고친 것이 있으면 4단계부터 다시 한다(한 번). 그래도 문제가 남으면 「보류」.

### 7. 저장
통과한 주제를 점수 순으로 주제마다 한 번씩 `save.cjs`로 저장한다(셸 반복문 없이 한 줄씩). `<이름>`은 3단계에서 돌려받은 파일 이름이다. 다음 빈 번호를 고르고(`인터렉티브_NN_*`도 `.assets/자료_인터렉티브_NN_*`도 없는 번호), 덮어쓰지 않으며, `RUN`에는 아무것도 쓰지 않는다.
```bash
SKILL=…; RUN=…; DEST=…; node "$SKILL/scripts/save.cjs" "$RUN/<n>/Main.dc.html" "$DEST" "<이름>"
```
출력 JSON(`{"nn", "html", "dir"}`)의 `dir`에 `Main.dc.html`과 `canvas.json`이 생긴다. `html`을 내장 브라우저로 한 번 열어 콘솔 오류가 없는지만 다시 본다.

### 8. 정리노트 연결
`references/note-links.md`대로 저장에 성공한 실제 `html` 경로와 브리프를 대조하여 `RUN/note-links.json`을 만든다. 관련 설명 바로 뒤에 관찰·조작할 포인트를 담은 자연스러운 한 문장과 현재 탭 링크를 넣는다. 노트별 연결을 모아 한 번씩 수정한다.
```bash
node "$SKILL/scripts/link-notes.cjs" "$RUN/note-links.json" --dry-run
node "$SKILL/scripts/link-notes.cjs" "$RUN/note-links.json"
```
- 새 링크는 상대 경로와 `target="_self"`를 쓴다. 안내 문장은 자연스럽게 마무리하고 `(새 탭)` 같은 표시 문구는 붙이지 않는다. 기존 같은 목적지 링크는 중복하지 않고 target만 보정하며 rel 등 다른 속성은 보존한다. 새 링크에는 새 탭용 rel을 추가하지 않는다.
- `skipped`는 이유를 보고하고 다른 연결을 계속한다. 저장된 자료를 삭제하거나 다른 절에 임의로 연결하지 않는다.
- 수정한 노트의 연결 문맥을 브라우저에서 읽고 대표 링크를 눌러 현재 탭에서 올바른 자료로 이동하고 뒤로가기로 정리노트에 복귀하는지 확인. 링크 경로는 모두 실제 파일 존재를 검사한다. 재실행 결과 노트별 `changed: false`여야 한다.

## 실패 처리
| 상황 | 처리 |
|---|---|
| `NO_TARGET` | 「대상 없음」 보고 후 멈춤 |
| 후보 0개 | 「후보 없음」과 이유 보고 후 멈춤 |
| 검사·내용 검토·브라우저 확인 실패(수정 1회 후에도) | 그 주제만 저장하지 않고 「보류」, 나머지는 계속 |
| 모든 주제 보류 | 파일 없이 보고만 |
| 번호 자리에 이미 파일이나 자료 폴더가 있음 | `save.cjs`가 다음 빈 번호로 넘긴다(덮어쓰지 않음) |
| 연결할 노트·절·자료 누락 또는 모호함 | 해당 연결만 skipped와 이유 보고, 저장된 자료와 다른 연결은 유지 |

## 템플릿 고치기
셸(패널·테마·재생 바·그리기)을 바꿔야 하면 `assets/template.dc.html`을 고치고 `references/scene-api.md`를 맞춘 뒤 테스트를 돌린다.
```bash
SKILL=…; node --test "$SKILL"/tests/*.test.cjs
```
템플릿 자체를 미리 보려면 `RUN`에 빌드한다(`build.cjs`는 원본 폴더에 `canvas.json`이 없으면 만들므로 `assets`에 생기면 지운다).
