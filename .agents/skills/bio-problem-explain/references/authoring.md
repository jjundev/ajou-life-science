# 문제풀이 입문 설명 저작

공부가 덜 되어 용어만 알아보거나 감으로 답을 고르는 학생도, 무엇을 확인하면 선지를 판단할 수 있는지 배우게 설명해요. 객관식의 기본 흐름은 **문제의 요구 → 판단 기준 → 각 선지에 기준 적용 → 판정과 답 → 확인**이에요. 학생이 실제로 어떤 오개념을 가졌는지는 풀이기록 없이 단정하지 않아요. 기출 합본·웹과제·교과서·강의노트·기존 정리노트의 관련 페이지를 먼저 확인해요. STT는 필요한 경우 보조로 사용하고 수업 밖 보충은 표시해요.

각 `explanations/pN.html`은 아래 필수 직계 구역을 각각 하나 포함해요. 선택 구역은 별도의 도움이 있을 때만 넣고, 없으면 제목까지 생략해요. 작성한 구역은 표 순서대로 배치하고 중복·빈 구역을 넣지 않아요. 본문 답은 모두 펼쳐요.

| data-explanation | 작성할 내용 |
|---|---|
| understand | **필수.** 비교 대상·핵심 조건·구할 것을 짧게 읽어요. 부정형이면 질문 방향을 굵게 적어요. `layer eli5` |
| recall | **필수.** 문제의 단서 → 필요한 개념의 뜻과 원리 → 확인할 판단 기준·적용 조건. `layer formal` |
| start | **선택.** 계산·교배표·방향 표시 등 실제 첫 조작이 필요할 때 그 첫 줄을 보여 줘요. recall이나 답의 반복이면 생략해요. |
| solve | **필수.** 모든 선지의 실제 표현에 기준을 적용해 판정하고 마지막에 답을 써요. `layer formal` |
| verify | **필수.** 완성 답과 다른 경로의 확인(소거 결과·교과서의 관련 원리 대조·교배표 재계산 등)을 짧게 밝혀요. |
| pitfall | **선택.** solve만으로 해소되지 않은 구체적인 혼동과 구별 방법이 있을 때 써요. 아래 문항 결함·인쇄 정답 오류의 대처가 필요한 경우에도 써요. `layer warn` |
| retry | **선택.** 설명을 닫고 실제로 판단해 볼 과제가 있을 때 1~3개 써요. 항목마다 `<li>` 하나(`<ul><li>…</li></ul>`). 일반적인 복습 당부는 생략해요. |

필수 순서는 `understand → recall → solve → verify`이고, start는 recall 뒤, pitfall·retry는 verify 뒤에 들어가요. 기존 일곱 구역도 각각 역할이 있으면 유효해요. recall의 제목은 **이 문제를 봤을 때 떠올릴 개념과 공식**이에요. 문제의 어떤 표현·조건에서 개념을 떠올리는지 설명한 뒤 **어떤 대상의 어떤 성질·관계·수치를 확인할지**를 밝혀요. 필요한 영어 전문용어와 기호의 뜻, 원리가 성립하는 조건을 입문형으로 연결해요. 기준 수는 문항에 맞춰 정하고, 서로 다른 개념을 묻는 선지에 하나의 기준을 억지로 적용하지 않아요.

```html
<div class="layer formal" data-explanation="recall">
  <h4>이 문제를 봤을 때 떠올릴 개념과 공식</h4>
  <p>‘서로 다른 CCU와 CCC가 모두 프롤린을 지정한다’에서 코돈(codon)과 아미노산의 대응을 봐요.</p>
  <p>판단 기준은 무엇이 여러 개인지예요. 여러 코돈이 한 아미노산을 지정하면 중복성(redundancy), 생물 사이에서 같은 코돈의 지정 아미노산을 비교하면 보편성(universality)을 판단해요.</p>
</div>
```

공통 개념은 한 번 설명하고, 서로 다른 개념을 요구하는 소문항은 (a), (b)처럼 구분해요. 계산이 필요 없는 정성 문항에서는 정의·판단 기준과 근거를, 유전 계산 문항에서는 대립유전자 기호와 비율 공식을 설명해요. 원리의 적용 조건과 한계를 유지하고 필요조건을 충분조건으로 뒤집지 않아요. 한두 사례가 맞는다는 것으로 일반 진술을 증명하지 않아요.

## 명칭과 판별 경계

[공통 피드백](../../bio-review-pack/references/note-feedback.md)의 해당 문항 판별 기준을 원천과 대조해 적용해요. recall에는 낯선 이름에서 개념으로 연결되는 짧은 대응을, solve에는 인접 오답과의 결정적 차이를 적어요. 추가 코칭이 필요하면 pitfall을 사용해요. 예를 들어 이 장 근거가 확인된 정지/넌센스/nonsense는 ‘아미노산 지정 코돈→종결 코돈’을 뜻하며 번역틀 이동과 구별해요. 다른 장에는 그 장 자료에서 확인한 대응만 써요. 영어 병기가 이미 있는 노트라면 누락이라고 진단하지 않아요.

단위가 핵심이면 understand에서 비교 대상을 명확히 읽고 recall에서 대상·조건·결과를 연결해요. 긴 설명은 solve·start·pitfall에 복제하지 않아요. 원문에 동의어·번역·방향 가정을 끼워 넣지 않고, 필요한 가정·결함은 기존 공개 규칙대로 해설에서 밝혀요. 해설·답이 보이는 상태의 성공은 독립 회상이나 학생 숙달 확인이 아니에요. retry는 설명을 닫고 이름 없이 현상을 설명하거나 다른 이름에서 개념을 떠올리게 할 수 있지만 수행 여부를 추정하지 않아요.

## 보기 판정

solve는 모든 보기를 빠짐없이 다루고, 각 문단에서 **해당 선지의 실제 표현·수치·관계 → 적용할 기준과 대입 결과 → 판정**을 연결해요. 판정부터 쓸 수도 있지만, 기준을 어떻게 적용했는지가 문단 안에 드러나야 해요. ‘정의와 달라요’처럼 결론만 쓰거나 선지를 바꾸어 말하는 것으로 끝내지 않아요. 공통 원리 전체는 복제하지 않고 각 선지에 적용한 부분만 설명해요.

판정 문단은 보기 라벨(`(n)`, `A`, `ㄱ`)로 시작하고, 끝의 별도 문단에 답을 써요. 화면에서는 라벨로 시작하는 문단마다 보기별 카드로 보이고 결론은 카드 밖에 남아요. 문제 패널에서 보기를 누르면 해당 카드로 이동하므로 **보기 라벨과 설명하는 주장의 대응**을 원문과 확인해요. 문제 패널의 방식·위치는 `od-panels:explain:v2:prob`에 기억돼요.

- **진술형**: 내용상 맞아요/틀려요와 정답으로 선택할지를 구별해요. 맞는 선지도 어떤 조건·원리와 일치하는지 설명해요.
- **용어·사례 선택형**: 그 용어의 정의를 설명하고, 지문의 어떤 관계가 정의에 해당하는지 또는 어떤 비교가 없어 해당하지 않는지 밝혀요. 올바른 정의 자체를 틀린 사실로 표현하지 않고 ‘이 사례의 답으로 적합/부적합’이라고 구별해요.

- **ㄱㄴㄷ형**: 진술 ㄱ, ㄴ, ㄷ을 각각 맞아요/틀려요로 먼저 판정하고, 맞는 진술의 조합과 일치하는 보기 번호를 고른 뒤 답을 써요. 조합 보기를 진술 판정 없이 바로 고르지 않아요.
- **부정형**("틀린 것", "아닌 것", "옳지 않은 것"): understand에서 질문 방향을 `<strong>`으로 굵게 적어요. 진술형은 내용의 참·거짓을 판정한 뒤 틀린 진술을, 용어·사례형은 해당 여부를 판정한 뒤 사례에 해당하지 않는 보기를 고른다고 결론에 밝혀요. 용어의 정의가 옳다는 것과 부정형 질문의 답으로 선택된다는 것을 구별해요. ‘항상’ 같은 절대 표현만으로 틀렸다고 판단하지 않아요.
- **모두 맞다/해당 없음형**: 다른 보기들의 판정을 먼저 마치고 그 결과로 판단해요. ‘일반적인 설명이라 맞아요’로 독립 판정하지 않아요.
- 유전 계산: 부모 유전자형과 생식세포를 쓰고 교배표(Punnett square)나 곱셈 규칙으로 비율을 구해요. 표의 각 칸을 생략하지 않아요.

verify는 소거 결과(질문 방향에 맞는 보기가 몇 개인지), 교과서의 관련 원리 대조(자료·쪽과 확인한 내용), 교배표 재계산(다른 방법으로 다시 센 비율) 중 하나 이상으로 답을 다른 경로에서 확인해요. solve를 다시 풀어 쓰거나 ‘교재와 일치해요’만 반복하는 것은 검산이 아니에요. 상세 대조 기록은 evidence에 보관하고 본문에는 무엇을 확인했는지 짧게 적어요.

`source.json`의 subparts가 a,b이면 **solve와 verify 모두** 각각 아래 표지를 한 번씩 사용해요. 단일 문항도 `main` 표지가 필요해요. 보기 목록(`ul/ol.choices`)은 소문항이 아니에요.

```html
<div class="layer formal" data-explanation="solve">
  <h4>왜 이렇게 푸는지 함께 따라가요</h4>
  <div data-subpart="main">
    <p>A. 이 사례에는 부적합해요. 보편성은 생물 사이에서 같은 암호를 공유하는지 비교해야 하지만, 지문은 서로 다른 생물을 비교하지 않아요.</p>
    <p>B. 이 사례에 적합해요. CCU와 CCC라는 코돈 둘이 프롤린 하나를 지정하므로 ‘여러 코돈 → 한 아미노산’ 기준을 충족해요.</p>
    <p>따라서 답은 B, 중복성이에요.</p>
  </div>
</div>
<div class="layer formal" data-explanation="verify">
  <h4>완성 답과 검산</h4>
  <div data-subpart="main"><p>답 B. 대응을 거꾸로 세어도 프롤린 하나에 코돈 둘이 연결되므로, 한 코돈에 여러 아미노산이 연결되는 관계와 구별돼요.</p></div>
</div>
```

`~해요` 체와 영어 전문용어 병기를 사용해요. 기존 원문·조건·질문·보기·그림은 조립기가 붙이므로 재작성하지 않아요. 기출 원문은 조립기가 문제 안에 "기출 원문 보기"로 접어 보존해요.

마지막에 직계 `<div class="sum" hidden>` 하나를 넣어 핵심 판단 기준과 결론을 짧게 요약해요. 첫 줄·함정·검산 그룹은 따로 볼 가치가 있을 때만 넣고 본문 전체를 복제하지 않아요. 이 요약만 UI의 우측으로 이동해요. 본문 hidden/details, 인라인 style, 실행 코드와 on* 속성은 사용할 수 없어요. 수식은 `$...$`/`$$...$$`, 그림은 저장소 내부 파일 상대경로나 정적인 inline SVG를 사용해요. 소문항 표지를 임의로 합치지 않아요.

개념 링크는 실제 존재하는 정리노트의 문항/토픽 anchor만 연결해요. 조각의 상대 링크와 그림은 입력 카드 HTML의 디렉터리 기준이에요.

## 필요한 내용만 남기기

문장마다 **지워도 기준 이해·선지 판정·오류 방지에 손실이 없는지** 확인하고, 손실이 없으면 삭제하거나 합쳐요. 발문을 길게 반복한 문장, 여러 구역에 복제한 정의·결론, 판정에 쓰이지 않는 배경지식·수치, ‘잘 기억해요’ 같은 당부가 대상이에요. 초보자에게 필요한 개념의 뜻·이유·적용 조건은 남겨요. 출처·가정·문항 결함·정답 충돌 공개도 삭제하지 않아요. 분량이나 문장 수를 맞추려고 필요한 설명을 자르거나 선택 구역을 채우지 않아요.

## 수식과 여백

짧은 수식은 문장 안에 두고 수식마다 스크롤 컨테이너를 만들지 않아요. 여러 행렬 답은 각각 독립된 줄에 배치해요. 긴 유도는 의미가 유지되는 등호·항을 기준으로 여러 식으로 나눠요. 한 수식의 여러 줄이 필요하면 `aligned`를 사용하고 수식 내용을 생략하지 않아요. 원문은 다시 쓰지 않고 템플릿의 표시 규칙으로 배치해요.

요약은 `<div class="summary-group"><h4>첫 줄</h4><p>...</p></div>`처럼 의미별로 묶어요. 제목과 내용 사이는 12px, 요약 그룹과 설명 구역 사이는 24px, 소문항 사이는 16px인 템플릿 규칙을 사용해요. 간격을 만들려고 빈 문단이나 연속 br을 넣지 않아요. 화면을 바꾸거나 요약 너비를 조절한 뒤에도 수식이 읽혀야 해요.

## 원자료 충돌

원문 오타·참고 답 오류를 몰래 수정하지 않아요. 카드의 답안지(정답·풀이), 기출 합본(`23, 24 소스/N강 합본.pdf`), 웹과제(`웹과제/N장/questions.json`), `.pack/key-check.md`의 정답 대조가 서로 다르면 disputed로 남기고 조건과 다른 해석을 밝혀요. `.pack/key-check.md`나 `.pack/question-audit.md`에 보류·모호로 적힌 문항도 같은 방식으로 다뤄요. 두 파일은 일부 팩에만 있어요. 없으면 `.pack/variants.md`의 `의도한 정답과 이유` 열과 대조하고, 파일이 없다는 것만으로 disputed로 두지 않아요. 교과서·강의노트·STT·정리노트의 설명이 충돌할 때도 disputed로 남겨요. 실제 자료를 필요한 범위에서 읽고 자료/쪽을 기록해요. 

원자료 충돌은 두 경우로 나눠요.
- (A) 충돌: (C)에 해당하지 않으면서 카드 정답이 인쇄 답안지·기출·웹과제·key-check 판단 답 또는 독립 재풀이 답과 다르면 disputed로 남기고 그 팩은 발행을 보류해요.
- (B) 결함 공개: 카드 정답이 인쇄 답·key-check·독립 재풀이와 모두 같고 문항 표현만 결함(다른 보기도 논쟁 여지, 방향·가닥 누락, 오타)이면 설명을 써요. understand에 `<strong>문항 결함:</strong>` 한 줄을 넣고, solve에서 논쟁 보기를 정직하게 판정해요("엄밀히는 맞을 수도 있어요 — 이유"). pitfall에는 시험 대처를 적어요. 결함이 있는 보기의 조건·유보는 verify의 소거·검산과 sum에도 유지해요. 출제 의도상 분석 답과 엄밀한 유일 정답을 구별해요. 예를 들어 분석 답이 C라도 B의 독립성 표현에 문제가 있으면 “분석 답 C / B의 독립 표현은 엄밀성 주의”를 함께 남기며 “C만 틀려요”로 단정하지 않아요. 공식 답을 확인하지 못했다면 “공식 답 미확인”을 밝히고, 답 부재 자체를 (A)의 답 불일치로 취급하지 않아요. 표현 결함이 없는 문항은 명확한 결론을 유지해요. content 검토는 understand·solve·verify·pitfall·sum에서 공개가 정확하고 일관적인지 확인해요. 이 경우는 disputed가 아니에요.
- (C) 인쇄 정답 오류: 카드 정답이 기출 인쇄 정답과만 다르고, 교과서·강의노트 근거와 독립 재풀이 답(있으면 key-check 판단 답)이 모두 카드 정답과 같으면 설명을 써요. understand에 `<strong>인쇄 정답 오류:</strong>` 한 줄로 인쇄 정답과 카드 정답을 함께 밝히고, solve에서 인쇄 정답 보기가 왜 틀렸는지 근거 쪽과 함께 판정하고, pitfall에 시험에서 인쇄 정답을 만났을 때의 대처를 적어요. 이 경우는 disputed가 아니에요.

## forecast 예상문제

명시 경로의 예상문제는 p1–p15 전체를 다루고 o1·o2 개요는 제외해요. 해당 버전 `웹과제예상/<N>장/.pack/v<K>/`의 pack.json과 blueprint.md의 기출 출처·모드·노트 앵커를 확인해요. key-check.md/variants.md 대신 이 근거를 사용해요. 원문 그대로인 문항만 원문 답과 직접 대조하고, 변형 문항은 바뀐 조건·숫자·보기 순서로 실제 재풀이해요. 새 예상문항을 실제 기출로 표현하지 않아요. original이 새 예상문항의 출처 안내이면 기출 원문이라고 주장하지 않아요.
