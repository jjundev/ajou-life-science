# 생명과학 페이지별 학습만화

기존 정리노트의 **학습·지난 수업 복습·전체 요약 페이지마다 4~8컷**을 만든다. 생물 구조를 살린 컷별 일러스트와 HTML 대사로 개념·원리·조건·혼동을 설명한다. 표지·미학습 예고·자료 링크는 만화 대상에서 제외한다. 결과는 원본 순서의 페이지, 목차, 우측 요약, 이전·다음 버튼을 가진 HTML이다. 그림이 부족한 페이지는 이유와 함께 보류하며 완성으로 세지 않는다.

**입력:** `MMDD`, 기존 `MMDD-MMDD` 폴더명, 또는 정리노트 HTML 경로. 날짜 생략·주제만·`all`은 자동 추정하지 않고 사용법과 실제 후보를 안내한다. 범위 폴더명은 날짜 사이의 모든 폴더를 일괄 실행하는 명령이 아니다.

**산출물:** 원본 폴더의 `학습만화_<원본의 날짜·주제>.html` 하나와 `.assets/자료_학습만화_<날짜·주제>/`의 그림·콘티·근거·검토·이전 버전. 새 퀴즈·정답 토글·영상·음성·PDF는 만들지 않는다. 원본 노트, 다른 스킬, 커밋·푸시는 이 호출로 수정하지 않는다.

## 준비와 경로

- `SKILL`은 이 파일의 실제 폴더(심볼릭 링크는 원본으로 해석), `REPO`는 저장소 루트다.
- `RUN`은 **비어 있는 새 폴더**다. 기본은 `REPO/tmp/bio-review-comic/<인자>-<실행ID>/`; 작업은 발행 때 전용 `.assets`에 보존한다. 자동화 브라우저의 HTTP 서버는 `REPO`에서 열어 원본 링크도 접근하게 한다.
- Python 3.10+ 표준 라이브러리만으로 CLI를 실행한다. 셸 호출 사이 변수 상태를 가정하지 않고 모든 경로는 실제 절대 경로로 전달한다. 경로 검색은 스크립트가 NFC/NFD를 처리한다.
- 아래 명령의 `python3 "$SKILL/scripts/comic.py"`를 사용한다. 이미지 생성은 내장 `image_gen` 도구가 담당하며 CLI는 생성 API를 호출하지 않는다.

## 1. 원본 추출

```bash
python3 "$SKILL/scripts/comic.py" extract --repo "$REPO" --target "1105" --run "$RUN"
```

`source.html`은 원본 스냅샷, `source.json`은 모든 토픽의 포함·제외 사유와 페이지별 근거, `storyboard.json`은 채울 콘티다. **`source.json`과 `source.html`은 편집하지 않는다.** 후보가 여러 개면 HTML 경로를 지정하고, 없으면 가능한 날짜를 안내한다. STT로 대체 생성하지 않는다.

원본의 `main article.topic` 하나가 만화 한 페이지다. 본문 전체·원본 그림·교수님 강조·주의·보충·요약을 읽는다. `source.json`의 텍스트 근거는 글의 목록이며 원본 그림 속 사실을 대신하지 않는다. 새로운 그림에도 필요한 방향·개수·비교 조건을 원본에서 확인한다. 원본의 오류나 모순이 보이면 해당 페이지를 보류하고 실제 문장을 보고한다.

첫 진행 보고에 대상 전체/포함/제외 수와 예상 컷 수(포함 페이지 × 4~8)를 적고 계속한다. 사용자가 전체 제작을 요청했다면 임의로 대표 페이지만 골라 끝내지 않는다.

## 2. 콘티

[콘티 기준](references/storyboard.md)과 [데이터 계약](references/contract.md)을 읽고 `storyboard.json`을 채운다. 출력은 다음 순서다.

1. 공통 그림 스타일·반복 대상의 모양/색/관찰 시점 약속을 `style`에 정한다.
2. 각 페이지의 핵심 질문 → 4~8개 구체적 장면 → HTML 설명/대사 → 근거 대응 → 우측 요약을 쓴다.
3. 원본 근거 **모든 항목**에 컷 번호 또는 생략 이유를 `coverage`로 남긴다. 조건·예외·오개념 판별 기준은 생략하지 않는다. 반복·주변 사례의 생략은 설명한다.
4. 페이지가 준비되면 `ready`, 해결 불가면 이유를 적고 `held`로 표시한다. 미완료 `draft`는 검사에서 실패한다.

```bash
python3 "$SKILL/scripts/comic.py" check --run "$RUN" --phase storyboard
python3 "$SKILL/scripts/comic.py" prompts --run "$RUN"
```

검사는 근거 존재·대응과 구조를 확인한다. 설명의 의미가 옳다는 판정은 4단계에서 별도로 한다.

## 3. 그림 생성과 등록

[이미지 제작](references/images.md)을 읽는다. `prompts.json`의 작업별 `prompt`를 사용해 **내장 이미지 생성 도구로 컷별 그림**을 만든다. 각각 다른 장면을 한 프롬프트의 변형 옵션으로 대신하지 않는다. 앞서 만든 대상의 외형이 중요하면 실제 이전 컷을 참조 이미지로 제공한다. 원본 텍스트를 이미지에 새기지 않고 한국어·라벨·정확한 표기는 HTML로 표시한다.

- `reusable: true`인 그림은 프롬프트와 파일 지문이 맞으므로 재사용 후보이다. 실제 장면의 적합성은 내용/그림 검토에서 확인한다.
- 생성 도구가 반환한 실제 로컬 파일을 등록한다. 파일 경로를 지어내거나 비트맵 대신 SVG·도형·빈 이미지로 채우지 않는다.
- 도구 사용 불가·아티팩트 저장 실패면 해당 페이지를 `held`로 표시한다. 별도 유료 API/키를 자동으로 사용하지 않는다.

```bash
python3 "$SKILL/scripts/comic.py" register-image --run "$RUN" --page s0-miller --panel 1 --image "/실제/생성결과.png"
python3 "$SKILL/scripts/comic.py" check --run "$RUN" --phase images
python3 "$SKILL/scripts/comic.py" build --run "$RUN"
```

도구가 이미지를 인라인으로만 반환하면 지원되는 저장 경로를 확인한다. 파일을 확보할 수 없으면 해당 페이지 보류와 원인을 보고한다. 생성 실패 시 페이지당 수정 시도는 한 번으로 묶고, 계속 실패하면 다른 페이지를 진행한다.

## 4. 내용과 그림 검토

[검토 기준](references/review.md)을 읽는다. 원본과 콘티를 대조하는 내용 검토, **모든 실제 그림**의 구조·방향·개수·의미 검토를 수행한다. 작성 패스와 검토 패스를 구분한다. 다른 에이전트를 사용할 수 있고 위임이 허용된 환경에서는 별도 검토자에게 원본과 결과를 주되 생성자의 자기평가를 정답으로 전달하지 않는다.

```bash
python3 "$SKILL/scripts/comic.py" fingerprints --run "$RUN"
```

검토를 실제 수행한 뒤 현재 지문과 검토 내용을 `review.json`에 기록하고 `check --phase reviewed`를 실행한다. CLI에 검토를 자동 통과시키는 명령은 없다. 근거 문자열 존재와 기계 검사만으로 의미 검토 완료를 기록하지 않는다. 대사만 바뀌어도 내용/그림 검토 지문이 바뀌며 장면·스타일·그림 의미 변경은 이미지 재등록도 필요하다.

## 5. 브라우저

`preview.html`을 **1440×900·375×812 각각 라이트·다크**에서 확인한다. 모든 페이지의 그림 로딩·대사 넘침·현재 요약을 확인하고 대표 페이지에서 목차, 이전·다음, 키보드, 패널/모바일 서랍, 테마, 원본 링크와 뒤로가기를 실제 조작한다. 세부 체크와 검토 JSON 형식은 [검토 기준](references/review.md)을 따른다.

현재 결과의 브라우저 지문, 4종 화면의 스크린샷 상대 경로와 확인 내용을 `review.json`에 기록한다. 스크린샷은 `RUN/checks/`에 둔다. 고친 부분은 영향받는 내용·그림·브라우저 검토를 갱신한다.

```bash
python3 "$SKILL/scripts/comic.py" check --run "$RUN" --phase browser
python3 "$SKILL/scripts/comic.py" publish --run "$RUN"
```

발행은 검증된 결과를 **로컬 파일**로 저장한다. 기존 HTML은 새 버전의 `previous.html`로 보존하고, 이미지·제작자료는 고유 버전 폴더에 둔다. 같은 결과를 재실행하면 중복 버전을 만들지 않는다. 저장소에 원본은 바꾸지 않는다. 성공/보류 수는 `publish` 출력에 따른다. 전부 보류라면 빈 제작물을 발행하지 말고 원인과 실행 폴더만 보고한다.

## 재실행·원본 변경

```bash
python3 "$SKILL/scripts/comic.py" extract --repo "$REPO" --target "1105" --run "$NEW_RUN" --reuse "$PREVIOUS_RUN"
```

원본 전체 해시가 달라지면 기존 RUN은 발행할 수 없다. 새 RUN에는 같은 토픽 지문의 콘티와 프롬프트·파일 지문이 맞는 그림만 가져온다. 변경 페이지는 다시 작성한다. 이전 검토는 새 RUN에 복사되지 않으므로 재사용 결과도 검토 후 현재 기록을 남긴다. 이전 발행자료의 버전 폴더도 `--reuse` 입력으로 사용할 수 있다.

## 디자인 유지

`assets/comic-template.html`은 `bio-review-pack/assets/note-template.html`에서 파생했다. 원본 색상·서체·간격·좌우 패널·표지·페이지 이동을 유지하고 `comic.css`는 만화 본문만 확장한다. 테마 키는 공유하고 읽음 키는 `od-comic-read:`로 분리한다. 원본 요약을 무조건 복사하지 않고 만화의 핵심·조건·구분을 요약하되 원본 근거로 검토한다. 그림은 밝은 종이 배경을 유지하며 다크 모드에서 반전하지 않는다.

템플릿을 갱신할 때 `template-provenance.json`의 원본·지문을 확인하고, 최신 원본을 복사한 뒤 읽음 키만 분리한다. 새 퀴즈나 위젯을 추가하지 않는다. 파생본과 CSS 변경 후 테스트와 브라우저 검사를 다시 실행한다.

## 마지막 보고

- 상태: `완료 N/N페이지` 또는 `일부 완료 N/N페이지, 보류 ID와 이유`. 원본 충실성 검토와 기계 검사를 구별한다.
- 최종 HTML, 그림·제작자료 폴더, 원본 연결, 실행 폴더의 실제 경로.
- 포함·제외 페이지 수, 실제 컷 수, 재사용/신규 그림 수.
- 내용·그림 검토에서 고친 내용, 생략한 주변 내용, 남은 불확실성.
- 데스크톱·모바일 및 라이트·다크 확인 결과와 제약.

`status: partial`을 전체 완료로 보고하지 않는다. 구조·내용·그림·브라우저 검토가 모두 통과하고 보류가 없을 때만 차수 전체 완료다.
