# 실행 데이터 계약

## 파일

- `source.html`: 수정하지 않는 실제 원본 파일 복사본.
- `source.json`: 원본 절대 경로·파일 지문·전체 토픽의 순서/포함 여부·주제 지문·본문 HTML·근거 목록. 수정 금지.
- `storyboard.json`: 에이전트가 작성하는 콘티. 아래 구조를 따른다.
- `prompts.json`: `prompts`가 생성하는 컷별 내장 이미지 도구 프롬프트와 재사용 가능 여부.
- `images.json`: `register-image`가 기록하는 실제 파일·프롬프트 지문. 수동으로 통과 기록을 만들지 않는다.
- `review.json`: 실제 내용/그림/브라우저 검토 결과. 형식은 [review.md](review.md).
- `preview.html`, `checks/`: 브라우저 확인 대상과 증거.

## 콘티

다음은 필드 설명을 위한 한 페이지 예시다. 근거 ID·문장은 실제 추출 결과로 교체하며, `panels`는 4~8개를 모두 작성한다. 원본 포함 토픽마다 페이지가 하나씩 있어야 한다.

```json
{
  "schema_version": 1,
  "source_sha256": "추출기가 넣은 값 유지",
  "title": "생명과학 1105 학습만화",
  "style": "생물 구조 중심, 밝은 종이 배경, 절제된 파란 강조. 관찰자는 남색 조끼. 같은 대상을 같은 형태로 유지.",
  "pages": [{
    "id": "s0-miller",
    "title": "유기물 검출과 생명 생성",
    "source_topic_sha256": "추출기가 넣은 값 유지",
    "status": "ready",
    "question": "유기물을 검출하면 생명을 만든 걸까요?",
    "summary": {
      "text": "가정한 조건에서 재료를 만들 수 있다는 결과와 생명 자체의 생성은 구별해요.",
      "evidence": ["s0-miller:e001"]
    },
    "terms": [{"term": "관찰과 해석", "text": "직접 검출한 것과 그 결과로 설명할 수 있는 범위를 나눠요.", "evidence": ["s0-miller:e001"]}],
    "panels": [{
      "scene": "학생이 실험 결과의 작은 분자 모형을 살펴본다. 세포는 없다.",
      "caption": "실험에서 아미노산 같은 작은 유기물을 검출했어요.",
      "dialogue": [{"speaker": "관찰자", "text": "재료를 찾았네. 살아 있는 세포까지 만든 걸까?"}],
      "alt": "시료의 분석 결과를 작은 분자 모형으로 나타낸 장면",
      "evidence": ["s0-miller:e001"]
    }],
    "coverage": [{"evidence": "s0-miller:e001", "panels": [1], "reason": ""}]
  }]
}
```

- `status`: `draft`(작업 중), `ready`(콘티 준비), `held`(보류). `ready`는 검토·그림 완료라는 뜻이 아니다.
- 보류 페이지에는 `reason`이 필요하다. 제목·ID·원본 지문·페이지 위치를 유지한다. 렌더러는 이유와 원본 링크를 보여 준다.
- `summary`: 핵심 관계/차이를 독립적인 문장으로 작성하고 근거를 연결한다. `terms`는 선택 목록이며 필요 없으면 `[]`.
- `panels`: 1부터 배열 순서로 컷 번호를 부여한다. `scene`, `caption`, `alt`, 유효한 `evidence`가 필요하다. 대사가 필요 없으면 `dialogue: []`.
- `coverage`: 그 토픽의 모든 근거 ID를 정확히 한 번씩 기록한다. `panels`의 각 번호는 실제로 그 근거를 참조하는 컷이어야 한다. 생략은 `panels: []`와 구체적인 `reason`을 쓴다.
- 독자에게 원본 근거 ID·녹음 시각·제작 이력·검토 해시를 노출하지 않는다. 근거와 제작 기록은 자료 폴더에 보존한다.

## 검사 단계

| 단계 | 보장하는 것 | 별도로 필요한 것 |
|---|---|---|
| `storyboard` | 원본 지문, 페이지 대응/순서, 4~8컷, 근거 ID와 coverage | 의미·과학적 정확성 |
| `images` | 위 조건 + 실제 이미지 파일·헤더 크기·프롬프트/파일 지문 | 이미지 디코딩/그림 의미 |
| `reviewed` | 위 조건 + 현재 콘티/그림에 대한 내용·그림 검토 기록 | 브라우저 동작·레이아웃 |
| `browser` | 위 조건 + 현재 템플릿/그림/콘티의 4종 브라우저 검토 기록과 스크린샷 파일 | 검토 기록이 실제 관찰을 반영하는지 |

검사기의 지문은 변경 후 검토 누락을 잡기 위한 것이다. 검토 기록을 자동 생성해서 의미 검토를 대신할 수 없다. `partial`은 보류 페이지가 있다는 뜻이며 종료 코드 0이라도 전체 완료가 아니다.
