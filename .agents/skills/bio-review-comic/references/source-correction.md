# 원본 교정 후 재개

## 1. 오류 기록과 보류

추출 또는 검토에서 원본 오류를 발견하면 토픽 ID, 문제 문장 또는 그림·위젯의 ID와 관찰 내용, 교정 근거, 같은 설명이 있는 위치를 실행 기록에 남긴다. 해당 명제를 사용하는 페이지를 `held`로 표시하고, 나머지 페이지를 계속 제작한다. 만화만 요청한 경우 이 상태와 이유를 보고한다. 사용자가 원본 교정도 요청한 경우 메인이 아래 절차를 진행한다.

## 2. 원본과 관련 파일 교정

1. 편집 전에 [HTML 검사](#3-검증과-재개)를 실행해 현재 결과를 기록한다. 강의자료·교재 또는 해당 주장의 검증 근거를 대조한다. 수업에서 쓴 표현과 과학적 설명에 차이가 있으면 각각의 적용 조건과 출처를 드러낸다. 근거가 부족한 항목은 이유를 기록하고 보류한다.
2. 실제 정리노트 HTML에서 같은 주장이 들어간 본문·주의·보충·우측 요약·전체 요약을 찾는다. 도해의 라벨·방향·캡션·대체 설명과 위젯의 동작·정적 그림도 확인한다. 관련된 다른 토픽까지 고치고 기존 토픽·앵커 ID와 만화 연결을 보존한다. `RUN/source.html`과 `RUN/source.json`은 당시 추출 증거로 보존한다.
3. 기존 정리노트 Markdown과 독립 SVG를 새 HTML에 맞춘다. `bio-review-pack/scripts/html2md.py`를 쓰는 팩은 정리노트·복습문제 HTML과 필요한 링크 대상을 임시 폴더에 복제한 뒤 같은 파일명·상대 구조에서 `--check`로 변환한다. 기본 변환은 복습문제 Markdown도 쓰고 공용 SVG를 다시 만든다. 기존 복습문제 Markdown의 SVG 참조를 확인해 그 파일을 보존하고, 실제 폴더에는 정리노트 Markdown과 해당 SVG의 변경만 반영한다. 복습문제나 별도 인터랙티브에서 발견한 불일치는 위치와 함께 보고한다.
4. `.pack/manifest.json`이 있으면 영향받은 토픽의 `required_terms`가 현재 본문의 핵심 개념을 요구하도록 맞춘다. 검사를 통과시키기 위해 교정 전 표현을 복원하거나 필요한 용어를 무조건 삭제하는 대신, 여전히 필요한 용어와 교체할 개념을 본문에서 확인한다. `.pack/summary-audit.md`가 있으면 영향받은 핵심 주장과 대응 문장·판정을 실제 본문과 요약에 맞춘다. 요약의 첫 문장이 바뀌었으면 인용도 갱신한다.

## 3. 검증과 재개

- `bio-review-pack/scripts/check_html.py`로 HTML을 검사한다. manifest와 복습문제 HTML이 있는 팩은 `--manifest <manifest> --note <정리노트> --review <복습문제>`로 팩 검사도 수행하고, 교정 전 결과와 비교한다. 기존 실패와 이번 교정으로 생긴 실패를 기록하고, 교정 관련 실패를 해결한다. 구조 검사와 별개로 감사표의 주장·대응 문장이 실제 본문·요약에 있는지 읽는다.
- 영향을 받은 Markdown·SVG의 내용과 상대 링크를 확인한다. 바뀐 도해는 실제 화면에서 열어 방향·개수·라벨을 대조하고, 바뀐 위젯은 관련 상태를 실제로 조작한다. 보류가 남으면 해당 항목과 사유를 기록한다.
- 실제 정리노트에서 새 `RUN`으로 `extract --reuse`를 실행한다. 교정한 토픽과 같은 주장을 담는 요약 페이지의 콘티·그림·검토를 새 원본과 대조한다. 해결된 보류 토픽은 콘티 작성으로 돌리고, 해결되지 않은 항목의 보류는 새 실행에도 반영한다. 재사용과 검토는 [재실행·원본 변경](../SKILL.md#재실행원본-변경)을 따른다.
