# 페이지별 생성·독립 검토 에이전트

## 메인의 배분과 병합

- 생성과 독립 검토를 서브에이전트에 위임한다. `spawn_agent`가 있으면 `fork_turns: "none"`으로 시작하며 모델·추론 설정은 현재 환경의 기본값을 상속한다. 다른 환경에서는 대화 이력을 복사하지 않는 동등한 위임 수단을 사용한다.
- 한 생성 에이전트는 한 페이지만 담당한다. 완료한 에이전트에 다음 페이지를 이어 맡기지 않는다. 수정은 같은 페이지 생성자에게 전달할 수 있다. 검토도 페이지마다 새 컨텍스트로 시작한다.
- 동시 실행 수는 실제 한도에서 메인 슬롯을 뺀 값이다. 생성자·검토자가 한도를 공유한다. 고정된 슬롯 수를 가정하지 않는다.
- 생성 전에 `check --phase storyboard`와 `prompts`를 실행한다. 배분 중인 콘티·프롬프트는 고정하고, 변경 시 영향받는 작업을 멈춘다. 이전 작업의 종료를 확인한 뒤에만 같은 페이지의 수정·재배분을 시작한다. 종료 확인 전에는 같은 결과 파일을 쓰는 작업을 중복 실행하지 않는다.
- 생성자는 `RUN/workers/<page>/generation.json`, 검토자는 `RUN/workers/<page>/review.json`에 결과를 쓴다. 자기 페이지 폴더의 이미지·수정 이력도 기록할 수 있다. 메인은 공유 `storyboard.json`, `images.json`, `review.json`과 CLI 상태를 관리한다. 생성 파일은 도구의 실제 저장 위치 또는 자기 `workers/<page>/` 하위에 보존한다.
- 메인은 생성 결과의 페이지·컷 번호가 담당 프롬프트와 정확히 일치하는지, 중복/누락이 없는지, `prompt_sha256`이 현재 작업과 같은지 확인한다. 실제 파일 존재·읽기 가능·래스터/파일 해시는 CLI 등록에서 검증한다. `generated`와 `reused`만 순차 등록하고 `failed`는 등록하지 않는다.
- 결과 파일이나 실제 파일이 없으면 완료로 세지 않는다. 성공 컷도 보존하되 실패 페이지는 수정 후 해결될 때까지 보류한다. 재사용은 `reusable: true`이며 실제 기존 파일이 검증되는 작업에만 허용한다.
- 검토 보고서는 생성자의 자기평가와 구분한다. 현재 `content`/`visual` 지문·전체 컷 목록·실제 관찰이 있어야 병합한다. `passed` 문자열만 반환한 보고서는 검토 완료가 아니다. 지문이 달라졌으면 다시 검토한다. 현재 지문의 최신 `failed`는 기존 통과 기록을 즉시 무효화하며, 메인은 해당 페이지를 수정 대기/보류로 반영한다. 오래된 `passed`로 실패를 덮어쓰지 않는다. `held`로 바꿨다면 재검토 전에 `ready`로 복원해 새 현재 지문을 얻는다.
- 메인 컨텍스트에는 결과 파일 경로·성공/실패 수·판정·수정 요약만 전달한다. 메인도 파일에서 페이지별 필요한 필드만 추출하고 정상 컷의 상세 관찰이나 프롬프트 원문을 일괄 출력하지 않는다. 프롬프트 전체, 모든 이미지, 도구의 원본 반환값을 부모 메시지에 복사하지 않는다. 브라우저 검증은 기존 전체 페이지·4종 화면 기준을 유지하고 대표 화면과 문제 컷을 직접 확인한다.
- 발행 후 `prompts.json`, `workers/`를 실제 발행 버전 폴더에 추가 보존한다. 생성 결과가 가리키는 도구 원본 파일과 발행 이미지의 대응은 `images.json`에서 확인한다. 파일 경로만 임의로 바꾸지 않는다.

## 생성자에게 전달할 작업

생성자와 독립 검토자는 `style.md`도 읽고 담당 장면에 가까운 `assets/style/`의 승인 시안을 실제 확인한다. 생성자는 이를 그림체 참조로 사용한다. 원본 도해·반복 대상의 이전 컷·승인 시안의 참조 역할을 구별하고 공통 `style`을 모든 컷에 적용한다.

메시지는 다음 정보만 담는다. 경로는 모두 실제 절대 경로로 치환한다.

> bio-review-comic 페이지 생성 작업. SKILL=<스킬 절대 경로>, RUN=<실행 절대 경로>, PAGE=<토픽 ID>. SKILL/references/agents.md의 생성 계약과 images.md를 읽고 PAGE 하나의 모든 컷을 수행하라. RUN/prompts.json과 storyboard.json에서 해당 페이지·공통 스타일·캐릭터만 읽고 source.html/source.json의 관련 본문·원본 그림을 확인하라. 내장 이미지 도구로 컷마다 생성하고 실제 결과를 확인하라. 참조 의존 컷은 먼저 만든 실제 파일을 확인한 뒤 사용하라. 결과는 RUN/workers/PAGE/generation.json에 기록하라. 공유 파일 수정·register-image·발행은 메인 담당이다. 부모에게 페이지 ID, 성공/실패 컷 수, 결과 파일 경로, 수정 필요 사항만 5줄 이내로 반환하라.

메인이 별도 기준 이미지를 제공할 때만 실제 경로와 참조 역할을 메시지에 추가한다. 도구가 없거나 지원되는 저장 경로를 얻지 못하면 실패 원인을 기록한다. 출력 예정 경로를 실제 생성 경로로 취급하지 않는다. 도구에 이미지 반환 규칙이 있으면 자기 에이전트 안에서 따르고 부모 보고는 짧은 텍스트로 한다.

생성 결과 형식:

```json
{
  "page": "s0-miller",
  "panels": [
    {
      "panel": 1,
      "prompt_sha256": "해당 작업의 실제 지문",
      "status": "generated",
      "image": "/도구가/실제로/저장한.png",
      "observations": ["실제 그림에서 확인한 구조·개수·배치"],
      "error": null
    }
  ]
}
```

`status`는 `generated`, `reused`, `failed` 중 하나다. 실패 컷은 `image: null`과 구체적 `error`를 남긴다. 실제 페이지의 모든 컷을 한 번씩 기록한다. 수정 시 최종 컷 결과를 갱신하고 이전 경로·실패 원인은 같은 페이지 폴더의 별도 기록으로 보존한다. 생성자의 관찰은 독립 검토 통과를 뜻하지 않는다.

## 독립 검토자에게 전달할 작업

> bio-review-comic 독립 검토. SKILL=<스킬 절대 경로>, RUN=<실행 절대 경로>, PAGE=<토픽 ID>. SKILL/references/review.md와 agents.md의 검토 계약을 읽어라. RUN/source.html/source.json의 해당 원본 본문·그림, storyboard.json의 해당 페이지·공통 정의, images.json의 해당 페이지 모든 실제 이미지를 직접 대조하라. 생성자의 평가를 정답으로 읽지 말라. 요약·대사·캡션·그림에서 가져온 다른 토픽과 별도 도해·위젯을 source_dependencies와 대조하라. 원본 핵심·조건·비유 한계·대사와 모든 실제 그림의 구조·방향·개수·연속성을 확인하라. comic.py fingerprints --run RUN --page PAGE로 검토 대상의 content/visual 지문을 얻어라. RUN/workers/PAGE/review.json에 page, checked_panels, content와 visual의 status/fingerprint/notes, issues를 기록하라. status는 passed 또는 failed, issues는 컷 번호(페이지 전체면 null)·문제·근거·수정 제안의 목록이며 남은 문제가 없으면 빈 배열이다. 실제 검토하지 않은 항목은 failed로 남겨라. 공유 review.json은 수정하지 말라. 부모에게 페이지·판정·보고서 경로·수정할 컷과 이유만 5줄 이내로 반환하라.

위임이나 검토 도구가 없으면 메인에 원인을 반환하며 통과 보고서를 만들지 않는다. 메인은 실패를 페이지 보류로 반영한다. 수정 결과를 검토할 때는 현재 등록 이미지와 현재 지문을 다시 읽는다.
