# 페이지별 생성·독립 검토 작업자

## 배정과 병합

- 서브에이전트를 깨끗한 컨텍스트에서 시작한다. 검토자는 콘티 작성자 및 이미지 생성자와 독립적이어야 한다. 해당 단계의 작업 파일 경로와 다음 절의 역할만 전달한다.
- 페이지별로 내용 검토 → 그림 생성 → 그림·합성 검토 순서로 배정한다. 실제로 비어 있는 슬롯에서 준비된 작업을 진행하고, 같은 페이지에 새 작업을 배정하기 전에 이전 작업이 종료됐는지 확인한다. 각 작업자는 자기 결과 파일만 쓰고 메인은 등록을 순차 처리한다.
- `prepare`가 `pending: 0`을 반환하면 기존 결과를 사용한다. 작업 파일 옆의 리소스는 배정 당시 복사본이다. 작업자는 현재 공유 콘티나 다른 페이지의 입력을 읽을 필요가 없다. 배정된 원본 절과 도해가 불충분하면 정확히 무엇이 빠졌는지 보고한다.
- 작업자 결과는 RUN의 `workers/<page>/`에 작업마다 별도 이름으로 저장한다. 메인에는 페이지·판정·수정할 컷·결과 파일 경로만 반환한다. 전체 원문·모든 프롬프트·도구 반환값은 각 작업자의 결과 파일에서 확인한다.
- 실제 도구·위임·아티팩트 확보가 실패하면 확인된 실패와 유효한 부분 결과를 반환한다. 메인은 원인을 기록하고 해결 불가한 페이지를 보류한다.

## 생성 대기열

1. **대기 등록.** 메인은 현재 내용 검토를 통과한 페이지의 ID와 생성할 범위를 대기열에 넣는다. 최초 생성은 미등록 컷, 그림 검토에서 반려된 작업은 교체할 컷 번호를 기록한다. 최초 생성과 재생성 모두 대기열에 들어온 순서로 처리하고, 동시에 준비된 페이지는 원본 순서로 넣는다. 먼저 등록해야 할 기준 컷이 있으면 그 컷을 배정하고, 참조가 확정된 뒤 후속 컷을 대기열에 넣는다.
2. **슬롯 확보.** 대기 작업이 있는 동안 생성 슬롯 1개를 우선 확보하고 그 담당은 그림 생성에 배정한다. 생성 담당이 작업 중이면 메인은 콘티 준비, 다른 슬롯에 검토 배정, 돌아온 결과 등록을 진행한다. 할 수 있는 일이 끝나면 현재 생성 작업이 끝날 때까지 기다린다. 슬롯 부족, 시간 압박, 도구 실패에도 최초 생성과 재생성의 이미지 호출은 생성 담당에게만 배정한다.
3. **고정 입력 전달.** 슬롯이 비고 해당 페이지의 이전 생성 작업이 종료됐으면 대기열의 첫 작업에 `prepare --stage generate`를 실행한다. 컷을 지정할 때 `--panel 컷번호`를 쓰고, 이미 등록한 그림을 교체할 때 `--redo`를 함께 쓴다. 현재 내용 통과 판정이 필요하면 내용 검토로 되돌리고, `pending: 0`이면 기존 그림을 사용한다. 한 번에 한 페이지의 고정 작업 파일만 전달한다.
4. **회수와 복구.** 메인은 성공 컷을 먼저 등록하고 `register-image`가 반환한 `failed`와 작업자 보고서의 사유를 대조한다. 복구 가능한 컷만 새 작업으로 대기열에 넣는다. 담당이 종료됐으면 기존 호출의 종료를 확인하고 확보한 결과부터 처리한 뒤, 대체 담당에게 남은 컷을 배정한다. 현재 생성 지문이나 내용 판정이 바뀌어 등록이 거부되면 현재 판본으로 작업을 다시 준비한다. 이미 진행 중인 생성 작업 뒤에 배정할 수 있으면 대기를 계속한다. 생성 가능한 담당을 확보할 방법이 없거나 실패 원인을 해결할 수 없으면 `storyboard.json`에서 해당 페이지의 `status`를 `held`로 바꾸고 `reason`에 실패와 복구 시도를 적는다. 다른 페이지의 검토와 발행은 이어간다.

## 독립 검토자에게 전달할 작업

> 배정 파일에서 `stage`와 `checks`를 읽고 [검토 기준](review.md)에 따라 독립 판정하라. 내용 단계는 대사·캡션·계획 장면에서 조건을 먼저 찾아 적고, 고정 원본과 도해를 대조하라. 그림 단계는 지정된 실제 그림을 직접 열고, 합성 단계는 고정 `preview.html`과 실제 컷을 보라. 소스·판정에 이미 익숙해도 관찰을 새로 기록하라. 실제 작업 시작과 종료를 재서 `elapsed_seconds`에 적고 결과 파일 경로만 반환하라.

```json
{
  "task": "task.json의 id",
  "elapsed_seconds": 42.5,
  "checks": {
    "content": {
      "status": "failed",
      "checked_panels": [1, 2, 3, 4],
      "notes": ["2컷에서 고정 조건을 읽을 수 없음. 원본의 비교 조건과 수정할 위치 기록."]
    }
  }
}
```

`checks` 키는 배정과 정확히 일치한다. 모든 컷을 실제로 본 뒤 판정과 근거를 남긴다. `record-review`는 실패와 현재 판본에 적용되지 않는 보고서도 배정별 결과로 남긴다.

## 생성자에게 전달할 작업

> 받은 작업 파일 한 개의 `jobs`에 있는 프롬프트를 내장 이미지 도구로 컷당 호출하라. 참조 파일은 각각의 고정 복사본을 쓰고, 참조가 확정된 같은 페이지의 컷은 병렬로 호출할 수 있다. 실제 결과 파일과 지문을 기록하고, 이 작업의 실제 시작부터 종료까지 잰 값을 `elapsed_seconds`에 적어라. 필요한 장면·참조 변경은 메인에 요청하라. 실제 호출 수에는 실패·재시도도 포함한다. 결과 파일 경로만 반환하라.

```json
{
  "task": "task.json의 id",
  "elapsed_seconds": 81.2,
  "image_calls": 2,
  "images": [
    {"panel": 1, "prompt_sha256": "배정에 기록된 생성 지문", "image": "/실제/그림.png", "sha256": "결과 파일 SHA-256"}
  ]
}
```

성공한 그림만 `images`에 넣고 실패 원인은 별도 `notes`에 적는다. 파일 해시는 `shasum -a 256`으로 얻을 수 있다. 메인은 `register-image --report`로 결과를 등록한다.
