# 내용·그림·브라우저 검토

## 내용과 그림: 페이지마다

내용 검토에서는 source.html의 실제 본문·그림과 콘티를 나란히 읽는다. 핵심 질문에 답하는 흐름인지, 모든 핵심 개념·작동 원리·성립 조건·혼동 구분이 남았는지, coverage의 생략이 반복/주변 내용에 한정되는지 확인한다. 요약·용어·모든 대사에도 같은 기준을 적용한다. 혼동 지점이 구체적인지, 비유의 관계 대응이 타당한지, 한계가 같은 페이지에서 실제로 드러나는지 확인한다. 대화형은 질문과 응답·자기수정이 연결되는지, 설명형은 화자의 설명이 핵심 추론을 이끄는지 확인한다. 그림 출연 여부와 무관하게 대사에서 핵심 추론을 따라갈 수 있어야 한다. 출처의 가설·불확실·보충 표시를 유지하고 원본의 잘못된 명제를 발견하면 원본을 고치지 말고 보류한다.

그림 검토에서는 **모든 실제 생성 이미지**를 본다. 근거 ID만 읽어서 그림 검토를 통과시키지 않는다. 방향·개수·상대 관계·인과/시간 순서·문자 생성 흔적·대상의 연속성·대사와 장면 일치를 확인한다. `characters`가 빈 컷은 사물·구조만 보이고, 화면 밖 화자 이름·대사가 사람 그림이나 의인화된 사물로 번지지 않았는지 확인한다. 출연자가 있는 컷은 정의와 실제 외형을 비교한다. 비유 소품과 실제 생물 구조의 구분도 확인한다. 원본 그림에서 확인한 내용은 그림 ID와 관찰 사항을 notes에 적는다. 이미지를 고치면 검토 지문도 갱신한다.

```bash
python3 "$SKILL/scripts/comic.py" fingerprints --run "$RUN"
```

출력 `pages.<ID>.content`, `pages.<ID>.visual` 값을 실제 검토 후 아래 기록에 복사한다. 실제 비교에서 확인한 중요한 사항과 수정 사항을 notes에 적는다. 검토자로서 내용을 확인하지 않은 채 `passed`를 만들지 않는다.

## 브라우저 확인

RUN이 저장소 `tmp/` 안에 있으면 저장소 루트에서 HTTP 서버를 띄워 preview.html을 연다. RUN만 서버 루트로 잡으면 원본 정리노트 링크가 서버 밖으로 나가므로 피한다. 실제 화면은 1440×900, 375×812 각각 light/dark 네 조합이다.

1. 모든 페이지에서 컷 수·이미지 로딩(`complete && naturalWidth > 0`)·설명·현재 요약을 확인한다. 말풍선이 figcaption 아래가 아니라 컷 내부에서 읽히는지 확인한다. 질문→응답 순서, 이름으로 화자 구별, 화면 밖 꼬리 방향, 17px 이상 본문 글자, 확대·좁은 화면의 잘림·가림을 확인한다. 실제 사물의 윗부분도 직접 확인한다. 여백 비율 검사만으로 가림이 없다고 단정하지 않는다.
2. 긴 설명·긴 요약·보충 배지·8컷 페이지를 포함해 가로 넘침 없이 끝까지 읽히는지 확인한다.
3. 목차의 첫/중간/마지막 페이지 이동, 이전/다음/처음으로, 키보드 화살표, 해시 직접 진입과 뒤로가기를 실제 조작한다.
4. 넓은 화면의 패널 토글/크기 조절, 모바일 목차/요약 서랍과 Escape/배경 닫기를 확인한다.
5. 테마 전환과 새로고침 유지, 만화 읽음 기록과 원본 읽음 기록의 분리를 확인한다.
6. 원본 정리노트 보기 링크를 눌러 해당 주제로 같은 탭 이동 후 뒤로 돌아온다. 링크 파일/해시 존재와 원본 내용 보존을 확인한다.
7. 콘솔 오류·실패한 이미지 요청·레이아웃 가로 스크롤이 없어야 한다. 오래된 노트의 네트워크 의존성 문제가 있으면 만화 자체 문제와 구별해 기록한다.

각 조합에서 대표 화면을 `checks/`에 스크린샷으로 저장한다. 검토 지문은 템플릿/CSS·원본·콘티·그림을 포함하므로 이후 변경하면 다시 build하고 영향을 확인해야 한다. 스크린샷은 실제 브라우저에서 캡처하며 테스트 이미지를 검토 증거로 대신하지 않는다.

발행 후 실제 최종 HTML도 한 번 열어 이미지와 원본 링크를 확인한다. 정리노트에 추가된 안내의 문맥과 정확한 페이지 해시도 확인하고, 같은 탭에서 만화 해당 페이지로 이동한 뒤 원본 링크·뒤로가기로 돌아온다. 연결 재실행은 changed: false여야 한다. 최종 링크가 깨지면 연결 성공으로 보고하지 않는다. 실패가 남은 페이지는 이유와 함께 보류하고 나머지 결과와 구별한다.
