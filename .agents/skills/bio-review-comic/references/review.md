# 내용·그림·브라우저 검토

## 내용과 그림: 페이지마다

[공통 그림체](style.md)의 승인 참조와 실제 컷을 비교한다. 인물·구조·과정·비유 사물 사이에 선 굵기·면색·아이보리 배경이 이어지고 수채화풍이나 입체 렌더링이 섞이지 않았는지 확인한다. 스타일을 단순화하면서 막 경계·개수·방향·작동 상태를 잃지 않았는지도 따로 검토한다. 참조 이미지 자체는 과학적 정답으로 사용하지 않는다.

메인은 [에이전트 작업 계약](agents.md)의 검토 지시문으로 생성자와 다른 검토자를 페이지별 배정한다. 검토자는 실제 원본·콘티·등록된 이미지와 현재 지문을 읽고 전용 보고서만 쓴다. 원본과 대조해 `source_dependencies`가 요약·대사·캡션·그림에 쓰인 다른 토픽과 별도 근거 파일을 담는지 확인한다. 빠진 근거가 있으면 콘티 수정 후 현재 지문으로 검토한다. 바뀐 그림과 영향을 받은 컷을 먼저 보고, 페이지 전체의 내용과 그림 연속성을 확인한다.

내용 검토에서는 source.html의 실제 본문·그림과 콘티를 나란히 읽는다. 핵심 질문에 답하는 흐름인지, 모든 핵심 개념·작동 원리·성립 조건·혼동 구분이 남았는지, coverage의 생략이 반복/주변 내용에 한정되는지 확인한다. 요약·용어·모든 대사에도 같은 기준을 적용한다. 혼동 지점이 구체적인지, 비유의 관계 대응이 타당한지, 한계가 같은 페이지에서 실제로 드러나는지 확인한다. 대화형은 질문과 응답·자기수정이 연결되는지, 설명형은 화자의 설명이 핵심 추론을 이끄는지 확인한다. 그림 출연 여부와 무관하게 대사에서 핵심 추론을 따라갈 수 있어야 한다. 출처의 가설·불확실·보충 표시를 유지한다. 원본 오류를 발견하면 보고서에 위치와 근거를 남긴다. 메인은 [원본 교정 후 재개](source-correction.md)에 따라 해당 페이지의 보류·교정을 처리한다.

그림 검토에서는 **모든 실제 생성 이미지**를 본다. 근거 ID만 읽어서 그림 검토를 통과시키지 않는다. 방향·개수·상대 관계·인과/시간 순서·문자 생성 흔적·대상의 연속성·대사와 장면 일치를 확인한다. `characters`가 빈 컷은 사물·구조만 보이고, 화면 밖 화자 이름·대사가 사람 그림이나 의인화된 사물로 번지지 않았는지 확인한다. 출연자가 있는 컷은 정의와 실제 외형을 비교한다. 비유 소품과 실제 생물 구조의 구분도 확인한다. 원본 그림에서 확인한 내용은 그림 ID와 관찰 사항을 notes에 적는다. 이미지를 고치면 검토 지문도 갱신한다.

```bash
python3 "$SKILL/scripts/comic.py" fingerprints --run "$RUN" --page "$PAGE"
python3 "$SKILL/scripts/comic.py" record-review --run "$RUN" --report "$RUN/workers/$PAGE/review.json"
```

검토자는 출력의 `pages.<ID>.content`, `pages.<ID>.visual`을 전용 보고서에 기록한다. 페이지 ID, `checked_panels`(실제로 본 모든 컷 번호), `issues`와 아래의 `content`·`visual` 형식을 사용한다. 실제 관찰을 notes에 적는다. 메인은 독립 검토자가 작성한 통과 보고서를 확인한 뒤 `record-review`로 병합한다. `review.json`의 `pages`는 이 명령과 `reuse-reviews`로 작성하며, `browser`는 실제 화면 확인 뒤 메인이 추가한다. 아래는 검토·브라우저 필드의 예시다.

```json
{
  "pages": {
    "s0-miller": {
      "content": {"status": "passed", "fingerprint": "현재 content 지문", "notes": ["관찰값과 결론의 한계를 원본 formal/warn과 대조. 실제 과거 대기의 확정 조성으로 표현한 문장을 수정."]},
      "visual": {"status": "passed", "fingerprint": "현재 visual 지문", "notes": ["6개 실제 그림 확인. 5컷에 세포가 나타나지 않음. 원본 fig-miller-origin의 순환·냉각 관계와 대조."]}
```

예시의 모든 값을 그대로 쓰지 않고 실제 페이지 목록·검토 결과·지문으로 채운다. `held`는 검토 통과로 만들 필요가 없다.

## 이전 독립 검토 승계

`reuse-reviews --dry-run`에서 `eligible`은 승계 가능, `needs_review`는 새 검토 필요, `held`는 보류, `already_reviewed`는 현재 입력으로 확인된 검토 기록이 있음을 뜻한다. `--dry-run`을 빼면 가능한 페이지를 `inherited`로 기록한다. 다른 페이지의 `draft`나 미등록 그림을 기다리지 않고 판정을 볼 수 있다.

`source_changed`는 자기 원본 변경, `related_source_changed`는 관련 원본 변경이다. 후자는 `related_topics`에서 바뀐 토픽을 확인한다. `legacy_review`는 이전 검토에 당시 기준·입력·보고서를 연결하는 기록이 없는 경우다. 현재 지문으로 새 독립 검토를 받는다. 콘티·그림·기준·근거 파일 차이, 보고서 누락이나 불일치도 승계하지 않는다. 새 검토가 필요한 페이지에서 기존 그림이 현재 프롬프트와 의미에 맞으면 계속 사용한다.

승계는 이전에 확인된 판정을 최초 보고서와 함께 보존한다. 보고서에 새 지문을 붙여 통과 판정을 만들지 않는다. 오래된 실행 폴더가 없어도 새 RUN과 발행 버전의 `review-evidence/`에서 최초 보고서를 확인할 수 있다. 새 RUN의 브라우저 판정과 화면 증거는 아래 절차로 다시 기록한다.

## 브라우저 확인

`browser-check`는 로컬 HTTP 서버와 Playwright Chromium으로 1440×900, 375×812 각각 라이트·다크를 연다. 브라우저 검사에 쓸 Python 환경에 Playwright가 없으면 `python3 -m pip install playwright`로 설치하고 `python3 -m playwright install chromium`을 실행한다.

```bash
python3 "$SKILL/scripts/comic.py" browser-check --run "$RUN" --stage preview --out "$RUN/checks/preview"
python3 "$SKILL/scripts/comic.py" browser-check --run "$RUN_OR_VERSION" --stage published --out "$FINAL_CHECKS"
```

미리보기는 최신 렌더와 일치하는 `preview.html`에서 만화 → 원본 → 브라우저 뒤로가기를 확인한다. 발행본은 `publication.json`이 가리키는 HTML과 현재 원본에서 원본 안내 → 만화의 같은 토픽 → 만화의 원본 링크 → 원본의 같은 토픽을 실제로 클릭한다. `--comic-only`는 연결 없이 발행한 경우에 쓰며, 만화 → 원본 → 브라우저 뒤로가기의 건수를 별도로 남긴다. 원본 안내 클릭은 `skipped`로 표시한다. 기존 발행본의 원본 본문이 교정된 경우에는 발행 당시 콘티와 현재 원본을 사용하고 `source_status: changed_since_publication`을 기록한다.

`--out`에는 비어 있는 새 폴더를 지정한다. `report.json`과 조합별 스크린샷을 남긴다. 보고서에는 검사기 지문과 브라우저 버전, 두 HTML의 전체 바이트 지문, 만화 이미지 지문, 통과 건수, 보류 목록과 실패의 토픽·동작·기대값·실제값을 기록한다. 발행본 검사 중 원본 관리 링크 블록이 손상된 경우 무결성 실패를 기록하고 클릭 검사도 수행한다. 외부 요청은 차단해 목록에 남긴다. 필수 동작이 실패하거나 검사 중 입력 지문이 달라지면 종료 코드 1을 반환한다. 결과를 검토한 뒤 직접 관찰과 함께 기존 `review.json`의 브라우저 판정을 기록한다. `check --phase browser`는 그 판정과 화면 증거를 확인한다.

새 RUN의 발행은 마지막 미리보기 보고서를 현재 입력과 대조한다. 4종 각각에서 준비 완료 토픽별 컷과 원본 복귀가 통과하고, 화면 증거와 로컬 렌더 자원의 지문이 맞아야 한다. 최종 왕복은 별도 명령으로 실행하며 `link-status`에서 연결 상태를 확인한다.

자동 검사와 직접 확인을 합쳐 다음을 확인한다.

1. 모든 페이지에서 컷 수·이미지 로딩(`complete && naturalWidth > 0`)·설명·현재 요약을 확인한다. 말풍선이 figcaption 아래가 아니라 컷 내부에서 읽히는지 확인한다. 질문→응답 순서, 이름으로 화자 구별, 화면 밖 꼬리 방향, 17px 이상 본문 글자, 확대·좁은 화면의 잘림·가림을 확인한다. 실제 사물의 윗부분도 직접 확인한다. 여백 비율 검사만으로 가림이 없다고 단정하지 않는다.
2. 긴 설명·긴 요약·보충 배지·8컷 페이지를 포함해 가로 넘침 없이 끝까지 읽히는지 확인한다.
3. 목차의 첫/중간/마지막 페이지 이동, 이전/다음/처음으로, 키보드 화살표, 해시 직접 진입과 뒤로가기를 실제 조작한다.
4. 넓은 화면의 패널 토글/크기 조절, 모바일 목차/요약 서랍과 Escape/배경 닫기를 확인한다.
5. 테마 전환과 새로고침 유지, 만화 읽음 기록과 원본 읽음 기록의 분리를 확인한다.
6. 원본 정리노트 보기 링크를 눌러 해당 주제로 같은 탭 이동 후 뒤로 돌아온다. 링크 파일/해시 존재와 원본 내용 보존을 확인한다.
7. 콘솔 오류·실패한 이미지 요청·레이아웃 가로 스크롤이 없어야 한다. 오래된 노트의 네트워크 의존성 문제가 있으면 만화 자체 문제와 구별해 기록한다.

각 조합에서 대표 화면을 `checks/`에 스크린샷으로 저장한다. 검토 지문은 템플릿/CSS·원본·콘티·그림을 포함하므로 이후 변경하면 다시 build하고 영향을 확인해야 한다. 스크린샷은 실제 브라우저에서 캡처하며 테스트 이미지를 검토 증거로 대신하지 않는다.

발행 후 실제 최종 HTML도 한 번 열어 이미지와 원본 링크를 확인한다. 정리노트에 추가된 안내의 문맥과 정확한 페이지 해시도 확인하고, 같은 탭에서 만화 해당 페이지로 이동한 뒤 원본 링크·뒤로가기로 돌아온다. 연결 재실행은 changed: false여야 한다. 최종 링크가 깨지면 연결 성공으로 보고하지 않는다. 실패가 남은 페이지는 이유와 함께 보류하고 나머지 결과와 구별한다.

## 선택형 발행 리허설

```bash
python3 "$SKILL/scripts/comic.py" rehearse --run "$RUN" --out "$REHEARSAL"
python3 "$SKILL/scripts/comic.py" publish --run "$RUN" --rehearsal "$REHEARSAL"
```

`rehearse`는 현재 검토와 해당 RUN에 필요한 미리보기 증거를 확인한 뒤, 비어 있는 `--out`의 `tree/` 아래에 저장소 기준 최종 경로를 재현한다. 버전별 그림, 새 만화와 안내가 삽입된 원본을 그 안에 만들고, 브라우저가 요청한 로컬 자원도 격리본에 복사한다. 실제 발행 폴더 밖에 `--out`을 둔다. 준비 완료 토픽 전부의 컷과 원본 → 만화 → 원본 클릭을 4종에서 검사한다. 실패는 종료 코드 1과 보고서의 토픽·동작으로 확인한다. 리허설만으로 실제 발행 파일이나 연결 상태가 바뀌지 않는다.

`publish --rehearsal`은 `candidate.json`과 `report.json`의 RUN·최종 경로·버전·검사 증거를 대조한다. 원본 전체 바이트, 기존 만화, 검사 후보 또는 읽은 로컬 자원이 달라졌다면 새 `--out`으로 리허설을 다시 실행한다. 성공 시 검사한 HTML 두 개를 그대로 반영하고 리허설 증거를 버전의 `checks/rehearsal/` 아래에 보존한다. `--no-link`와 함께 쓰지 않는다. 발행 후 실제 파일의 왕복은 `browser-check --stage published`로 다시 확인해야 `link-status`가 `passed`가 된다.
