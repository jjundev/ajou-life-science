# 같은 문제의 연습형·시험형

새 세트는 문제 원본 한 벌에서 **연습형 문제 HTML·시험형 문제 HTML·공통 상세 해설 HTML**을 만든다. 별도 파일이며, 페이지 안에서 모드를 바꾸지 않는다. 두 문제판의 문항 ID·순서·발문·그림·보기 순서·정답·단답형 허용답은 같다. 문제를 두 번 저작하거나 두 판에서 보기를 따로 섞지 않는다.

| 스킬 | 연습형 | 시험형 | 공통 상세 해설 |
|---|---|---|---|
| 웹과제 예상 | `복습문제_<N>장_웹과제예상_v<K>.html` | `복습문제_<N>장_웹과제예상_시험형_v<K>.html` | `문제해설_<N>장_웹과제예상_v<K>.html` |
| 시험 예상 | `시험예상문제_<범위>_연습형_v<K>.html` | `시험예상문제_<범위>_v<K>.html` | `문제해설_<범위>_시험예상_v<K>.html` |

기존 파일명은 유지하며 제목에 연습형/시험형을 표시한다. 새 생성부터 적용한다. 기존 단일 문제판이나 공개 파일명을 소급 변경·삭제하지 않는다. 버전은 두 판이 함께 쓰며 반대 형태를 새 출제 세트로 세거나 이전 버전 중복으로 집계하지 않는다.

## 화면과 기록

- 연습형: 기존 웹과제 복습문제의 템플릿·상호작용을 재사용한다. 객관식 선택 즉시 정오·선택 보기와 정답 보기의 설명을 본문에 펼치고 현재 문항을 유지한다. 다른 보기는 눌러 설명을 펼친다. 답 변경은 문항별 `다시 풀기`를 사용하고, 정답 문항은 오른쪽 패널의 `애매함으로 표시`를 지원한다. 단답형은 입력 중 판정하지 않고 `답 확인`으로 정답/허용답 자동 일치 또는 자기채점 대기를 표시하며 입력을 잠근다. `다시 풀기`로 입력·판정을 지우고 재시도한다. 마지막 문항의 기존 `복기 프롬프트 복사`에 객관식·단답형 기록을 함께 포함한다. 연습형에는 시험식 전체 결과·채점표·학습 결과 버튼을 두지 않는다.
- 시험형: 객관식 선택 후 다음 문항으로 이동하며 답 수정이 가능하다. 단답형은 수동 이동한다. 마지막 문항에서 전체 제출한 뒤 채점·입력 잠금·전체 결과·5열 채점표·복기 프롬프트를 제공한다. 제출 전에는 정답·해설·출처와 상세 해설 열기 버튼을 숨긴다. JS off/인쇄에서도 문제판의 숨김이 유지되어야 한다.
- 두 풀이 형태 사이의 바로가기를 두지 않는다. 연습형은 추가 기능 바 없이 기존 헤더에서 상세 해설을 연다. 시험형은 전체 제출 후에만 기능 바 전체를 표시하고 제출 전에는 빈 공간도 남기지 않는다. 상세 해설은 발행된 같은 버전 파일을 연다. 부분 완료 단계에서는 상세 해설이 아직 없을 수 있음을 최종 보고한다.
- 새로고침하면 두 형태 모두 답안·채점 결과·진행 표시·제출 상태를 초기화한다. 결과 URL(`#exam-results`)이 남아 있으면 첫 문제로 이동한다. 테마·패널 배치 설정은 유지한다. 일반 복습팩의 기록 보존 정책은 바꾸지 않는다.
- 응시 문서 ID와 풀이 형태를 구분한다. 같은 문항을 연습한 뒤 시험형으로 다시 푼 결과는 새 문제 첫 응시의 성과로 보고하지 않는다. 별도 제한시간·서버 기록·자동 기록 통합은 추가하지 않는다.
- 웹과제 시험형의 채점·진행·목차 대상은 p1~p15다. o1/o2는 `출제 개요 보기`로 열며 시험 순서에 끼워 넣지 않는다. 시험형은 개요의 정답 정보를 스스로 열어 볼 수 있는 연습 도구이며 보안 시험 환경이 아니다.

## 빌드와 검증

기존 build 명령이 두 문제판을 함께 만든다. `.pack/vK/presentations.json`에 원본 지문 집합 식별값·원본 해시·두 파일명과 SHA-256을 기록한다. `scripts/exam_presentations.py`가 이름·연결·변환·검사를 공유한다. 시험형은 `assets/exam-runtime.js`, 두 연습형은 공통 `review-template.html`과 `review-interaction.js`를 사용한다. 시험 예상 연습형은 `scripts/exam_practice.py`에서 원본을 복습문제 구조로 렌더링한다. 새 시험 예상 객관식에는 모든 보기 ID에 대응하는 `option_explanations`가 필요하며 일반 풀이 단계를 임의 대응하지 않는다. 누락·빈 설명은 빌드를 중단한다. 문항 원본과 정답은 공유하고 표시 DOM만 다를 수 있다. 웹과제는 15문항, 시험 예상은 55+20을 유지한다.

1. 내용·범위·독립 풀이는 원본 문제 한 벌을 검토한다. 두 판의 표시된 발문·그림·보기와 원본 일치는 별도로 확인한다.
2. 두 판 각각 1280×900/375×812, light/dark에서 브라우저로 확인한다. 가로 넘침·콘솔 오류·문항 이동·입력 보존·초기화·풀이 표시 시점·연결을 확인한다. 연습형 객관식 비이동/즉시 채점과 단답형 확인, 시험형 일괄 채점/채점표를 모두 실제 조작한다.
3. 시험 예상은 `question-review.json`의 `reviews.browser.presentations.practice`와 `.exam` 각각에 status/reviewer/evidence를 기록한다. 둘 다 pass이어야 `check --final`이 통과한다. 웹과제는 컨트롤러 RUN의 브라우저 증거에 두 판 경로·해시·확인 결과를 구별해 남긴다. 기계 검사의 성공을 실제 브라우저 검토로 대신하지 않는다.
4. 해설은 기존 대표 파일(웹과제 연습형, 시험 예상 시험형)의 **명시 절대 경로**에서 한 번만 추출한다. 해설기는 presentations.json과 두 문제판을 문맥 해시에 묶고 각 문항에서 두 판으로 돌아가는 링크를 만든다. 어느 판이든 바뀌면 이전 해설 승인을 재사용하지 않는다.
5. 원본을 고치면 두 판을 함께 재빌드·재검토하고 새 해설 RUN에서 재추출한다. 검증 스냅샷에는 두 문제판과 해당 `.pack/vK/`를 함께 보존한다. 기존 수정 예산은 유지한다.
6. 완료 보고는 연습형·시험형·상세 해설의 **HTML 3개 링크와 각 검증 상태**를 필수로 제시한다. 하나라도 누락·미검증·발행 보류라면 부분 완료다. 기존 단일 문제판은 기존 계약으로 검사하며 새 실행의 완료 증거로 대신 쓰지 않는다.
