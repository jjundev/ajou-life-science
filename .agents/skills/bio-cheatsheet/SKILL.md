# 생명과학 커닝페이퍼

장 하나의 커닝페이퍼를 `웹과제예상/커닝페이퍼/<N>장/`에 만든다. 시험 중에 태블릿으로 보며 보기를 판별하는 용도라서, **원천에 있는 사실만**, **함정은 출처와 함께**, **쪽 나눔은 스크립트로** 처리한다. 중간에 사용자에게 묻지 않고 끝날 때 한 번만 보고한다. 커밋은 제안만 한다.

**산출물**(`웹과제예상/커닝페이퍼/<N>장/`): `cheatsheet_<N>장.html`, `cheatsheet_<N>장.pdf`, `spec.json`, `찾기-점검.md`. `cheatsheet_<N>장_웹과제당일.*`처럼 이름이 다른 파일은 응시 기록이라 건드리지 않는다.

**인자**: `<N> [<N>…] [lite] [refresh]`. 장마다 아래 절차를 따로 돈다. `lite`이면 구역 작성자를 sonnet으로 쓴다. 사실 리뷰는 lite여도 opus로 한다. `refresh`이면 아래 "refresh 모드"를 따른다.

**경로 약속**
- `SKILL`은 이 폴더 `.agents/skills/bio-cheatsheet`의 절대 경로다.
- `REPO`는 저장소 루트다.
- `RUN`은 `<scratchpad>/cheatsheet/<N>장/`이고, 그 안에 `sources/`, `sections/`, `work/`를 둔다.
- `OUT`은 `REPO/웹과제예상/커닝페이퍼/<N>장`이다.
- 셸 상태는 Bash 호출 사이에 이어지지 않는다. 그래서 명령마다 절대 경로를 쓴다.

**OUT에 `cheatsheet_<N>장.html`이 이미 있으면**(refresh가 아닐 때) 덮어쓰지 않는다. spec이나 찾기-점검이 없어도 시트가 있는 것으로 본다. `RUN/out/`에 새로 만든 뒤 보고할 때 교체 여부를 묻는다. 사용자가 다시 만들라고 하면 기존 파일도 교체할 수 있다.

## 절차

### 0. 당황 패턴 최신화
`REPO/웹과제/<M>장/`에 `questions.json`이나 `raw/` 화면이 있는데 `references/panic-patterns.md`에 "M장 웹과제 사실" 절이 없으면, 이 장을 만들기 전에 panic-patterns.md를 직접 고친다.
- 그 평가의 문항 수, 보기 수, 시간 제한, 부정형 비율과 문항 번호, 그림 문항, 기출과 같은 문제를 세어 "M장 웹과제 사실" 절을 더한다. 출처(파일 경로, 응시일)는 맨 위 출처 줄에 더한다.
- 표에 없는 패턴이 보이면 표에 한 줄을 더한다. 기존 줄은 지우지 않는다.
- 선택 표시는 답이 아니다. 사실은 questions.json(`option_diagnostics`, `issues`)과 intake.md에서만 가져온다.
- 고친 내용은 마지막 보고에 요약한다(더한 절, 더한 패턴 줄).

### 1. 원천 모으기
`REPO`에 `복습노트/`, `강의노트/`, `웹과제/`가 없으면 "생명과학 저장소에서만 동작합니다"라고 알리고 멈춘다. 아래에서 찾은 원천을 `RUN/sources/manifest.md`에 경로와 범위로 적는다.

| 원천 | 찾는 법 | 쓰임 |
|---|---|---|
| 정리노트 MD | `복습노트/*/정리노트_*.md` 중 3행 `(…N장…)` 표기가 있는 파일. 여러 장이 섞인 파일에서는 `*… · N장 p…*` 줄이 붙은 토픽만 쓴다 | 본문, `**착각:** … **바른 구분:**` 줄은 함정 재료 |
| 복습문제 MD | 같은 폴더의 `복습문제_*.md` | 기출 원문과 보기별 해설(틀린 보기는 함정 재료) |
| 장마감 | `복습노트/*/장마감_*_N장.md` | §1 범위, §2 필수 용어는 `chapter_terms`, §4 "몰라도 됨"은 `later` |
| 기출 | `23, 24 소스/N강*합본.pdf`(파일명에 `+`가 섞여 있다) | 기출 출제 범위 |
| 강의노트·교과서 | `강의노트/N장*.pdf`, `교과서/…/0N장_*.pdf` | 노트에 없는 사실을 확인할 때만 |
| 웹과제 | `웹과제/N장/questions.json`. 없고 `raw/`만 있으면 화면 이미지 | 문항 형식과 함정 재료. 화면의 선택 표시는 답이 아니다 |

- 정리노트가 하나도 없으면 멈춘다.
- 웹과제가 `raw/` 화면뿐이면 메인 에이전트가 `RUN/sources/webquiz_<N>장.md`에 문항마다 발문·보기·형식(단일 선택, 복수 선택, ㄱㄴㄷ 조합)만 받아 적는다. 선택 표시와 채점 결과는 옮기지 않는다. 화면에 없는 값(시간 제한 등)은 비워 두고, ①에서는 그 값을 1장 값으로 대신하되 "1장:"을 붙인다.
- `later`는 장마감 §4와 정리노트의 "몰라도 됨" 표시(교수님 발언)를 합친 목록이다. 장마감이 없으면 `chapter_terms`만 비우고 `later`는 정리노트에서 모은다. 이때 보고에 "장마감 없음"이라고 적는다.

### 2. 구역 설계 → `RUN/spec.json`
```json
{"chapter": 3, "title": "3장 세포분열",
 "sections": [
   {"label": "① 시험장 체크", "traps": false, "terms": ["1장"]},
   {"label": "② 용어 바꿔 부르기", "traps": false, "terms": []},
   {"label": "③ 염색체", "terms": ["자매염색분체", "상동염색체"], "sources": "0917 L209–L260, 0922 L68–L140"}],
 "chapter_terms": [], "later": [],
 "basis": {"built": "2026-10-07", "webquiz": ["1장", "2장", "3장"], "panic_patterns": "<sha256 앞 12자>"}}
```
- ① 시험장 체크와 ② 용어 바꿔 부르기는 언제나 맨 앞에 두고, 함정을 넣지 않는다.
- ③부터는 강의 순서(과정 순서)를 따른다. 구역은 10~16개로 하고, 라벨은 `번호 + 찾아볼 때 쓰는 말`로 짓는다.
- `terms`에는 그 구역에서 판별에 꼭 필요한 용어를 원천 표기 그대로 적는다.
- `basis`에는 `python3 "$SKILL/scripts/stale.py" "$REPO" --basis`가 출력한 값을 그대로 넣는다. 이 시트가 어떤 웹과제와 어떤 panic-patterns를 근거로 만들어졌는지 남기는 값이다. 0단계를 마친 뒤에 뽑는다. check.py는 이 값이 없으면 위반으로 센다.
- **쪽 수는 정하지 않는다.** 내용을 쪽에 맞춰 줄이지 않고, 쪽은 build.py가 늘린다.

### 3. 구역 작성 (병렬)
- 구역 하나에 서브에이전트 하나를 띄운다. 브리프는 `references/section-brief.md`를 채워 보내고, 결과는 `RUN/sections/NN.html` 하나로 받는다.
- 내용 규칙은 `references/content-rules.md`를 따른다.
- ①의 원천은 `references/panic-patterns.md`와 이 장의 웹과제 자료다.
- 서브에이전트가 없는 환경에서는 같은 브리프로 구역을 차례로 직접 쓴다.

### 4. 조립·쪽 나눔·PDF
```bash
python3 "$SKILL/scripts/build.py" "$RUN/spec.json" "$RUN/sections" "$RUN/out"
```
- build.py가 템플릿의 견본을 버리고 구역 조각을 spec 순서대로 넣는다. 그다음 Chrome으로 넘침을 재며 쪽을 나누고 PDF로 출력한다.
- 쪽 번호, 목차 줄, 테마 버튼도 build.py가 채운다. **HTML을 손으로 고치지 않는다.** 고칠 것이 있으면 조각을 고친 뒤 다시 build한다.
- "한 쪽보다 큼" 오류가 나면 그 구역을 둘로 나누고, spec에 라벨을 하나 더한다.

### 5. 검사 (모두 통과할 때까지, 리뷰-수정은 최대 2회)
1. `python3 "$SKILL/scripts/check.py" "$RUN/out/cheatsheet_<N>장.html" "$RUN/spec.json"`를 돌린다. 위반이 0건이어야 한다. 위반이 나오면 조각을 고치고 4단계로 돌아간다.
2. 쪽 이미지를 `pdftoppm -r 80 -png <pdf> "$RUN/work/page"`로 만들어 직접 본다. 그림 라벨이 겹치는지, 화살표가 글자를 지나가는지, 빈 쪽이 생겼는지 확인한다.
3. `references/review-brief.md`로 새 opus 에이전트에게 사실 리뷰를 맡긴다. 지적받은 것은 원천에서 직접 확인한 뒤에만 고친다.

### 6. 마무리
1. `RUN/out/`에 `찾기-점검.md`를 쓰고, `RUN/spec.json`도 `RUN/out/`에 복사한다. `OUT`에 시트가 없으면 `RUN/out/`의 네 파일을 `OUT`에 복사한다. 이미 있으면 복사하지 않고 보고에서 교체 여부를 묻는다.
2. `찾기-점검.md`는 기출(복습문제 MD) **5문제, 정확히 5행**이다. 다섯 문제는 서로 다른 구역에 걸치고, 부정형 문항과 그림 문항이 하나 이상씩 들어가게 고른다.
   ```
   | 문제 | 경로 | 찾을 구역 | 10초 이내 |
   |---|---|---|---|
   | 0922 P4 자매염색분체 vs 상동염색체 | 복습노트/0922/복습문제_….md | ③ 염색체 | |
   ```
   "10초 이내" 칸은 학생이 직접 재서 채운다.
3. `python3 "$SKILL/scripts/stale.py" "$REPO"`를 돌린다. 방금 만든 장 말고 낡은 시트가 나오면 보고에 그대로 옮기고 `/bio-cheatsheet <N> refresh`를 권한다.
4. 보고한다. 산출물 경로와 쪽 수, 검사 결과(check, 시각, 리뷰 지적 수와 처리), 원천에 없어서 뺀 내용, "장마감 없음" 여부, 0단계에서 고친 panic-patterns 내용, 낡은 시트 목록을 적는다. 마지막에 커밋 명령을 제안한다.

## refresh 모드
이미 만든 시트에 이후 등록된 웹과제와 갱신된 panic-patterns를 반영한다. ③부터의 본문은 이미 사실 리뷰를 통과했으므로 다시 쓰지 않는다. 바꾸는 것은 ①과 함정 추가뿐이다. 본문까지 고쳐야 하면 refresh 대신 전체를 다시 만든다.

1. OUT에 `cheatsheet_<N>장.html`과 `spec.json`이 없으면 "refresh할 시트가 없습니다"라고 알리고 일반 절차로 만든다.
2. 0단계를 돈다.
3. `python3 "$SKILL/scripts/extract.py" "$OUT/cheatsheet_<N>장.html" "$RUN/sections" --spec "$OUT/spec.json"`로 조각을 되살린다. 라벨이 spec과 다르다는 오류가 나면 멈추고 전체 재생성을 권한다. `$OUT/spec.json`은 `$RUN/spec.json`으로 복사하고 `basis`를 2단계처럼 새로 채운다.
4. ①을 3단계 규칙대로 새로 쓴다(원천: 최신 panic-patterns와 이 장의 웹과제 자료).
5. 이전 `basis.webquiz`(없으면 빈 목록)에 이 장의 웹과제가 없었고 지금은 등록되어 있으면, ③부터의 구역마다 서브에이전트에게 `references/section-brief.md`를 "refresh" 줄과 함께 보낸다. 기존 본문과 함정은 그대로 두고, 이 장 웹과제의 `option_diagnostics`로 함정을 더한다. 구역당 함정은 기존 것과 합쳐 3개를 넘지 않는다. 더할 게 없는 구역은 손대지 않는다.
6. 4·5단계(조립, 검사)를 그대로 거친다. 사실 리뷰는 바뀐 구역만 맡긴다.
7. 사용자가 refresh를 요청한 것이므로 `RUN/out/`의 시트, PDF, spec을 OUT에 바로 덮어쓴다(이전 판은 git에 있다). `찾기-점검.md`는 그대로 둔다. 보고에는 바뀐 구역과 더한 함정 수를 적는다.

## 흔한 실수

| 실수 | 대신 |
|---|---|
| 2쪽 안에 맞추려고 내용을 깎는다 | 쪽 수 제한은 없다. build.py가 쪽을 늘린다 |
| 넘침을 손으로 재고 HTML을 직접 옮긴다 | 조각만 고치고 build.py를 다시 돌린다 |
| 원천에 없는 "일반 교과 지식"을 넣는다(맞는 말이어도) | 뺀다. 보고의 "원천에 없어 뺀 내용"에 적는다 |
| 함정을 몇 구역에만 몰아 넣고 출처를 안 단다 | ③부터 구역마다 1~3개를 넣고, 함정마다 `<!-- 출처: … -->`를 단다 |
| 시험장 체크를 맨 뒤에 둔다 | ①로 둔다. 시험 시작 전에 보는 구역이다 |
| 웹과제 화면에서 학생이 고른 답을 정답으로 옮긴다 | 원천으로 판단한다. 답 번호와 "정답"은 시트에 쓰지 않는다 |
| 스스로 검토하고 끝낸다 | check.py, 쪽 이미지, 새 에이전트의 사실 리뷰를 모두 거친다 |
| 새 웹과제를 보고만 하고 panic-patterns에 안 넣는다 | 0단계에서 직접 더한다. 안 넣으면 다음 시트도 낡는다 |
| refresh에서 ③부터의 본문까지 다시 쓴다 | ①과 함정 추가만 한다. 본문을 고칠 거면 전체 재생성 |
| spec에 `basis`를 손으로 짐작해 적는다 | `stale.py --basis` 출력을 그대로 넣는다 |
