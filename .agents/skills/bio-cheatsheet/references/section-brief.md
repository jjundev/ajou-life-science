# 구역 작성 에이전트 브리프

메인 에이전트는 구역마다 아래 블록의 `{…}`를 채워 그대로 보낸다.

```
너는 생명과학 웹과제 커닝페이퍼의 구역 하나를 쓴다. 학생은 시험 중 태블릿에서 이 구역을 30초 안에 찾아 보기를 판별한다.

구역: {라벨}  (spec.json의 이 항목: {spec 항목 JSON})
원천 파일(이것만 읽고 이것만 근거로 쓴다. 웹과제 화면의 선택 표시는 답이 아니다):
{원천 경로와 줄 범위 목록}
규칙: {SKILL}/references/content-rules.md 를 먼저 읽고 따른다.
부품 견본: {SKILL}/assets/cheatsheet-template.html 의 <body> 안 견본 구역.

출력: {RUN}/sections/{NN}.html 파일 하나. 다른 파일은 만들지 않는다.
- spec 항목의 terms는 모두 본문 글자로 들어가야 한다.
- 명칭·단위·단계 요구: 제공된 장별 note-feedback 행과 실제 근거 위치를 대조한다. ②의 명칭 대응·단서는 원천 주석을 달고, 나머지는 필요한 비교 대상·조건·결과를 짧게 적는다. 개인 미확인 가설을 시트의 사실로 쓰지 않는다. 원천에 없는 이름은 제외하고 기존 설명이 충분하면 늘리지 않는다.
- 원천에 "몰라도 됨" 표시가 있는 항목: {later 목록 또는 "없음"}

끝나면 다음 세 줄만 보고한다:
1. 쓴 함정 수와 각 함정의 재료(착각 줄 / 기출 보기 / 웹과제 진단)
2. 원천에 없어 뺀 내용
3. 이 구역이 반 쪽을 넘을 것 같으면 그 사실
```

①은 `references/panic-patterns.md`를 원천으로 더 준다.

refresh 모드(SKILL.md "refresh 모드" 5)에서는 블록 끝에 아래 줄을 더하고, 원천 목록에는 이 장 웹과제 questions.json을 넣는다.

```
refresh: {RUN}/sections/{NN}.html 이 이미 있다. 본문과 기존 함정은 한 글자도 바꾸지 않는다. 이 장 웹과제의 option_diagnostics에서 기존 함정과 겹치지 않는 함정만, 기존 것과 합쳐 3개 이하가 되게 later 블록 앞(없으면 </section> 앞)에 더한다. 더할 게 없으면 파일을 건드리지 않고 "추가 0"이라고 보고한다.
``` ②는 원천 전체에서 실제로 같은 것을 다르게 부른 쌍만 모으라고 덧붙인다(근거 줄을 출처 주석에).
