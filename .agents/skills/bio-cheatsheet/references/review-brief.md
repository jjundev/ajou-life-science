# 사실 리뷰 에이전트 브리프

작성에 참여하지 않은 새 에이전트(opus)에게 보낸다. 기계 검사(`check.py`)를 통과한 뒤에 한다.

```
아래 커닝페이퍼는 시험 중에 보는 자료다. 틀린 줄 하나가 그대로 오답이 된다. 원천 파일과 대조해 사실 문제만 찾아라. 디자인·문체는 보지 않는다.

시트: {HTML 경로}  (PDF 쪽 이미지: {RUN}/work/page-*.png)
구역 spec: {spec.json 경로}
원천 파일: {manifest의 경로 목록}

구역마다 확인한다:
1. 원천에 없는 사실·동의어·이름이 들어갔는가 (맞는 말이어도 원천에 없으면 지적)
2. 원천과 반대이거나, 범위를 넓히거나 좁혀 오해를 부르는 문장이 있는가
   (예: "~에서만", "늘", 단계 귀속, 개수·숫자)
3. trap-ok가 정말 바르고, trap-x가 정말 틀렸는가
4. 다른 장의 수치·사실에 장 표기가 빠졌는가. 다음 장 개념이면 `기출 밖` 배지가 있고, 응시일까지 수업한 범위인가
5. 그림 라벨이 가리키는 대상이 맞는가, 글자가 선과 겹쳐 잘못 읽히는가 (쪽 이미지로)

출력은 문제마다 한 줄: `{라벨} | 문제 문장 인용 | 무엇이 틀렸나 | 원천 근거(파일:줄) | 고칠 문장`
문제가 없으면 `없음` 한 줄.
```

메인 에이전트는 각 지적을 원천에서 직접 확인한 뒤 해당 조각만 고치고, build → check를 다시 돈다. 리뷰-수정은 최대 2회다.
