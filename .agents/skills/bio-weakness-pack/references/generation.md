# 기존 생성기 연결

## 저작 규칙 재사용

형제 `bio-review-pack/references/manifest-guide.md`, `content-rules.md`, `card-rules.md`, `browser-check.md`를 읽는다. 내용의 범위는 수업 전체가 아니라 `diagnosis.json`에서 선정한 개념과 그것을 이해하는 데 필요한 선행 개념이다.

- `manifest.range`, `slug`는 `plan.json`과 일치시킨다. 제목·출처는 공부 기록 기반 약점 보완으로 쓴다. 학습자의 말을 `prof` 레이어에 넣지 않는다.
- 정리노트: 당시 막힌 지점, 쉬운 설명, 정확한 기준, 작은 사례·필요한 그림, 혼동 방지, 요약. 기존 레이어와 `.sum` 구조를 쓴다. 마지막에는 요약·다음 확인·자료 링크를 둔다. `preview_topic`에는 다음 수업의 내용을 새로 넣지 않고 다음 재확인을 안내할 수 있다.
- 보충이 있으면 공유 `content-rules.md`의 「보충 요약」 계약을 적용한다. 보충마다 본문 id와 우측 `.sum-supp`을 연결하고 동일 배지로 수업 요약과 구분한다. 모든 보충의 핵심·조건·예외가 요약에도 있는지 검토하며, 수정 후 정리노트 MD도 동기화한다.
- 원래 차시의 정리노트·복습문제·문제설명 HTML 전체를 먼저 읽는다. SSTT의 발언은 diagnosis.json의 source_context에 원래 문항·보기·해설과 연결한다. 관련 기존 노트에는 실제 토픽으로 링크한다. 상대 링크는 임시 RUN이 아니라 **최종 출력 폴더 기준**으로 계산한다. v2는 한 단계 더 깊다.
- 문제 수를 10개로 고정하지 않는다. 주요 미해결 혼동은 기준 확인과 조건 변경 적용을 구분하고, 공부 중 정정도 필요한 짧은 재확인으로 배치한다. 독립 자기교정인지 해설 참고 후 정정인지 불명확하면 이를 현재 숙련이나 독립 풀이 성공으로 표현하지 않는다. 의미가 같은 문제를 수만 늘리려고 반복하지 않는다. 문제당 판단 기준 하나를 중심으로 하되 필요한 비교는 허용한다.
- 새 문제는 `partC`, `variant=true`, `source="생성 변형 <topic-id>"`로 표시한다. 실제 기출·웹과제라고 쓰지 않는다. 모든 보기에 구체적인 선택·제외 이유를 쓴다. 수준1~2를 기본으로 하며 심화는 실제 보완 목적이 있을 때만 사용한다.
- 실제 원문 문제를 넣는다면 출처와 원문을 검증하고 기존 partA/B 규칙을 따른다. 문제 원문을 특정하지 못하면 새 문제로 작성한다.

저작물은 `RUN/manifest.json`, `sections/<sid>.html`, `cards/<pid>.html`, 필요한 `figures/`에 둔다. 생성 변형은 `variants.md`에 ID·근거 토픽·형태·자료 쪽·의도한 답과 이유를 적고, `key-check.md`에는 생성 문항임과 검산 결과를 적는다. 내부 진단의 시각은 학생용 조각에 넣지 않는다.

`python3 CLI assemble --run RUN`은 진단 근거와 입력 해시를 확인한 뒤 기존 조립·기계 검사·MD 변환을 수행한다. 생성된 복습문제의 저장 안내·`약점노트` 루트 선택만 이 팩 위치에 맞게 조정한다. 기존 스킬 자산을 수정하지 않는다. 동일 RUN의 초안은 백업 후 재조립할 수 있지만 완료 팩이나 풀이기록이 있는 초안은 새 버전으로 진행한다. 원문 또는 저작물이 바뀌면 독립 풀이·해설 검토를 필요한 단계부터 다시 한다.

## 문제설명

형제 `bio-problem-explain/SKILL.md`, `references/authoring.md`, `references/verification.md`를 읽고 전체 절차를 따른다. 그 스킬의 `all`·최신 날짜 선택은 복습노트용이므로 **최종 복습문제 HTML의 절대 경로**를 `extract --target`에 준다. EXPLAIN_RUN도 저장소 밖 새 경로를 `resolve()`해 사용한다.

정답 비공개 검산자는 카드 풀이·manifest 정답·variants·설명 조각을 보지 않고 문제·개념노트·강의자료·교재로 다시 푼다. 답이 다른 생성 문제는 컨트롤러가 표현·정답 유일성·범위를 확인해 수정하고 새 입력으로 검토한다. 구조 검사만으로 정답·시각 검토를 승인하지 않는다. 실제 자료 시각·내용·독립·브라우저 네 검토가 pass일 때만 publish한다. 검산자가 없거나 충돌을 해소하지 못하면 보류한다.

## 약점팩 완료 검토

문제설명 네 검토와 별도로 다음 두 범위의 실제 결과를 `RUN/review.json`에 기록한다. `evidence`는 비어 있지 않은 RUN 내부 파일의 상대 경로다. 검토 파일에 확인한 항목·결과·한계를 적는다.

```json
{
  "diagnosis": {"status": "pass", "reviewer": "실제 검토자", "evidence": "work/diagnosis-review.md"},
  "browser": {"status": "pass", "reviewer": "실제 검토자", "evidence": "work/browser-results.json"}
}
```

- **진단:** 선택한 모든 SSTT의 끝까지 읽었는지, 뒤의 정정과 정정 경로가 반영됐는지, 해당 차시 정리노트·복습문제·문제설명 HTML 전체(접힌 해설 포함)를 실제 확인했는지, 원래 문항·보기·해설 연결이 맞는지, 누락 자료·미확정 연결이 보류됐는지, 모든 약점과 문항의 연결·자료 근거가 맞는지 본다. 현재 숙련을 단정하지 않는지 확인한다.
- **브라우저:** 기존 browser-check 기준으로 정리노트·복습문제 전체 화면을 1280×900/375×812, light/dark에서 검사하고 스크린샷을 직접 본다. 요약·그림·링크·가로 넘침·콘솔·채점·오답과 정답 해설·재시도·Enter/Space·새로고침 복원·새 탭 초기화·unsure·JSON 내보내기를 확인한다. 버전 폴더와 상위 약점노트 폴더를 선택할 때의 저장 경로도 확인한다. 테스트 답은 사용자 풀이기록에 넣지 않는다.

정리노트·복습문제의 기존 허용 CDN(Pretendard/KaTeX)과 문제설명의 로컬 자원 계약을 구분한다. 전자를 외부 요청 0·오프라인 동작으로 보고하지 않는다.

`python3 CLI finish --run RUN`은 입력·참고자료·발행 산출물 해시, HTML/MD 3종, 문제설명 검토와 팩 검토 근거를 확인해 `.pack/weakness-run.json`을 complete로 만든다. 해시·파일 검증은 사람이 실제 검토했는지 자동으로 증명하지 않는다. 근거 없는 pass를 만들지 않는다.

실패한 팩은 초안으로 보존하고 보류 이유를 보고한다. `remaining`의 다른 날짜는 계속한다. 변경·미완료 팩은 다음 호출에서 자동 재작성하지 않고 날짜 지정 `regenerate` 대상으로 안내한다.
