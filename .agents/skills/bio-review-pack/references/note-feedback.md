# 실제 웹과제의 문항별 피드백을 본문에 연결하기

## 자료 읽기와 증거 구별

이번 장의 `웹과제/<N>장/note-feedback.md`가 있으면 **questions.json 등록·partA 포함 여부와 독립적으로** 읽는다. 4장 자료는 `웹과제/4장/note-feedback.md`다. 없으면 원본 raw만으로 판별 원리를 즉석 확정하지 말고 ‘문항별 피드백 미작성’으로 보고한다. 기존 bank 문항의 requirements/option_diagnostics는 기존 포함 문항 전달 경로를 유지한다.

피드백은 원본 source ID, 판단에 필요한 개념, 강의노트·STT·교재의 실제 위치, 판독 불확실성을 갖춰야 한다. 선택 표시는 공식 정답·개인의 오개념으로 취급하지 않는다. 개념 근거를 확인했다고 미등록 발문을 partA에 복사하거나 정본 questions.json을 생성하지 않는다. 등록은 web-quiz-extract의 기존 검증 절차를 따른다. 원본과 근거 파일을 다시 열어 필요한 주장을 확인하고, 사용한 자료 path/SHA256을 아래 실행 기록에 남긴다.

## 명칭·비교 단위의 충족 기준

출제 관찰과 개인 학습 가설을 구별한다. 선택 불일치는 공식 오답이 아니며, 가설은 경쟁 설명·확인 방법과 함께 미확인 상태로 유지한다. 모호한 문항·무선택만으로 취약점을 정하지 않는다. 기존 노트의 영어 병기·예시가 충분한지 먼저 확인하고, 병기 존재와 다른 이름에서의 회상 연습을 따로 판단한다.

해당 문항이 요구할 때만 출처가 확인된 이름↔현상, 대상·비교 단위, 조건·결과, 인접 반대 사례를 최소 문장으로 가르친다. 예를 들어 하나의 전구체에서 여러 성숙 mRNA를 만들 수 있다는 설명과 진핵 세포질의 성숙 mRNA 한 종류가 대개 한 단백질 정보를 담는 설명은 함께 성립한다. 전사 조절은 DNA 접근성·개시 조절, 전사 후 조절은 만들어진 RNA의 가공·수명으로 구별한다. 모든 토픽에 표·긴 동기 문단을 붙이지 않는다.

아래 8열 감사표를 유지한다. `필요 개념/판별 기준`에 명칭·단위 등 실제 요구를 적고 `본문 문장 또는 보류 이유`에는 그것을 충족하는 실제 문장을 적는다. 단어가 없다는 이유로 근거 없는 동의어를 추가하거나 원문 문제를 고치지 않는다. 기존 설명으로 충분하면 그 문장을 인용해 중복을 피한다. 피드백 없음은 미작성, 근거 부족은 보류이며, 예정은 완료가 아니다.

## manifest와 섹션 저작

카드에 넣지 못한 문항도 본문 개념 점검 대상이다. 2단계에서 `RUN/note-feedback-audit.md`를 만든다. 이번 장의 모든 피드백 ID를 다음 표에 한 번씩 적고, 여러 장이면 장 번호를 함께 쓴다.

`| 피드백 ID | 원본 source | 필요 개념/판별 기준 | 범위 상태 | 대상 토픽/이전 노트 링크 | 계획 레이어 | 적용 상태 | 본문 문장 또는 보류 이유 |`

- 범위 상태: 이번 수업 / 이전 수업 / 미학습 / 판독·근거 불확실. 이번 수업은 STT와 슬라이드 대조표로 확인한다.
- 계획 시 적용 상태는 ‘예정’이다. 관련 토픽의 formal·warn에 **질문을 판단하는 기준과 필요한 최소 과정**을 배치하고 required_terms에 판별 용어를 포함한다. 같은 개념은 합쳐 가르치되 표의 피드백 ID는 모두 유지한다.
- 이전 수업 개념은 원천 노트의 정확한 토픽 링크와 핵심 연결을 준다. 아직 안 배운 다음 토픽은 이름만 예고하거나 보류한다. 출제됐다는 이유로 범위를 앞당기지 않는다.
- 이번 토픽의 판단을 위해 필요한 추가 사실은 기존 supp 규칙대로 출처·배지를 붙인다. 근거 없는 보충은 넣지 않는다. 공식 답/문항 번호/보기 글자를 본문에 노출하거나 문제 풀이를 복사하지 말고 원리·짧은 새 사례를 가르친다.
- 3단계 섹션 작성자에게 카드 포함 여부와 관계없이 해당 토픽의 행과 근거 파일을 전달한다. 작성자는 formal·warn·supp에 반영하고, 이전 노트만으로 충분하면 링크로 연결한다. 이미 충분한 설명은 늘리지 않는다.

표 앞에는 입력 피드백·원본·강의노트·STT·교재의 실제 path/SHA256과 range를 적는다. 작성 후 적용 상태를 ‘본문 반영 / 기존 설명 충분 / 이전 노트 연결 / 미학습 보류 / 판독·근거 불확실’ 중 하나로 바꾸고 실제 토픽 id·본문 문장(링크면 링크 대상의 판별 문장)을 채운다. 계획만 적힌 ‘예정’을 반영 완료로 세지 않는다.

## 필수 검토와 기록

6단계에서 `review-prompt.md`의 **본문 피드백 검토**를 카드 블라인드 검사와 별도로 수행한다. 대상 범위의 모든 행에서 원본이 요구하는 판별 기준을 본문 문장으로 설명할 수 있는지 확인한다. 빠진 기준이 있으면 섹션을 고치고 기존 조립·검사·검토를 다시 수행한다. 미학습·불확실 행은 보류 사유를 공개한다. 카드 검사 통과를 전체 실제 문항의 본문 검증이라고 보고하지 않는다.

최종 표를 저장한 뒤 마지막 조립을 다시 수행하여 `.pack/note-feedback-audit.md`에도 같은 기록을 남긴다. 조립기는 full 모드에서 이 선택 파일을 복사한다. 이전 실행 기록을 이번 실행 결과로 재사용하지 않는다. 피드백 파일이 없으면 이번 검토 대상이 없음을 보고하며 이전 감사표가 남아 있다면 과거 기록으로 구별한다. 미반영/보류 수와 이유를 9단계 보고한다. 장 마감에서는 해당 장의 전체 피드백 ID를 회차별 적용 기록과 대조해 빠진 연결을 점검한다.

## 기존 팩과 augment

augment는 복습문제 보강 모드이고 정리노트 HTML·MD를 바꾸지 않는다. 따라서 새 피드백의 본문 반영 완료로 보고하지 않으며 `.pack`의 기존 본문 피드백 감사표도 덮어쓰지 않는다. 본문 반영이 필요한 기존 팩은 **전체 재생성(augment 아님)** 대상으로 보고한다. 재생성 때 기존 백업·카드 번호·풀이기록 보존 규칙을 지킨다. 사용자가 생성 스킬만 업데이트하라고 한 경우 기존 팩을 자동 재생성하지 않는다.
