# 리뷰어 지시문

6단계에서 세 리뷰어(블라인드 풀이·본문 감사·일반 리뷰)를 한 메시지에서 병렬로 띄운다. 메인 에이전트는 이 파일에서 **블라인드 사본 스니펫만** 실행하고 나머지는 읽지 않는다. 리뷰어에게 "`<SKILL>/references/review-prompt.md`의 「<절 이름>」 브리프와 `<SKILL>/references/report-contract.md`를 읽고 따른다"와 값 `RUN`, `SKILL`, `range`, 정리노트·복습문제 HTML 경로만 넘긴다. 리뷰어는 상세를 `<RUN>/work/reports/`에 쓰고 영수증만 돌려준다. 대조·배분은 `scripts/pack_run.py`가 한다.

## 블라인드 풀이 검사

먼저 메인 에이전트가 복습문제에서 문제·보기·그림만 뽑은 사본을 만든다(`REVIEW`는 조립된 복습문제 HTML 절대 경로). 기출 그림(`<img>`)은 PNG 경로를, 웹과제 인라인 `<svg>`는 `OUT`과 같은 폴더의 `blind-figs/<pid>-<n>.svg` 파일로 저장한 경로를 `[그림: …]` 줄로 남긴다. `OUT`의 `$RUN`은 같은 명령 앞에 붙인 `RUN=…`로는 펼쳐지지 않으므로, 같은 Bash 호출 맨 앞에 `RUN=…;`로 먼저 설정하거나 `OUT`에 절대 경로를 직접 쓴다.
```bash
REVIEW=… OUT="$RUN/work/blind-<range>.md" IDS="" python3 - <<'EOF'
import html, os, re
src = open(os.environ["REVIEW"], encoding="utf-8").read()
base = os.path.dirname(os.environ["REVIEW"])
cards = re.findall(r'<article class="card" id="(p\d+)"[^>]*>\s*<h3>(.*?)</h3>\s*<div class="problem">(.*?)</div>\s*<details', src, re.S)
ids = {i for i in os.environ.get("IDS", "").split(",") if i}
if ids:  # 보강 모드: 새 카드만
    cards = [c for c in cards if c[0] in ids]
figs = os.path.join(os.path.dirname(os.path.abspath(os.environ["OUT"])), "blind-figs")
def text(pid, h):
    n = 0
    def svg(m):  # 웹과제 인라인 SVG → blind-figs/<pid>-<n>.svg
        nonlocal n
        n += 1
        os.makedirs(figs, exist_ok=True)
        path = os.path.join(figs, f"{pid}-{n}.svg")
        s = m.group(0)
        if "xmlns=" not in s.split(">", 1)[0]:
            s = s.replace("<svg", '<svg xmlns="http://www.w3.org/2000/svg"', 1)
        open(path, "w", encoding="utf-8").write(s)
        return f"\n[그림: {path}]\n"
    h = re.sub(r"<svg\b.*?</svg>", svg, h, flags=re.S)
    h = re.sub(r'<img [^>]*src="([^"]+)"[^>]*>', lambda m: f"\n[그림: {os.path.join(base, m.group(1))}]\n", h)
    h = re.sub(r"</(p|li|figure)>|<br\s*/?>", "\n", h)
    return html.unescape(re.sub(r"<[^>]+>", "", h)).strip()
with open(os.environ["OUT"], "w", encoding="utf-8") as f:
    for pid, title, body in cards:
        f.write(f"## {pid}. {html.unescape(re.sub(r'<[^>]+>', '', title))}\n\n{text(pid, body)}\n\n")
print(len(cards), "문항")
EOF
```
출력 문항 수가 manifest 문제 수와 다르면 카드 마크업 순서를 고친 뒤 다시 만든다. 보강 모드에서는 `IDS`에 새 카드 id만 넣는다(출력 문항 수 = 새 카드 수).

---
생명과학 복습팩의 블라인드 풀이 검사를 한다. 파일은 수정하지 않는다.

- 열 수 있는 파일은 **두 개뿐**이다: 정리노트 `<RUN>/repo/복습노트/<range>/<정리노트 html>`, 문항 사본 `<RUN>/work/blind-<range>.md`(그 안의 `[그림: …]` 줄이 가리키는 그림 파일 — 기출 PNG와 `<RUN>/work/blind-figs/`의 웹과제 SVG — 도 볼 수 있다). 복습문제 HTML, manifest, 요약, 교과서, 인터넷, 다른 파일은 열지 않는다. 자기 배경지식으로 풀지 말고 정리노트에 쓰인 내용만 근거로 삼는다.
- 수준 판정 기준: 1 정의·관계·도식을 직접 식별, 2 한 가지 원리 적용·짧은 추론, 3 여러 조건·원리 연결·추가 조건부 계산. 그림·부정형·보기 개수 자체로 높이지 않는다. 기본은 1~2, 심화는 3이다.
- 문항마다 최소 풀이 단계와 수준을 독립 판정한다. 설계의 예상 수준은 보여 주지 않는다. 보강의 새 문항에도 이 검사를 적용한다.
- 문항마다 답을 고르고, 근거가 된 정리노트 토픽 id를 적는다. 정리노트만으로 판단할 수 없는 보기가 있으면 "근거 없음"으로 적고 무엇이 빠졌는지 쓴다.
- 이 검사에서만 `<SKILL>/references/report-contract.md`도 읽을 수 있다(쓰는 방법과 영수증 형식).
- 보기 진단에 `+낯선참`으로 설계된 보기(교과서에만 있는 참인 진술)는 정리노트에 근거가 없어도 정상이다. 정답 보기의 근거만 판정하고, 그 보기 때문에 "근거 없음"으로 적지 않는다(메인 에이전트가 해당 카드 id를 알려 준다).

출력: `<RUN>/work/reports/blind.tsv` 한 파일(탭 구분, 문항마다 한 줄, 칸 순서 `문항 · 내 답 · 근거 토픽 · 빠진 사실 · 최소 풀이 단계 · 수준`). 이 파일 쓰기만 예외로 허용된다.
```
p1	(2)	s1-centromere		위치 확인 → 기능 판별	2
p4	근거 없음	—	보기 (3)의 방추사 부착 위치가 노트에 없음	판정 불가	판정 불가
```
보고: 영수증만 쓴다. `수`에는 답을 고른 문항 수와 "근거 없음" 수, `결함`에는 "근거 없음" 문항 id와 빠진 사실 한 줄씩만 적는다. 표를 보고 본문에 싣지 않는다(정답을 모르므로 맞았는지는 판정하지 않는다).
---

메인 에이전트는 `python3 "$SKILL/scripts/pack_run.py" blind-check --run "$RUN"`으로 리뷰어 답을 manifest `answer`와 비교한다(결과 `RUN/blind-results.md`, 출력은 풀린 수와 불일치 문항뿐). 다르거나 "근거 없음"인 문항은 `anchor` 토픽의 섹션 작성자에게 빠진 사실을 가르치도록 되돌린다(스크립트가 `findings-blind.tsv`로 넘기고 `pack_run.py fixes`가 담당자 파일에 넣는다). 카드 풀이를 바꿔서 맞추지 않는다. 고친 뒤 사본을 다시 만들어 그 문항만 다시 검사한다(재검사 결과는 `blind-results.md`에 이어 붙는다).

메인은 `blind-check` 출력의 수준 불일치 목록으로 독립 수준을 manifest `level` 및 partC `variants.md`와 대조한다. 불일치하면 풀이 단계를 확인해 분류를 재검토한다. 원문은 난이도 배합 때문에 수정하지 않는다. 생성 변형은 범위·유일 정답을 확인한 뒤 수정/교체하거나 배합 차이를 보고한다. 기본/심화 실개수는 partC만 따로 센다. 기존 최대 2회 검사 한도 안에서 재검사하며, 판정 불가나 남은 차이는 미해결로 보고한다.

## 본문 피드백 검토

카드 블라인드 검사와 별개다. 실제 웹과제 자료가 있어도 카드로 등록되지 않았거나 이전 팩에 들어 있으면 카드 검사만으로 개념 누락을 찾지 못한다.

- 검토 대상: 최종 정리노트, `RUN/note-feedback-audit.md`, 해당 장 `웹과제/<N>장/note-feedback.md`, 연결된 raw 원본, 실제 강의노트·STT·교과서. 공식 답·선택 표시를 정답으로 삼지 않는다.
- 피드백의 전체 ID가 표에 있고 이번 수업/이전/미학습/불확실 상태로 나뉘었는지 확인한다. 이번 수업과 관련된 ID마다 토픽과 **본문 문장**을 직접 읽고 원본 보기의 판별 기준·최소 적용 과정을 설명할 수 있는지 확인한다. `required_terms`만 존재하는 것으로 통과시키지 않는다. 명칭 요구는 근거 있는 이름→현상·현상→이름의 연결이 가능한지, 단위 요구는 대상·조건·결과·인접 사례를 바르게 구별하는지 실제 문장과 짧은 새 사례로 확인한다. 영어 병기가 이미 있는 노트를 병기 누락으로 재진단하지 않는다. 다른 장에 해당 용어가 없으면 그 장의 범위로 검토한다. 이 검토자의 풀이 성공은 학생의 회상·숙달 증거가 아니다.
- 이전 노트 연결은 실제 링크 대상의 설명으로 충분한지 확인한다. 다음 수업 내용은 당겨오지 않는다. 출처 없는 보충, 판독 불확실의 확정, 문제번호/정답을 본문에 복사한 것은 수정한다.
- 출력: `notes-feedback-review.tsv`에 `피드백 ID · 상태 · 근거 토픽·본문 문장 · 빠진 판별 기준/보류 이유`. 판정은 통과/누락/보류다. 누락은 `findings-body.tsv`에도 고칠 내용과 함께 적는다. 공식 채점 미확인은 이 검토로 해소되지 않는다.
- 메인은 누락을 작성자에게 되돌리고 재조립·기계 검사 및 해당 ID 재검토를 한다. 기존 최대 2회 제한을 지킨다. 최종 결과를 감사표에 반영한 후 마지막 조립으로 `.pack/note-feedback-audit.md`에 저장한다. 미해결은 보고한다. 이 검토는 근거를 열어 수행하는 본문 충족도 검토이며 블라인드 풀이로 명명하지 않는다.

## 본문–요약 전수 대조

- 먼저 용어 설명을 읽지 않고 토픽의 `sum-lead`만 따로 읽는다. 대상·핵심 관계가 명확한지, 비교 토픽에서 핵심 비교 대상과 차이가 함께 드러나는지 확인한다. 이어 본문과 대조해 정확성과 수업·보충 경계를 검토한다. 아래 용어 설명의 복사나 단순한 바꿔쓰기를 토픽 요약으로 통과시키지 않는다. 세부 항목을 모두 나열하도록 요구하지 않으며 단순 정의 토픽은 정의 한 문장으로 충분하다.
- 학습 토픽별 `첫 문장 검토` 행을 `rows-review.tsv`에 남긴다(작성자가 이미 쓴 토픽은 다시 판정해 같은 형식으로 쓴다). `pack_run.py audit-merge`가 `RUN/summary-audit.md`에 합친다. 본문의 핵심 주장 칸에 `첫 문장 검토: <핵심 관계·차이>`, 대응 문장 칸에 실제 `sum-lead`, 판정 칸에 통과 또는 수정 필요와 이유를 적는다. 이 행은 기존 핵심 주장별 행에 추가하며 수정 후 재검토한다. 문장 복사가 아니어도 주어·대상 누락이나 비교의 한쪽 누락은 수정한다.
- `references/content-rules.md`의 전수 대조 규칙대로 모든 학습 토픽을 검사한다. formal·warn·supp와 prof의 강조 내용에서 추출한 핵심 개념·원리·조건·구분을 `RUN/summary-audit.md`의 실제 요약 문장과 대조한다. 감사표의 행만 읽지 말고 본문을 읽어 표 자체에서 누락된 핵심도 찾는다.
- 용어 개수나 `.sum` 존재만으로 통과시키지 않는다. 요약만 따로 읽었을 때 작용 대상·단계·결과가 구별되고 한정어·예외·수업 범위가 보존되는지 판단한다. 반복·긴 비유·명칭 유래는 이유를 남겨 생략할 수 있다. 마지막 `layers: []` 토픽의 요약 부재는 결함이 아니다.
- 누락은 요약을 고친 뒤 다시 대조한다. 본문·요약 변경 시 해당 감사표와 정리노트 MD도 갱신한다. 최종 표는 `.pack/summary-audit.md`에 남긴다.

## 본문 밀도 검토

본문 감사 리뷰어가 학습 토픽마다 펼쳐진 본문(접힌 `details` 제외)만 읽고 `references/content-rules.md`의 「내용 유형별 형식」과 대조한다. 기계 검사는 함정 표·사슬·접힘의 모양만 보므로 아래는 직접 판단한다.
- 같은 사실이 eli5·formal·warn·prof·figcaption에 두 번 이상 펼쳐져 있는가(`.sum`은 제외).
- 대상 2~4개의 비교나 고리 2~5개의 짧은 과정이 문단으로 풀려 있는가.
- 요약의 `⚠️ 혼동 지점`이 모두 warn 표의 행이나 문장 쌍으로 있는가.
- 시험 언급·강조 발언·판별 기준·동기·인과 설명이 `details` 안에만 있는가.
- 표 칸이 조건을 잃었는가(예: "항상"이 아닌 것을 한정어 없이 적음).

「어려운 개념에 한정한 동기·인과 설명」에 따라 비교 대상이나 고정 조건이 바뀌는 곳, 관측값을 해석하는 곳, 중간 상태로 다음 상태를 판단하는 곳에서 추론이 막히기 쉬운 토픽을 고른다.
- 토픽마다 대표 질문 하나를 만든다. 근거 자료를 펼치기 전에 해당 토픽의 펼쳐진 본문·그림과 직접 연결된 선행 토픽을 읽고, 어느 문장이나 표시로 답을 유도할 수 있는지 확인한다. 주어진 근거로 유도할 수 있으면 통과다. 단순 정의·명칭·목록은 이 질문 검사의 적용 대상에서 제외한다.
- 답에 필요한 전제가 접힌 설명이나 별도 인터랙티브에만 있거나 본문에서 빠졌으면, 강의노트·STT·교재로 보강 근거와 수업 범위를 확인한다. `findings-body.tsv`의 기존 네 칸을 사용한다. `문제` 칸에 대표 질문과 빠진 전제를, `고칠 내용` 칸에 보강할 최소 내용과 본문의 위치를 쓴다.

결함은 토픽 id와 고칠 내용을 `findings-body.tsv`에 적어 섹션 작성자에게 한 번에 되돌린다. 수정 후에는 그 파일의 `문제` 칸에서 대표 질문을 가져와 다시 답하고 본문–요약 전수 대조의 해당 행도 다시 본다. 영수증의 `수`에는 해결·미해결 건수, `결함`에는 남은 `critical`·`important`의 토픽 id와 빠진 전제를 적는다. 기존 최대 2회 한도에 포함한다. 중복을 정리할 때 판단에 필요한 전제는 펼쳐 둔다. 선택적으로 읽는 부연은 접힘에 둔다.
