## 범위
- 본문(eli5·formal·prof·warn)에는 이번 STT에서 **한 번이라도 언급된** 개념만 쓴다. 강의노트는 목차 뼈대일 뿐이고 STT가 주 자료다. 다음 수업 내용을 당겨오지 않는다.
- 슬라이드 대조표에서 "예고만/안 다룸"인 내용은 `s<N>-next`에 이름만 쓴다. 끊긴 지점은 여기에 교수님 마지막 발언을 간결하게 적는다.
- STT의 시각·구간·파트 번호는 내부 근거 확인에만 쓴다. 학생용 HTML 본문·인용·그림 설명·요약 패널에는 녹음 위치를 적지 않는다(`(0929 Part 05)`, `Part 08 끝` 같은 표기도 금지. 인용 뒤에 출처 괄호를 붙이지 않는다. `check_html.py`가 `stt-part`로 검사한다). 날짜 배지와 강의노트·교재 쪽수는 유지한다.
- STT에 없지만 포함 문항·검토된 실제 문항 피드백의 현재 토픽을 판단하거나 아래 기준에 해당하는 어려운 개념의 인과적 이해 공백을 메우는 데 필요한 사실은 supp 레이어에 쓰고 실제 출처를 밝힌다(`출처: 강의노트 3장 p14`, `출처: 교재 3장 p.68`, 외부 자료면 자료명). 수업에서 생략했다는 사실을 "시험에 안 나온다"로 바꾸지 않는다. 배지는 둘 중 하나다. 강의노트·STT 어디에도 없고 교재·외부에만 있으면 `보충 · 수업에서 다루지 않았어요`, STT나 강의노트에 있는데 정리노트 본문에서 빠졌으면 `보충 · 노트에 빠졌던 수업 내용`. 출처 줄로 어느 자료인지 밝힌다(`출처: 0903 수업, 강의노트 1장 p5`).
- 수업에서 말한 모든 개념, 교수님 비유와 강조 발언을 빠짐없이 싣는다. 잡담은 "이 비유를 지우면 개념 이해가 나빠지는가"로 판별해 버린다.
- STT 오인식과 말실수는 올바른 형태로 쓴다.
- 쉬운 설명에서도 성립 조건과 분류 경계를 지킨다. 어떤 경로·과정에 참여한다는 것을 그 계(系)의 구성원이라고 쓰지 않는다. 시험에서 판별에 쓰는 원래 용어는 쉬운 말과 함께 남긴다.
- 분류 개념(무엇이 어디에 속하는가)은 포함되는 것과 제외되는 것을 나란히 쓴다. 헷갈리는 짝이 있으면 역방향으로도 확인한다(예: 기능이 특히 많이 필요한 세포 → 소기관, 조건 → 분류).
- "항상", "늘", "반드시" 같은 절대 표현은 반례를 확인하라는 신호로 가르친다. 절대 표현이면 무조건 오답이라는 요령은 쓰지 않는다.

## 어려운 개념에 한정한 동기·인과 설명
- 사용자가 이해가 안 된다고 지적하거나 “왜 쓰는가”, “처음에는 어떻게 시작하는가”를 물은 개념에 적용한다. 별도 지적이 없어도 이중 부정, 여러 단계의 인과, 겉보기 순환(산물이 있어야 그 산물을 만들 수 있는 상황), 중요한 숨은 조건 때문에 정의만으로 원리가 연결되지 않는 경우에 적용한다. 실험·기술의 재료나 절차만 읽으면 직접 측정하는 대상 또는 궁극적으로 답하려는 질문을 오해하기 쉬운 경우도 적용한다. 단순히 전문용어가 낯설다는 이유로 적용하지 않는다.
- 해당 개념이 필요한 상황과 해결하는 문제를 먼저 연결하고, 작동 원리와 작은 사례·상태 변화를 이어 설명한다. 시작 조건이나 흔한 오해가 막힌 지점이면 함께 밝힌다. 예를 들어 lac 억제자는 자원 절약, 억제 해제, 첫 젖당 유입을 연결해야 “운반 단백질이 없는데 어떻게 시작하지?”라는 공백이 해소된다.
- 위 선별 기준에 해당하는 어려운 실험·기술 개념에만, 필요한 상황 → 직접 측정하는 값 → 그 값의 해석 → 궁극적으로 답하려는 질문을 연결한다. 절차를 나열하거나 “비교한다”라고만 쓴 것을 목적 설명으로 인정하지 않는다. 실제로 혼동하기 쉬운 대상이 있으면 재료의 역할과 측정 대상을 짧게 구분하고, 작은 가상 사례는 가상임을 밝힌다. 예를 들어 발현용 미세배열에서는 고정 DNA가 유전자를 구별하는 탐침이며, 조건별 RNA 유래 시료의 결합 신호로 발현 차이를 살펴 세포 활동의 차이를 연구한다는 연결이 필요하다. 서열 유사도 평가나 단백질 직접 측정과 혼동하지 않도록 구분하되, 다른 종류의 미세배열까지 같은 목적이라고 일반화하지 않는다. 관찰 결과만으로 인과를 확정하지 않는다.
- 과정에 참여하는 재료의 출처·준비 상태나 선택 주체를 생략하면 원리를 오해하기 쉬운 토픽에서는, 과정에 들어오기 전에 무엇이 준비되어 있는지와 누가 준비하는지를 짧게 연결한다. 새 물질의 생성과 기존 재료의 선택·운반·연결을 구분하고, 정확한 짝을 고르는 단계가 여러 개면 각 단계의 담당 주체와 인식 대상을 구별한다. 예를 들어 번역에서는 아미노산 자체의 생성, 합성효소의 아미노산–tRNA 짝맞춤, 코돈–안티코돈 짝짓기, 폴리펩티드 연결을 같은 사건으로 설명하지 않는다. 재료의 출처는 해당 오해를 해소하는 범위만 설명하고, 상세 대사·영양 내용을 모든 노트에 강제하지 않는다. 수업 밖 사실은 아래 supp·출처 규칙을 따른다.
- 필요한 부분만 짧게 기존 formal/warn/supp에 통합한다. eli5의 전문용어 없는 1~3문장 규칙은 유지한다. 토픽마다 고정된 동기 문단·문단 수를 강제하지 않는다. 명칭·목록·단순 정의(예: 코돈의 뜻)에는 추가하지 않고, 이미 필요성과 원리가 충분한 설명은 반복하지 않는다. 인접 토픽에 필요한 설명이 있으면 정확한 토픽 링크로 연결한다.
- 생물학에서 “왜”는 기능과 효과로 설명한다(예: 합성을 줄이면 에너지와 재료 사용이 줄어든다). 생물이 의도적으로 설계·선택했다는 표현이나 근거 없는 진화 목적론을 쓰지 않는다.
- 수업 밖 기작이 필요한 경우 범위 규칙에 따라 supp로 구분하고 실제 자료명·쪽수 또는 외부 링크를 붙인다. 출처를 확인하지 못한 사실은 단정해 삽입하지 않고 이해 보강의 한계로 보고한다. 보충을 교수님 말씀이나 수업에서 배운 사실로 바꾸지 않는다.

## 토픽 마크업 (이 순서)
```html
<article class="topic" id="…"><h3>…</h3><div class="tags"><span class="tag date">MMDD 수업</span><span class="tag slide">3장 p12</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">한 문장 비유</p> …그림… </div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span> …정의·성립 조건·인과·과정(ol.steps)… </div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span> …비유·일화, 원문은 blockquote… </div>
  <div class="layer warn"><span class="layer-title">꼭 기억해요</span> …헷갈리는 짝과 바른 구분, 필요하면 짧은 원문 인용… </div>   ← layers에 warn이 있을 때만
  <div class="layer supp"><span class="badge supp">보충 · 수업에서 다루지 않았어요</span><p>…</p><p>출처: 교재 3장 p.68</p></div>   ← manifest supp=true만
  <div class="layer supp"><span class="badge supp">보충 · 노트에 빠졌던 수업 내용</span><p>…</p><p>출처: 0922 수업, 강의노트 3장 p2</p></div>   ← 수업 자료에는 있는데 노트에서 빠진 사실
  <div class="sum" hidden>…페이지 요약(아래)…</div>                                                    ← layers가 빈 목록이 아닌 토픽만, 맨 끝
</article>
```
- 레이어 제목과 배지 글자는 위와 글자 그대로 쓴다. 이모지, 장식 기호(★, ↗, → 같은 화살표 아이콘), "아래를 보세요" 같은 안내 문장은 쓰지 않는다.
- warn 레이어는 오개념 방어가 목적이다. 요약의 `⚠️ 혼동 지점`마다 "무엇을 무엇으로 착각하기 쉬운지"와 "바른 구분"을 한 쌍으로 쓴다.
- `s0-recap` 토픽(지난 수업 복습)은 formal 레이어에 요점 3~5줄과 이전 팩 링크만 둔다.
- 템플릿이 토픽 하나를 한 화면에 보여 준다. 토픽은 그것만 읽어도 이해되게 쓰고, 앞 토픽에 기대는 말 대신 `<a href="#토픽id">토픽 제목</a>`으로 잇는다.
- 요약·예고 섹션: 치트시트는 표(`<div class="table-wrap"><table>`)로, 행마다 "주제 | 시험 직전 한 줄"이며 성립 조건과 분류 경계를 한 줄 안에 보존한다. 예고는 `<ul>`, 링크는 `<ul><li><a>`.

## 명칭 회상과 비교 단위

[본문 피드백 규칙](note-feedback.md)의 해당 토픽 행을 적용한다. formal·warn에는 출처가 확인된 한국어·영어·다른 번역명을 현상과 연결하되, 이미 충분하면 문장을 늘리지 않는다. ‘정지 돌연변이(nonsense mutation)’가 있다는 사실과 nonsense라는 이름만 보고 조기 종결을 떠올리는 연습은 다르다. 필요한 토픽에서만 이름→현상·현상→이름의 짧은 새 사례를 연결하며, 해당 범위에 없는 5장 용어를 다른 장에 강제하지 않는다.

단위·단계가 핵심이면 대상/조건/결과와 헷갈리는 인접 사례를 짧게 나란히 쓴다. 전구체 한 개의 여러 가공 산물과 성숙 mRNA 한 종류의 통상적 암호화 범위, DNA 접근성의 전사 조절과 RNA 가공의 전사 후 조절처럼 비교 기준을 명시한다. 시간 순서만으로 조절 단계를 분류하지 않는다. 부정형도 내용의 참·거짓과 답으로서의 적합성을 구별하며 절대 표현만으로 판단하지 않는다. eli5의 전문용어 없는 1~3문장 규칙과 선택적 동기 설명 기준은 그대로 유지한다.

작성 후 감사표에 실제 문장과 적용 상태를 남긴다. 원문 카드에 번역·정답 단서를 추가하지 않으며 생성 `+용어` 변형의 대응은 해설에서 공개한다.

## 페이지 요약 (`.sum`)
화면 오른쪽 "페이지 요약" 패널에 그 토픽의 핵심만 보여 준다. 템플릿이 토픽의 **직계 자식** `.sum`을 패널로 옮기므로 토픽 안 맨 끝에, 레이어 밖에 둔다. `hidden`은 꼭 붙인다.
```html
<div class="sum" hidden>
  <p class="sum-lead">토픽 핵심 한 문장("~해요" 체)</p>
  <p class="panel-label">핵심 식</p>
  <ul class="eq-list"><li><span class="eq-name">식 이름</span>$$…$$</li></ul>
  <p class="panel-label">용어</p>
  <dl class="terms"><dt>용어(영어)</dt><dd>한 줄 뜻</dd></dl>
</div>
```
- 새 내용을 쓰지 않는다. 본문에 이미 나온 식·용어를 같은 표기로 1~3개씩 고른다.
- 식이 없는 토픽(생명과학은 대부분)은 "핵심 식" 줄과 `eq-list`를 뺀다. 용어가 없으면 "용어" 줄과 `dl`을 뺀다. `sum-lead`는 항상 쓴다.
- `layers`가 `[]`인 토픽에는 두지 않는다.

### 보충 요약
- 본문의 직계 자식 `.layer.supp` 각각에 고유 id를 주고, 같은 토픽의 `.sum` 안에 대응하는 `.sum-supp`을 하나씩 쓴다. 기존 id는 유지하며 수업 요약·식·용어 뒤에 둔다.
- 기존 용어 양식인 `<dl class="terms"><dt>…</dt><dd>…</dd></dl>`을 그대로 사용한다. 제목 앞에는 `(보충) `만 붙이고 짧은 주제명을 쓴다. 설명은 기존 용어 설명과 같은 색상·글꼴·간격을 쓴다. 별도 초록색 제목·구분선·글머리표·본문 이동 링크를 추가하지 않는다.
- 핵심 주장·조건·예외·오개념 판별 기준을 설명 한 항목으로 압축한다. 핵심을 빼거나 본문에 없는 사실을 추가하지 않는다. 출처·범위 불확실성도 보존한다. 보충 전용 사실은 표시 없이 수업 요약에 남기거나 중복하지 않는다. 수업 본문에도 근거가 있는 공통 핵심은 수업 요약에 남길 수 있다.
- `data-supp-source`에는 본문 보충 id를 `#` 없이 적는다. `data-supp-label`에는 본문의 `badge supp`와 같은 문자열을 기록해 내부적으로 두 보충 종류를 구분한다. 화면에는 `(보충)`만 표시하고 상세 배지·출처는 본문에 유지한다. 보충이 없는 토픽에 빈 영역을 만들지 않는다.
```html
<!-- 본문: 기존 상세 배지 유지 -->
<div class="layer supp" id="s1-processing-supp-1">
  <span class="badge supp">보충 · 수업에서 다루지 않았어요</span>
  <p>엑손에는 UTR도 포함될 수 있어요.</p><p>출처: 교재 5장 p.104</p>
</div>
<!-- 같은 토픽의 .sum 안 -->
<div class="sum-supp" data-supp-source="s1-processing-supp-1" data-supp-label="보충 · 수업에서 다루지 않았어요">
  <dl class="terms"><dt>(보충) 엑손과 UTR</dt><dd>엑손에는 UTR도 있어, 성숙 RNA에 남는 구간이 모두 번역되는 것은 아니에요.</dd></dl>
</div>
```
`check_html.py`는 보충별 내부 대응·배지 메타데이터·기존 용어 양식·제목 접두사·빈 설명·중복·잘못된 토픽의 연결을 검사한다. **의미상 충분한 요약인지는 자동 판정하지 않는다.** 작성자와 검토자는 모든 보충을 해당 요약과 대조한다. 본문 보충을 추가·수정할 때는 요약과 정리노트 MD도 함께 맞춘다.

## 객관식 선택과 보기별 해설 연결

- 중앙의 채점 상태에는 짧은 판정만 표시한다(모호한 문항: ‘단일 정답 판정 주의’). 긴 추가 해설·모호성 사유는 오른쪽 ‘추가 해설 · 수업과의 연결’에만 표시하며 중앙에 복제하지 않는다. 보기별 접이식 해설은 중앙에 유지한다.

- 보기 li에 `data-choice="1"`, 대응 풀이 li에 `data-explains="1"`을 붙인다. A~E 보기는 같은 문자 식별자를 사용한다.
- 모든 보기에 정확히 하나의 해설을 제공한다. 해설은 기존 `details.solution > ol.steps`에 두며 수업 연결 li에는 식별자를 붙이지 않는다.
- `p.answer`는 `정답: (2)` 또는 `정답: B` 형식을 유지한다. ‘틀린 것’ 문제에서도 이 정답이 채점 기준이다.
- 모호한 문항은 article에 `data-grade-mode="ambiguous"`와 `data-grade-notice="모호한 이유"`를 명시한다. 출제 의도상 답은 기존 answer에 남긴다. 이 문항은 단정적인 정오답 대신 주의 안내를 표시하며 선택한 보기와 출제 의도상 답의 해설만 먼저 펼친다.
- 조립기는 채점 모델·CSS·JavaScript를 내장한다. 해설 누락·중복·잘못된 정답은 조립을 중단하므로 카드 원본을 고친다. 별도 클릭 스크립트를 카드마다 작성하지 않는다.
- 보기 선택 즉시 내 선택과 정답의 해설만 펼친다(정답을 골랐다면 한 개). 제출 후 모든 보기 버튼은 해설을 개별적으로 접고 펼치는 버튼으로 바뀌며, 답은 바뀌지 않는다. 다시 풀기로 초기화한다. 새로고침 때는 저장된 답을 기준으로 기본 펼침 상태를 복원한다. 선택은 문서·문항·내용 버전별로 **`sessionStorage`**에 저장한다: 같은 탭에서 새로고침·뒤로가기를 해도 남지만, 탭·창을 닫고 파일을 다시 열면 푼 흔적(고른 답, 푼 문제 표시, 진행률)이 없어야 한다. 답·푼 기록에 `localStorage`를 쓰지 않는다(테마·패널 너비 같은 화면 설정만 `localStorage`). 문제 화면을 벗어날 때마다(다음·이전·목차·방향키·스와이프) 그 문제의 고른 답·정오·시각을 `sessionStorage` 스냅샷(`od-review-export:v1:<문서>`)에 갱신하고, 마지막 문제 화면에서만 보이는 **JSON 내보내기** 버튼이 Chrome 폴더 선택창(`showDirectoryPicker`)으로 `<파일명>_풀이기록_<YYYYMMDD-HHmm>.json`을 저장한다. 저장 위치는 `복습노트/<날짜>/.assets/풀이기록/`로 고정이다. 웹은 경로로 직접 쓸 수 없으므로 **처음 한 번만** 폴더 선택창(`id:'od-review-export'`)에서 날짜 폴더(안에 이 HTML이 있는 곳), 그 안의 `.assets`, `.assets/풀이기록`, 또는 `복습노트`(`<range>/.assets/풀이기록`으로 풀어서 저장) 중 하나를 고르면 핸들을 IndexedDB에 기억하고, 이후 내보내기는 창 없이 바로 저장한다(브라우저를 다시 열면 Chrome이 권한을 한 번 더 물을 수 있다). 관계없는 폴더를 고르면 저장하지 않고 안내한다. 폴더 API가 거부·미지원이면 다운로드로 대체하고(이때 `scripts/collect_solves.py`가 다운로드 폴더의 `*_풀이기록_*.json`을 `복습노트/<날짜>/.assets/풀이기록/`으로 옮긴다; 웹 페이지가 스크립트를 실행하는 것은 아니다), 선택창을 취소하면 저장하지 않는다. 저장·취소 결과와 버튼 옆 `?` 도움말(시스템 폴더 제한 안내)은 정답 피드백과 같은 화면 상단 팝업(토스트)으로 알린다. 답을 고르면 풀이 패널에 **애매함으로 표시** 토글이 생기고, 누르는 즉시 스냅샷에 반영돼 JSON 카드마다 `unsure: true/false`, `summary.unsure`로 내보낸다(다시 풀기로 해제, `sessionStorage` 범위). 기존 `result: "ambiguous"`는 출제 자체가 모호한 문항이라는 뜻이므로 `unsure`(사용자 표시)와 섞지 않는다. 안 푼 문제도 `selected: null`로 전체를 문서 순서대로 넣는다. 확인용 기록이라 불러오기 기능은 없다. 정적 HTML/Markdown에는 원래 풀이 구조가 남는다.

## 문체
- 쉽게 말하면(eli5): 초등학생이 이해할 1~3문장(figcaption 포함) + 그림. 전문용어 없이. 토스처럼 짧고 다정한 "~해요" 체.
- 정확히 말하면(formal): 정의와 성립 조건, 인과, 과정(위치·입력·출력)을 빠짐없이 정확하게. "~해요" 체.
- 교수님 말씀(prof)/꼭 기억해요(warn): 원문 인용은 15단어 안팎으로 줄인다. STT 녹음 시각은 붙이지 않는다.
- UI 글은 한국어, 전문용어는 영어 병기(예: 자매염색분체(sister chromatid)). 한 문장에 한 가지만 말하고 군더더기 수식어는 뺀다.

## 수식과 기호
- 반응식·화학식을 식으로 보여야 할 때만 `$…$`/`$$…$$`(예: `$$\mathrm{C_6H_{12}O_6 + 6O_2 \rightarrow 6CO_2 + 6H_2O}$$`). 문장 속 화학식은 H₂O처럼 유니코드 아래첨자를 써도 된다. 본문에 리터럴 `$` 금지.
- TeX 안에 `<`, `>`, `&` 금지 → `\lt`, `\gt`.
- 원문자(①~⑳)는 어디에도 쓰지 않는다. 목록 번호가 필요하면 `(1) (2) (3)`.

## SVG 그림
- 개념 토픽마다 eli5 레이어에 그림 1개 이상(구조도, 과정 흐름도, 단계 비교 등).
- `<figure class="figure"><svg id="fig-<kebab>" viewBox="…" role="img" aria-label="한국어 설명">…</svg><figcaption>…</figcaption></figure>`
- 색은 클래스로만: `fig-ink`, `fig-accent`, `fig-danger`, `fig-dot`, `fig-text`, `fig-muted`. 하드코딩 색 금지(다크모드).
- 채움과 윤곽: `fig-ink`, `fig-accent`, `fig-danger`는 선만 그린다(`fill:none`). 속이 칠해진 도형은 `fig-dot`뿐이다. 글·figcaption·`aria-label`에서 "색칠된", "채워진"은 `fig-dot` 도형에만 쓰고, 선만 있는 도형은 "테두리", "선"으로 부른다.
- 글자 12~14px, SVG `<text>`에 `$` 금지.
- id는 페이지 전체에서 유일해야 한다(`fig-` + 토픽 고유 단어).
- 문항이 교재·기출 그림을 판독하게 하면, 그 그림의 구조(표지 이름, 위치 관계)를 같은 이름으로 먼저 그려 가르친다.
