# 웹과제 캡처 PDF

`/bio-webquiz-capture <장 번호…> [YYYY-MM-DD]` 또는 자연어로 실행한다. 날짜 기본값은 한국 시간 기준 오늘이다. 경로를 지정하면 그 파일이나 폴더를 사용한다. 기본 완료 범위는 프로젝트에 PDF를 저장하는 것까지다. 원본 휴지통 이동과 Git 작업은 각각 사용자가 요청한 경우에 수행한다.

## 1. 캡처 판별

- macOS에서 `defaults read com.apple.screencapture location`으로 저장 위치를 확인한다. 미설정이면 기본 위치인 바탕화면을 확인한다. 촬영일은 파일명과 생성 시각으로 확인한다. 여러 장을 요청하면 장마다 독립적으로 처리한다.
- 캡처를 시간순으로 모아 축소판과 원본을 확인한다. 필요하면 macOS Vision OCR로 제목, 문항 번호, 전체 문항 수와 크롭 경계 후보를 읽는다. OCR은 판별 보조로 사용하고 원본에서 다시 확인한다.
- 블랙보드 제목과 문항·페이지 번호를 근거로 퀴즈를 묶는다. 이미 잘려 제목이 없는 캡처는 인접한 화면의 시각과 문항 흐름 등으로 소속을 확인할 수 있을 때 사용한다. 요청한 장과 원본에서 확인된 장이 다르거나 소속이 불명확하면 발견한 장·문항 수를 제시하고 처리할 대상을 확인한다.
- 문항마다 발문, 조건, 표·그림, 배점, 보기와 화면에 남은 선택 표시를 포함한다. 브라우저, 타이머, 사이드바, 이동 버튼을 잘라낸다. 번호 또는 보기·그림이 누락됐거나 가려졌으면 다른 원본을 찾아 대조한다. 누락이 해결되지 않은 장은 누락 번호를 보고하고 완성본으로 저장하는 것을 보류한다.
- 같은 퀴즈의 같은 문항은 촬영 시각이 가장 늦은 완전한 캡처를 쓴다. 최신 화면이 일부 잘렸다면 온전한 이전 화면을 사용하고 두 원본을 보존한다. 촬영 순서만으로 중복을 판단하지 않는다.

## 2. 생성, 검토, 저장

스킬의 `scripts/build_pdf.py`를 사용한다. Python 3.10 이상과 Pillow, PyMuPDF가 필요하다. 현재 환경의 설치본이나 프로젝트 외부 임시 가상환경을 사용한다.

장별로 임시 디렉터리에 JSON을 작성한다. `expected_questions`는 캡처에서 확인한 전체 문항 수다. `source`에는 절대 경로, `sha256`에는 원본 바이트의 SHA-256, `crop`에는 원본 이미지 왼쪽 위를 기준으로 `[왼쪽, 위, 오른쪽, 아래]` 픽셀 좌표를 기록한다. 오른쪽과 아래 좌표는 범위에 포함되지 않는다. 각 번호에 최종 선택한 캡처 하나만 기록한다.

```json
{
  "chapter": 9,
  "date": "2026-11-19",
  "expected_questions": 1,
  "pages": [
    {
      "question": 1,
      "source": "/absolute/path/to/screenshot.png",
      "sha256": "<원본의 SHA-256>",
      "crop": [343, 747, 1912, 1385]
    }
  ]
}
```

프로젝트 루트에서 실행한다. 아래의 `$quiz_tmp`는 이번 작업의 임시 디렉터리다.

```sh
python3 .agents/skills/bio-webquiz-capture/scripts/build_pdf.py build \
  "$quiz_tmp/manifest.json" --output "$quiz_tmp/candidate.pdf"
```

후보 PDF의 모든 쪽을 렌더링해 번호순인지, 발문·보기·그림 끝이 잘리지 않았는지, 주변 UI가 남았는지 원본과 대조한다. 고칠 경우 새 후보 경로로 생성해 다시 검토한다. 확인한 후보의 SHA-256을 전달한다.

```sh
python3 .agents/skills/bio-webquiz-capture/scripts/build_pdf.py publish \
  "$quiz_tmp/manifest.json" --repo "$PWD" --candidate "$quiz_tmp/candidate.pdf" \
  --reviewed-sha256 "$reviewed_sha256"
```

스크립트는 1번부터 마지막 번호까지 한 쪽씩 만들고 원본 해시, 좌표 범위, 후보 해시와 렌더링 픽셀을 검사한다. 저장 위치는 `웹과제/N장/raw/웹과제_N장_YYYY-MM-DD.pdf`다. 기존 PDF가 같은 제목과 페이지 픽셀을 가지면 재사용한다. 기존 PDF와 충돌하면 경로를 보고하고 해당 파일의 교체 여부를 확인한다.

## 3. 요청받은 원본 정리와 Git 작업

- “가장 최신본만 남겨줘”처럼 원본 정리를 요청받으면 해당 장 PDF가 최종 위치에 저장되고 검증된 후 실행한다. 이전 파일과 보존할 최신본의 경로·해시를 다시 확인하고, 동일 문항임이 확인된 이전 파일만 macOS 휴지통으로 옮긴다. 최신 화면에 누락이 있어 이전 화면을 사용했거나 중복 여부가 모호하면 두 원본을 보존한다. 이동 결과와 보존한 최신 파일을 확인한다.
- 커밋 요청이 있으면 Git 상태와 스테이징을 확인한 뒤 이번 PDF 경로만 커밋한다. 이미 스테이징된 다른 변경이 있으면 경로를 지정해 이번 결과만 커밋한다. 푸시 요청이 있으면 대상 브랜치와 원격을 확인한다. 관련 없는 로컬 커밋까지 함께 전송되는 상황이면 그 사실과 푸시 범위를 먼저 확인한다. 푸시 후 원격에 결과 커밋이 반영됐는지 확인한다.
- 결과 PDF 링크, 장별 문항 수, 중복 처리 결과와 요청받은 Git 작업의 결과를 보고한다.
