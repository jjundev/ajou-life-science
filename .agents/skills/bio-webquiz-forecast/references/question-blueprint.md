# 설계표와 pack.json

## blueprint.md (.pack/v<K>/blueprint.md)
15행 표: `카드 | 정답 | 유형(data-types) | 토픽 | 겨냥 혼동 | 기출 출처 | 노트 앵커 | 수준 | 최소 풀이 단계`. 아래에 "재출제 유력 기출 10"과 고른 이유를 한 줄씩 적는다.

표현 전환을 선택한 행은 v1부터 [공통 변형 설계 규칙](../../bio-review-pack/references/problem-selection.md) 6절을 따른다. 기존 `겨냥 혼동` 칸에 `원래 표현 → 새 표현 / 불변 판별 기준`을, `최소 풀이 단계` 칸에 그 기준을 적용하는 과정을 적는다. 기존 혼동 설명과 출처 기록은 유지하며 새 열이나 pack.json 필드는 추가하지 않는다. v2 이후에는 아래 차별화 규칙도 함께 지킨다.

## 고정 배치
- p1–p5 기출: p1·p2 `기출그대로`, p3·p4 `기출쌍둥이`, p5 `기출숫자`(계산·조건이 있는 기출이 없으면 `기출쌍둥이`로 바꾸고 `exam_counts`를 `{"기출그대로":2,"기출쌍둥이":3}`로 적는다).
- p6–p15 새 문제.
- 정답 A~E 각 3개. 기출그대로 카드는 원문 보기 순서를 섞어 정답 글자를 맞춘다.
- 유형 목표는 공통 `bio-review-pack/references/webquiz-style.md`의 장별 근거로 정한다. 해당 장 근거가 부족하면 1~3장 경향을 참고했다고 적는다. ㄱㄴㄷ·장섞기는 선택 유형이며 의무 최소 0이다. 넣을 때 교육적 이유를 blueprint에 적는다.
- 4장 참고 생성 목표의 `types_required`: `{"부정형":4,"계산":5,"그림":3,"표":1,"ㄱㄴㄷ":0,"장섞기":0}`. 이 예제를 다른 장에 복사하지 않는다. 실제 관찰과 생성 목표를 구별한다. 유형은 중복될 수 있다. 그림·표를 읽어야 답이 정해질 때 `data-types`에 각각 `그림`·`표`를 넣고 장식 그림은 세지 않는다.
- `types_required`는 기존 검사기의 최소값이다. 목표와 실제 수를 blueprint에 별도로 적고 초과·미달 이유도 남긴다. 계산 거리가 없으면 `계산` 최소값을 0으로 정하고 이유를 쓴다. 근거 부족으로 최소값을 낮출 때 목표 차이를 공개한다. 범위 밖이나 반복 문항으로 채우지 않는다.

## 난이도 설계

- 공통 `problem-selection.md` 5절 기준: 수준 1은 정의·관계·도식을 직접 식별, 수준 2는 한 가지 원리 적용·짧은 추론, 수준 3은 여러 조건·원리 연결·추가 조건부 계산. 그림 유무·부정형·보기 개수로 수준을 자동 상향하지 않는다.
- 같은 장의 실제 요구·최소 풀이 과정을 먼저 검토해 15문항의 기본/심화 목표와 이유를 정한다([공통 기준](../../bio-review-pack/references/webquiz-style.md)). 장별 근거가 부족할 때만 기본 12(수준 1~2)·심화 3(수준 3)을 참고 생성 정책으로 쓴다. 의무 비율이나 실제 출제 통계가 아니며, 근거만으로 수준 분포를 정할 수 없으면 그 한계를 공개한다. 기출 p1~p5를 먼저 분류하고 새 문제 p6~p15를 설계한다. 원문은 배합 때문에 바꾸지 않는다.
- 각 행의 `수준`은 1~3, `최소 풀이 단계`는 답을 얻는 데 필요한 과정(예: 부모 유전자형 → 자손 비율)이다. 새 pack.json 필드나 난이도 배지를 추가하지 않는다.
- 목표를 맞출 근거가 부족하면 실제 기본/심화 개수와 목표 차이를 보고한다. 쉬운 주제를 이전 버전에서 썼다는 이유로 추론 단계를 늘리지 않는다. 다른 상황·숫자·질문 방향으로 동일 수준을 연습한다.
- `review_intro`와 o1에 기본/심화 실제 개수와 목표 차이를 짧게 밝힌다. 카드 번호·part 순서는 유지한다.

## 유력 기출 고르는 규칙
1. o1의 ★★★·★★☆ 주제를 다루는 기출부터.
2. `pool.json`에 있는 기출만(답이 확정된 복습팩 카드).
3. 이전 버전 `pack.json`의 `exam_sources`와 `used_exam_sources`에 있는 번호는 p1–p5에 쓰지 않는다.

## v2 이후 차별화
- 일반적으로 이전 blueprint와 같은 (토픽, 겨냥 혼동, 발문 방향) 조합을 피한다. 이전 세트에서 덜 다룬 ★★★·★★☆ 토픽을 먼저 채운다. 아래 목적을 기록한 명칭·비교 단위 연습에만 좁은 예외를 둔다.
- 같은 혼동을 다시 낼 때는 보통 숫자·생물·그림·발문 방향(옳은 것 ↔ 옳지 않은 것) 중 둘 이상을 바꾼다. 단, 명칭 전환 또는 비교 단위 진단 목적이면 한 요소만 바꿀 수 있다. 아래 목록에 이전 카드·바꾼 요소·진단 목적을 기록해야 하며 동일 발문이나 실제 웹과제 발문 복사를 허용하는 예외는 아니다.
- 발문은 이전 세트와 같으면 안 된다(check.py `stem-dup`). 차별화는 조건·표현을 바꾸는 것이며 난이도 상승을 요구하지 않는다. 기존 범위 안에서 새 문항을 만들 수 없으면 부족한 재료와 목표 차이를 보고한다.

## 회상·비교 연습

기존 15행 표의 열은 그대로 둔다. 표 뒤에 이 제목으로 `카드 ID / 피드백 ID 또는 근거 토픽 / 바꾸는 요소 / 질문 방향 / 반복 이유` 목록을 적는다. 해당 연습이 없으면 그 이유를 적고 의무 개수를 채우지 않는다. 기존 새 문항 p6~p15 안에서 배치하며 pack.json 필드·data-types를 늘리지 않는다.

명칭 회상은 출처가 있는 이름→현상·현상→이름을 필요한 방향으로 설계한다. 같은 혼동 반복의 한 요소 예외를 쓰면 `반복 이유`에 이전 버전·카드 ID와 명칭 전환/단위 진단 목적을 함께 적는다. 모든 동의어를 발문에 붙이지 않으며 해설에서 대응을 공개한다. 원문 기출 모드·사용 제한은 기존 계약 그대로다.

## pack.json
```json
{
  "course": "생명과학", "chapter": 4, "version": 2,
  "note_href": "../../복습노트/<날짜>/정리노트_<날짜>_<slug>.html",
  "review_title": "4장 웹과제 예상 v2", "review_intro": "…", "footer_review": "근거: …",
  "parts": [
    {"id": "partA", "title": "A. 예상 개요", "short": "예상 개요"},
    {"id": "partB", "title": "B. 기출 재출제 예상", "short": "기출 5"},
    {"id": "partC", "title": "C. 새 문제 예상", "short": "새 문제 10"}
  ],
  "problems": [{"id": "o1", "part": "partA"}, {"id": "o2", "part": "partA"},
               {"id": "p1", "part": "partB"}, "… p5까지 partB", {"id": "p6", "part": "partC"}, "… p15까지 partC"],
  "answer_key": {"p1": "A", "…": "…"},
  "exam_sources": {"p1": {"source": "기출 4강 6", "mode": "기출그대로"}, "…": "…"},
  "types_required": {"부정형": 4, "계산": 5, "그림": 3, "표": 1, "ㄱㄴㄷ": 0, "장섞기": 0},
  "forbidden": ["다음 장 핵심어", "…"],
  "legacy": false, "used_exam_sources": []
}
```
`problems`의 `"…"` 자리는 실제 항목으로 모두 펼쳐 쓴다. `note_href`는 그 장을 처음 다룬 정리노트다. `forbidden`에는 다음 장 핵심어(예: 4장이면 `헬리케이스`, `오카자키`, `코돈`, `전사`, `번역`)와 수업에서 빠진 쪽의 용어를 넣는다.
