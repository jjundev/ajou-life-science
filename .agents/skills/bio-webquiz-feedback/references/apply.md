# 등록된 웹과제의 출제 지침 반영

`apply`로 호출됐을 때 아래 순서로 진행한다. 지침 변경 대상은 [장별 원본 관찰](../../bio-review-pack/references/webquiz-observations.md)과 [공통 출제 기준](../../bio-review-pack/references/webquiz-style.md)이다. 적용 결과 보고서는 스킬의 기존 저장 규칙을 따른다. 기존 학습 자료의 보강과 커밋·푸시는 각각 별도 요청에서 처리한다.

## 1. 대상 장 검증

장마다 [스킬의 자료 확인](../SKILL.md#자료-확인)에 있는 `validate --complete` 명령으로 정본 bank를 다시 검증한다. bank가 없거나 검증에 실패하면 그 장의 적용을 보류하고 이유를 기록한다. 나머지 장은 개별 처리한다. 공통 변경이 보류된 장의 근거에도 의존하면 그 변경 역시 보류한다. raw로 직접 확인한 부분 관찰은 분석 보고서에 남길 수 있다.

## 2. 기존 분석 재사용

해당 장의 `feedback/*/report.md`에서 판단에 필요한 분석을 찾는다. 적용 결과만 있는 보고서는 연결된 분석 보고서를 확인한다. 재사용할 판단마다 보고서에 적힌 실제 파일 경로와 SHA256을 현재 파일에 대조한다. bank·원본·기존 노트나 카드 등 판단에 쓰인 자료가 일치하면 그 대조 결과를 재사용한다.

공통 지침이나 장별 관찰만 바뀌었으면 최신 문서를 열어 과거 제안이 이미 반영됐는지부터 확인한다. 자료가 달라졌거나 해당 근거의 해시가 없으면 영향받는 판단을 스킬의 기존 자료 확인과 대조 절차로 다시 검토한다. 쓸 수 있는 보고서가 없으면 필요한 분석부터 진행한다. 적용 결과에 어떤 보고서와 판단을 재사용했는지, 어떤 부분을 재검토했는지 남긴다.

## 3. 적용 결정

| 대상 | 변경 판단 |
|---|---|
| 장별 관찰 | 확인된 문항 수·보기 수·발문 방향과 계산·필수 자료 판독 등 다음 문제 설계에 필요한 새 관찰이나 정정 사항을 적는다. 기존 장 절을 갱신하고, 없으면 한 번만 추가한다. 1~3장 기존 집계의 기준 시점과 분모를 보존한다. |
| 공통 출제 기준 | 실제 문항 근거, 현재 규칙의 공백, 다음에 생성할 문항에서 확인할 차이가 모두 있을 때만 해당 절을 최소 범위로 수정한다. 규칙이 충분하면 장별 사례나 연결만 보강할 수 있다. |
| 이미 충족 | 내용상 같은 관찰이나 규칙이 이미 있으면 `변경 없음`으로 기록한다. 문구가 다르다는 이유로 중복 추가하지 않는다. |
| 근거 부족 | `보류`로 기록하고, 어떤 자료나 비교가 필요한지 밝힌다. |

장별 관찰값과 생성 목표를 구별한다. 한 회차의 배합을 공통 의무로 만들지 않는다. 공식 답 미확인과 기출 재사용 미집계는 각각 유지한다. 자료 판독은 실제 풀이에 필요한지로 판단하며, 파일의 이미지 형식만으로 그림 문항에 넣지 않는다.

## 4. 변경 확인과 보고

쓰기 직전에 변경안에 쓰인 근거와 변경 대상 절이 검토한 상태와 같은지 확인한다. 달라졌으면 영향을 받은 판단을 재검토하거나 보류한다. 두 문서의 다른 장과 기존 규칙을 보존하며 실제로 필요한 부분만 고친다.

변경 후 문항 수와 근거 문항 ID를 대조하고, 같은 장 절이나 같은 규칙이 중복됐는지 확인한다. 공통 규칙을 수정했다면 기존 설계표나 독립 풀이로 기대한 차이를 확인할 대표 사례를 적는다. 이번 실행에서 확인한 결과와 이후 생성물에서 확인할 기준을 구별한다.

[보고서 규격 7절](report-format.md#7-구현-인계보류)에 장별 관찰과 공통 변경의 `반영 / 변경 없음 / 보류` 결과를 남긴다. 반영했다면 실제 수정 파일·절과 검증 결과를, 변경 없음이나 보류라면 그 근거를 적는다. 여러 장이 뒷받침하는 공통 변경은 같은 근거를 연결한다. 기존 분석 보고서는 보존한다.
