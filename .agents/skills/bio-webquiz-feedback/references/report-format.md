# 웹과제 피드백 보고서 규격

이 보고서는 변경안을 넘기기 위한 분석 기록이다. 아래 항목을 채우되, 근거 없는 칸은 추측으로 채우지 않고 미확인·보류 이유를 적는다. 문항 원문 전체나 기존 스킬 설명을 복제하지 않는다.

## 1. 핵심 결론·증거 범위

- 평가명·장·응시/캡처 시점과 확인 출처, 전체 문항 수 또는 확인된 부분 범위
- bank 검증 상태, 공식 답 확인 범위, 선택 기록의 제출 전/후 상태
- 기존 자료가 분석에 사용됐다는 사실과 사용자가 실제 공부했는지의 확인 여부
- 이번에 확인한 공백과 유지할 충분한 설명, 가장 중요한 권고

## 2. 사용 자료

`| 역할 | 실제 파일 경로 | SHA256 | 사용 문항·쪽·절·행/anchor |`

실제로 읽은 원본·bank·노트·카드·강의 자료·스킬·검사기를 기록한다. 사용자 진술은 파일 해시 대신 이 대화의 진술과 확인 시점으로 구분한다. 파일명·mtime만으로 학습 여부나 응시 전 생성 시점을 확정하지 않는다. 읽지 않은 자료를 근거 목록에 넣지 않는다.

## 3. 실제 출제 경향

`| 관찰 | 정의·집계 기준 | 수/분모 | 근거 문항 ID | 생성 시사점 | 한계 |`

부정형, 계산, 서열 처리, 제공 표·그림 판독, 인접 개념·역할 교환, 조건 변경 등을 필요한 만큼 분류한다. 유형 중복 여부와 계산/서열의 구분을 밝힌다. 문제에 그림이 있는 것과 답을 위해 그림을 읽어야 하는 것은 구분한다. 확인하지 않은 전체 수, 난이도, 제한 시간, 기출 재사용률을 추정 집계하지 않는다. 분석자가 분류한 난이도와 학습자에게 실제 어려웠던 정도도 구별한다.

## 4. 전체 문항 대조

`| 문항 ID·source | 필요한 판별 기준 | 기존 자료의 위치·판별 문장 | 제공한 연습·표현 | 충분한 점/공백 | 상태·한계 |`

- 확인된 문항을 모두 포함하고, 누락·미판독 문항은 따로 표시한다. 자료가 여러 회차에 걸치면 관련 토픽을 연결한다.
- 기존 설명의 존재만으로 전이가 충분했다고 결론 내리지 않는다. 반대로 선택 불일치만으로 노트에 설명이 없다고 결론 내리지 않는다.
- 상태 예: 기존 설명 충분 / 명칭·표현 전환 연습 부족 / 비교 경계 설명 부족 / 기존 규칙 미적용 / 자료·판독 부족. 새 상태가 필요하면 이유를 밝힌다.

## 5. 학습 가설

`| 관찰된 선택·사용자 추론 | 관련 문항의 일치/차이 | 유력 가설 | 경쟁 설명 | 구분할 확인 방법 | 확인 상태 |`

선택 기록이 없으면 개인 취약점 분석을 생략하고 근거 부재를 명시한다. 확인 상태는 추정 / 사용자 진술로 확인 / 독립 질문에서 확인 / 설명 후 재확인 등을 구분한다. 이 분석에서 실시하지 않은 질문을 통과한 것으로 기록하지 않는다.

예: 이름을 제시한 문항에서는 선택이 다르고 현상을 제시한 문항에서는 분석 답과 일치했다면, 명칭 연결과 개념 이해 중 무엇이 흔들리는지 확인할 후보가 된다. 이것만으로 명칭 혼동을 확정하지 않는다.

## 6. 스킬 변경안

제안별로 다음 내용을 연결한다. 번호와 우선순위는 실행마다 필요한 만큼 둔다.

- **문제와 근거:** 실제 문항 ID, 기존 학습 자료의 정확한 위치와 차이
- **현행 규칙 감사:** 관련 스킬 파일·행, 규칙 부재인지 미적용인지, 이미 충분한 부분
- **최소 변경:** 대상 파일·절, 추가/수정/통합/유지 중 선택과 구체적 동작
- **기대 변화:** 다음 노트·생성 문항·해설에서 관찰할 수 있는 차이
- **검증:** 적합한 기존 자동 검사, 내용 검토, 필요할 경우 학습자 확인을 구별
- **범위와 부작용:** 장별 사례인지 일반 원칙인지, 과잉 설명·출제 배합 왜곡·원문 훼손 방지

용어 존재나 규칙 문구 검사만으로 교육 효과를 검증했다고 쓰지 않는다. 학습 가설은 수정 우선순위의 참고가 될 수 있지만, 미확인 개인 결함을 일반 생성 규칙의 확정 근거로 쓰지 않는다.

## 7. 구현 인계·보류

`| 우선순위 | 변경 대상 파일·절 | 변경 내용 | 검증·완료 기준 | 의존성·보류 이유 |`

기존 원본·정본 bank·학습 자료를 바꾸지 않는 현재 분석의 범위를 밝힌다. 실제 수정 여부는 이 실행의 작업 결과만 기록한다. 이전에 있던 변경을 이번에 수행한 것으로 보고하지 않는다. 기존 `note-feedback.md`를 갱신할 제안이 있어도 이 보고서로 자동 대체하지 않는다.

사용자 선택이 필요한 결정과 권장값, 확인할 수 없었던 주장, 다음 구현에 필요한 자료를 남긴다. 보고서 작성 완료와 변경안 적용 완료를 구분해 종료한다.

`apply` 결과에는 아래 표를 사용한다. 기존 분석을 재사용한 경우 분석 보고서 경로와 SHA256 확인 결과를 연결하고, 다시 검토한 판단을 구별한다. 검증 실패로 보류한 장은 누락 대신 보류 이유를 기록한다.

`| 장 또는 공통 변경 | 대상 파일·절 | 결과(반영 / 변경 없음 / 보류) | 근거 문항·보고서·재검토 범위 | 실제 검증 또는 보류 이유 |`
