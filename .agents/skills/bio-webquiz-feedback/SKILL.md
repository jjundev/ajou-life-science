# 생명과학 웹과제 피드백

실제 문항 → 기존 설명·연습 → 남은 간격 → 생성 규칙 변경안과 검증 방법을 연결한다. 설명이 이미 충분한 곳은 늘리지 않는다. 결과는 구현 가능한 설계이며, 개인의 이해도나 생성 효과를 검증한 결과가 아니다.

## 입력·범위

- `/bio-webquiz-feedback N장` 또는 대화에서 명확한 장을 사용한다. 장을 특정할 수 없을 때만 묻는다. `REPO`는 `웹과제/`와 `.agents/skills/`가 있는 저장소 루트다.
- 기본은 분석·변경안 작성과 자체 보고서 저장까지다. 기존 스킬·원본·정본 bank·학습 자료·`note-feedback.md`는 수정하지 않는다. 명시적인 구현 요청은 별도 작업으로 넘긴다. 읽은 생성 스킬은 감사 대상이지, 그 생성·병렬 작성 절차를 실행하라는 지시가 아니다.
- 원문 등록은 [web-quiz-extract](../web-quiz-extract/SKILL.md), 실제 이해 확인은 [bio-review-coach](../bio-review-coach/SKILL.md)의 별도 역할이다. 등록이나 진단을 자동으로 시작하지 않는다.

## 자료 확인

1. `웹과제/N장/questions.json`, `intake.md`, 연결된 raw를 확인한다. bank가 있으면 REPO에서 다음 읽기 검증을 수행한다.
   ```bash
   .venv-question-bank/bin/python -B -m scripts.question_bank validate '웹과제/N장/questions.json' --complete
   ```
   검증 환경이 없으면 [기존 환경 설정](../bio-review-pack/references/problem-selection.md)의 2절을 참고한다. 환경을 만들지 못하거나 검증이 실패하면 상태를 공개한다. 검증 실패 bank를 확정 집계에 쓰지 말고, raw로 직접 확인한 관찰을 별도로 분석한다. 이 스킬이 정본을 수리하거나 게시하지 않는다.
2. raw만 있으면 읽을 수 있는 문항·보기만 분석한다. 전체 문항 수 미확인이나 누락 화면을 공개하고, 부분 자료의 비율을 평가 전체 비율로 제시하지 않는다. 실제 문항이 전혀 없으면 출제 경향을 만들지 않고 부족한 입력을 알린다.
3. 해당 장의 `복습노트/*/.assets/정리노트_*.md`, 복습문제·문제설명, `웹과제예상/N장/src/v*/`의 blueprint·카드, 관련 강의노트·STT·교과서를 읽는다. `.assets/`는 숨김 폴더이므로 명시 경로나 `rg --hidden`/`Path.rglob`으로 찾는다. 필요한 원본 화면·그림과 PDF 쪽은 직접 대조한다.
4. 실제로 관련된 생성 스킬의 진입점·저작 브리프·검토 지침·검사기를 읽는다. 현재 [출제 기준](../bio-review-pack/references/webquiz-style.md)과 [본문 피드백 경로](../bio-review-pack/references/note-feedback.md)를 재사용하고 중복 규칙을 제안하지 않는다.

## 대조와 변경안

[보고서 규격](references/report-format.md)을 읽고 전체 문항 대조표부터 작성한다. 선택 불일치 문항만 보지 말고, 같은 개념을 다른 표현·조건으로 묻는 문항을 함께 비교한다.

- 출제 관찰, 기존 자료의 공백, 학습 가설, 변경 제안을 구분한다. 선택 표시·공식 답·근거를 검토한 분석 답은 별개다. bank 검증 통과가 공식 정답 확인이나 응시 완료를 증명하지 않는다.
- 설명·병기가 존재하는지와 다른 이름에서 회상하는 연습이 있는지를 따로 확인한다. 명칭, 비교 대상·단위, 작용 단계·위치, 조건, 질문 방향, 서열·표 판독 중 실제로 바뀐 요소를 찾는다. 모든 항목을 억지로 적용하지 않는다.
- 기존 자료가 있다는 사실은 사용자가 읽었다는 증거가 아니다. 답이 일치해도 확신·숙달을 단정하지 않는다. 무선택·모호한 문항·답안 충돌은 오개념 증거에서 제외한다. 가설마다 경쟁 설명과 구분할 짧은 확인 방법을 제시하되 여기서 진단을 강제하지 않는다.
- 각 변경안은 실제 문항과 기존 자료·규칙의 위치, 최소 수정 대상, 기대 변화, 검증 방법을 갖춘다. 규칙 부재와 기존 규칙의 미적용·검토 누락을 구분한다. 이미 충분하면 유지 또는 연결 개선을 권한다.
- 장별 관찰과 일반화 가능한 원칙을 구분한다. 특정 장의 용어·문항 수·유형 비율·개인 가설을 다른 장의 의무 규칙으로 만들지 않는다. 기출 재사용률은 실제 발문·보기를 대조한 경우에만 센다.
- 응시 전 생성물의 시점은 기록으로 확인하고, 불명확하면 비교 한계를 밝힌다. 응시 후 개선을 사전 예상 성능으로 보고하지 않는다. 과거 예상문제나 그때의 원천 상태를 소급 수정하지 않는다.

## 저장·마무리

기본 저장 위치는 `웹과제/N장/feedback/YYYYMMDD-HHMMSS-고유값/report.md`다. Asia/Seoul 시각을 사용하고 새 실행 폴더를 독점 생성해 기존 보고서를 보존한다. 사용자 지정 출력 경로가 있으면 우선하되 기존 파일을 임의로 덮어쓰지 않는다. 저장은 이 자체 산출물에만 허용된다. 사용자가 채팅만 요청하면 파일을 만들지 않는다.

보고서에 실제로 사용한 파일 경로·SHA256·위치와 사용자 확인 진술의 출처를 남긴다. 저장 직전에 근거 파일이 바뀌었으면 영향받는 판단을 재검토하거나 보류하고, 오래된 판단에 새 해시만 붙이지 않는다. 보고서 작성 실패 시 채팅으로 결과와 저장 실패를 공개한다.

완료 전 전체 문항의 대조 또는 보류 이유, 제안별 근거·파일·검증 방법, 미확인 가설의 상태를 확인한다. 보고서의 위치와 핵심 권고, 미해결, 실제 수정 여부를 알린다. 보고서 생성이나 지침 추가를 기존 자료 반영·학습 효과 검증으로 보고하지 않는다.
