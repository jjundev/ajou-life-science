## 1. 핵심 결론·증거 범위

현재 자료는 **16문항 모두에 대응하는 본문과 원문 연습**을 갖추고 있다. 가장 먼저 손볼 곳은 설명 분량이 아니라 **0915 문제설명 p33의 전자 이동 방향 오류와 모호성 공개 누락**이다. 0910의 ATP 합성효소 차단 보충에는 원문이 주는 ‘전자전달 유지’ 조건을 붙이는 편이 정확하다. 명반응/암반응 병기, 산소의 기원, 초록빛 반사, 피루브산/젖산 구분을 새 의무 규칙으로 다시 만들 이유는 없다.

- 평가 ID `web-20261001-ch02`, 캡처 파일명 시각 2026-10-01 12:03:10–12:11:09. intake는 응시일을 이 캡처로 기록한다. 서버 제출 시각·응시 완료는 확인되지 않았다.
- raw 17장 = 16문항 + q10 중복 1장. 16문항·80보기, 모두 5보기. 전체 16개 및 q15 번호·1점은 **intake에 기록된 2026-10-01 사용자 확인의 재인용**이다. 이번 대화에서 사용자가 다시 확인한 값은 아니다. q15 머리글은 원본에서도 잘려 있다.
- 읽기 검증: `.venv-question-bank/bin/python -B -m scripts.question_bank validate <2장/questions.json> --complete`, 종료 0, `Valid: 16 questions (complete)`. 경로는 실제 Unicode 이름으로 탐색했다. 원본 17장도 이 실행에서 직접 열어 대조했다.
- 공식 답 **0/16 확인**, 선택 기록은 모두 `pre_submission`. 선택 14개 중 분석 답과 일치 11개, 불일치 q01/q07/q14 3개; q09/q10은 무선택. 이는 점수·정답률이 아니다. q07의 오타 해석과 q14의 표현 모호성은 개인 오개념 증거에서 제외한다.

### P1. p33의 전자 방향 오류와 유보 누락을 같은 해설 조각에서 수정

**기대 변화/검증:** p33의 공여체/수용체 문장이 원천과 일치하고, 과학적으로 가장 정확한 분석 D와 출제 의도/공식 채점을 구별한다. 기존 설명 생성기의 build/check로 구조·링크·해시를 검사하고 source_visual/content/independent/browser를 실제 다시 수행한다. 내용 검토는 포도당→NAD⁺, NADH→피루브산 두 방향을 원천과 대조하고 본문과 우측 요약을 따로 읽는다. 기계 검사 통과만으로 의미 검증을 주장하지 않는다. 독립 검산자가 끝내 답 충돌을 확인하면 기존 disputed 절차를 따른다.

### P3. 새 회상 연습은 필요가 확인된 곳에만 제한

**근거:** q01/q10은 N15에 동의어와 O₂ 기원 설명이 있고 R15 p4/p7/p12/p26/p30에 이미 다른 발문 연습이 있다. ‘영어·별칭이 없어 틀렸다’는 근거는 없다. q07에 대응하는 흡수/반사 설명도 있지만 R15 p20은 주로 스펙트럼의 측정 대상을 구분하므로 보이는 색에서 흡수색을 회상하는 연습과 같지 않다. q03/q14는 수치/기작의 차이를 보여 주지만 q14가 모호하므로 개인 전이 실패를 확정하지 않는다.

**현행 규칙:** `webquiz-style.md` L66–86에 상황 전이·용어 바꿔 쓰기가 있고, forecast `question-blueprint.md` L29–38과 `card-brief.md` L5–14에는 회상·비교/답 누설 방지가 이미 있다. 새로운 고정 유형이나 동의어 병기 의무를 제안하지 않는다.

**최소 변경:** 다음 생성이나 사용자가 원한 확인에서만 기존 문제 일부를 활용해 발문 방향을 먼저 읽거나, 새 식물/색 조건에서 흡수와 보이는 색을 짧게 확인한다. 재확인에서 실제 공백이 드러나기 전에는 문제 수를 의무적으로 늘리지 않는다. 설명이 열린 성공은 독립 회상 성공과 구별한다. 2장 과거 예상 세트를 새로 만들어 사전 예상물로 주장하지 않는다.

**기대 변화/검증:** 어떤 표현·조건을 바꿨는지, 기존 연습과 무엇이 달라졌는지를 검토자가 설명할 수 있어야 한다. 예상 세트에서는 기존 blueprint의 회상·비교 목록에 기록하고 기존 검사와 블라인드 내용 검토를 따른다. 학습 효과는 별도 학습자 확인이 필요하며 이번에는 검증하지 않았다.

### 검사·전달 경로의 한계

`check_html.py`의 `required_terms` 검사는 단어 존재를 확인하며 전자 이동 방향이나 원문 유보의 의미를 검사하지 않는다. 해설 `verification.md`도 구조 검사와 의미 판단을 분리한다. review 입력 로더 `mpe_source.py` L206–218은 카드에서 문제·steps·answer를 만들며, `Problem`/`SourcePack`에는 bank의 issues/official_answer 전용 필드가 없다. 이것은 **자동 전달 필드가 없다는 코드 관찰**이며 작성자가 bank를 읽을 수 없었다는 뜻은 아니다. 현행 저작 규칙은 bank를 별도로 읽도록 한다. 우선 이 절차와 이슈→해설 위치 대조를 적용하고, 반복 누락이 확인되기 전에는 새 스키마·전용 의미 검사기를 만들지 않는 편이 낫다.
